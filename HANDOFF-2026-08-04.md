## The Real Problem: Installed App Doesn't Launch

### Symptoms
1. User double-clicks vivim or runs `"C:\Program Files\vivim\vivim-desktop.exe"`
2. A popup appears briefly (unknown content — user clicks OK)
3. Window disappears, nothing happens
4. No vivim processes remain
5. No supervisor log created at `%LOCALAPPDATA%\vivim\vivim-supervisor.log`
6. No server log at `%LOCALAPPDATA%\vivim\vivim-server.log`

### Investigation Results
- **WebView2 IS installed** — `msedgewebview2` processes running, registry entries present
- **vivim-server.exe works standalone** — `"C:\Program Files\vivim\vivim-server.exe"` starts on port 9421, logs to server.log
- **No crash events in Windows Event Viewer** related to vivim (only MsiInstaller Error 1730 from uninstall attempts)
- **Process starts then dies within seconds** — `Start-Process` shows PID but it disappears in ~5s
- **No supervisor log** — means `lib.rs::run()` crashes before `setup()` callback

### Installed Files (`C:\Program Files\vivim\`)
```
vivim-desktop.exe      16,831,488 bytes
vivim-server.exe     101,707,264 bytes
vivim_desktop_lib.dll    457,728 bytes
Uninstall vivim.lnk          943 bytes
```
- No `frontend/` directory (Tauri embeds frontend into binary — this is expected)
- No `binaries/` subdirectory
- `tauri.conf.json` specifies `"externalBin": ["binaries/vivim-server"]`

### Build Binaries
- `src-tauri/binaries/vivim-server-x86_64-pc-windows-msvc.exe` = 101,707,264 bytes (same as installed)
- `%LOCALAPPDATA%\vivim\vivim-server-x86_64-pc-windows-msvc.exe` = 47,128,576 bytes (older/different)

### lib.rs Analysis
```rust
// Key flow:
fn main() { vivim_desktop_lib::run() }
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_shell::init())
        .plugin(tauri_plugin_updater::Builder::new().build())
        .invoke_handler(tauri::generate_handler![backend_port])
        .setup(|app| {
            supervise_sidecar(&app.handle().clone());  // <-- spawns vivim-server
            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error while running vivim tauri application");
}
```
- Sidecar spawns via `app.shell().sidecar("vivim-server")` with args `["serve", "--host", "127.0.0.1", "--port", "9421"]`
- Logs go to `vivim-supervisor.log` via `log_supervisor()` function
- Auto-restart with exponential backoff (5 attempts max)

### Likely Cause
The app crashes before `setup()` runs. Possible causes:
1. **Sidecar path mismatch** — `externalBin: ["binaries/vivim-server"]` but no `binaries/` dir in install
2. **Missing DLL dependencies** — `vivim_desktop_lib.dll` or other runtime deps
3. **Tauri plugin init failure** — `tauri_plugin_shell` or `tauri_plugin_updater`
4. **WebView2 version mismatch** — installed version vs what Tauri expects
5. **Windows permissions** — MSI installed per-machine but user lacks admin
