# Data Model: Provider Protocol Data Layer

**Feature**: 021-provider-protocol-data-layer
**Source of truth**: DB (Prisma / SQLite). Static `provider-protocol.ts` is a compiled projection.

## Canonical DB tables (single source of truth)

| Table | Role | Key columns | Notes |
|-------|------|-------------|-------|
| `provider_definition` | Provider registry | `id`, `slug`, `display_name`, `category`, `provider_type`, `auth_type`, `website_url`, `protocol_status` | `protocol_status` default `'Active'`; generator filters on it (R1.1) |
| `provider_endpoint` | CDP endpoints | `provider_id`, `endpoint_type`, `url`, `composer_type`, `send_method`, `selectors_json` | `selectors_json` is canonical selector storage (R1.3) |
| `provider_parser` | Stream parsers | `provider_id`, `name`, `version`, `parser_logic_code`, `parser_file_path` | `parser_logic_code` canonical; `parser_file_path` retained, always `null` (R1.2) |
| `provider_capability` | Capability bindings | `provider_id`, `capability_id`, ... | Seeded via harvest seed (R5.1) |
| `provider_config` | Key/value config | `provider_id`, `config_key`, `config_value`, `config_type`, `is_secret` | |
| `provider_model` | Model catalog | `provider_id`, `model_slug`, `display_name`, ... | |
| `ProviderParser.fallback_parser_id` | Fallback chain | (FK) | Wired by 2-pass upsert (feature 020) |

### State transitions

- `provider_definition.protocol_status`: only `'Active'` rows are projected into the generated
  static file. Inactive providers are omitted from `provider-protocol.ts` / `.dev.ts`.
- Boot (`seedAll`) sets `protocol_status = 'Active'` on every seeded definition (R5.1).

### Validation rules

- Manifests validated through `ProviderManifestSchema` (Zod) before `register()` (R5.3).
- Generator reads only `protocol_status = 'Active'` rows.
- `parser_logic_code` must be non-empty inline `LOGIC_CODE`; `parser_file_path` must be `null`.

## Generated static projection (`src/__generated__/provider-protocol.ts`)

Compiled shape (from `ProviderProtocol` in `provider-protocol-generator.ts`):

```ts
interface ProviderProtocol {
  schemaVersion: 1
  generatedAt: number
  providerCount: number
  providers: ProviderProtocolEntry[]
}

interface ProviderProtocolEntry {
  slug: string
  displayName: string
  description?: string
  category: string
  providerType: string
  authType: string
  websiteUrl?: string
  profileStrategy: string
  isActive: boolean
  endpoints?: EndpointEntry[]
  parsers?: ParserModuleEntry[]
  streamConfig?: StreamConfigEntry
  capabilities?: CapabilityBindingEntry[]
  composerSelectors?: string[]
  sendButtonSelectors?: string[]
  config?: Record<string, string>
}
```

- `provider-protocol.ts` = prod (committed, regenerated by `gen:protocol`).
- `provider-protocol.dev.ts` = editable clone, gitignored, selected via `PROVIDER_PROTOCOL_SOURCE=dev`.

## Node-layer tables (PRESERVED, out of scope)

`Node`, `NodeEdge`, `NodeVersion`, `NodeAlias` — untouched by migration squash (R5.8 / Non-Goals).

## Relationships

```
provider_definition 1──* provider_endpoint
provider_definition 1──* provider_parser (parser_file_path = null)
provider_definition 1──* provider_capability
provider_definition 1──* provider_config
provider_definition 1──* provider_model
provider_parser  *──1 provider_parser (fallback_parser_id chain)
```

## Invariants (unchanged)

- DB-only parser execution (no file-based parser loading).
- `protocol_status` gate honored by generator and registry.
- Zero FS reads of `seeds/providers/*.json` at boot.
