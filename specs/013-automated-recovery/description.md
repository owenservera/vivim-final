Build an automated health recovery system that fixes common provider issues without user intervention. The kernel oracle (oracle-reader.ts) already monitors provider health, circuit breakers, selector drift, and session expirations. Build an auto-healing engine that: (1) Detects stale/crashed Chrome slaves and automatically restarts them (reconnect to debug port if Chrome is still running, or launch a new instance). (2) When a circuit breaker opens after N consecutive failures, wait the cooldown period then auto-transition to half-open and test with one request — if it succeeds, close the circuit; if it fails, keep it open and notify the user. (3) When selector drift is detected (a DOM selector no longer matches the provider UI), run the selector-healer engine to find new selectors and auto-update them. (4) When a provider session is about to expire (cookie TTL < 1 hour), show a preemptive "Your ChatGPT session may expire soon — click to refresh" notification. (5) Log all auto-recovery actions to the existing trace log for audit. Expose recovery status in the health dashboard. The kernel oracle, circuit breaker, selector healer, and Chrome governor all exist — this spec wires them into automated recovery with user-visible status.
