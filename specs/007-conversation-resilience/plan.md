# Implementation Plan: Conversation Resilience

**Branch**: `007-conversation-resilience` | **Date**: 2025-07-17 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/007-conversation-resilience/spec.md`

## Summary

Make conversations resilient to three failure classes that interrupt an in-flight `send`:
(1) **Chrome slave crash** — the Chrome process backing a provider dies mid-stream;
(2) **CDP disconnection** — the debug-protocol transport drops; and
(3) **Provider session expiry** — the authenticated cookie expires mid-conversation.

Today the send pipeline delegates to `ChromeGovernor` (the only legal CDP surface —
Governor Canon) which throws `EngineError('CDP transport not configured')` or
`EngineError('Circuit breaker open for slave: …')`, and the upstream handler lets these
bubble as a raw stack trace. The fix is a thin **`SendResilienceEngine`** that wraps the
send path with a pre-flight gate, a one-shot auto-reconnect, and a structured
`SendResilienceError` carrying a `recoveryKind` enum (`chrome_crash | cdp_down | session_expired | circuit_open`).
The chat UI renders this error as a capability slot (not a hardcoded string), surfacing the
correct recovery action: **Retry** (reconnect + resend) or **Re-login** (launch `ChromeSetupWizard`).

The engine does not touch CDP directly. It depends on the `ChromeGovernor` instance
(reconnect via `governor.ensureConnected` / `governor.launch`), on `ProviderHealthKernel`
for session-expiry + circuit state, and on the `ChromeSetupWizard` for re-login — all
already existing, all behind contracts. New recovery UI strings live in the conceptual
model (`UiComponent`) tiers, consistent with FR-006 / the One Entry Point invariant.

## Phase 0 — Research (decisions)

See [research.md](./research.md) for the full decision log. Summary of the binding decisions:

- **Reconnect surface**: `ChromeGovernor` is the single legal CDP owner. Its `ensureConnected(slaveId)`
  already auto-attaches a transport; `launch(providerId, { visible:false })` recreates a dead slave.
  The resilience engine calls these — it never imports `BunCdpClient`.
- **Session-expiry signal already exists**: `ProviderHealthKernel.checkSessionExpiry()` returns
  0/50/100/null via CDP cookie inspection. We read `governor.getHealth`/`ProviderHealthKernel.getHealth`
  rather than re-implementing cookie logic (avoid drift with `004`/`006`).
- **Circuit state already enforced**: `ChromeGovernor` throws `EngineError('Circuit breaker open …')`
  on `cdp.send`. We catch this and map to `recoveryKind: 'circuit_open'`.
- **Re-login**: `ChromeSetupWizard.needsSetup()` + launch-visible flow already covers manual re-auth.
  Recovery "Re-login" button calls the existing setup capability.
- **No new DB tables**: all state is derived from existing `providerAccount` + health/circuit stores.
