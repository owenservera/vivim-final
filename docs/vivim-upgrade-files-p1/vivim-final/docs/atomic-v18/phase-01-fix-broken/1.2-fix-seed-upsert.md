## Context

The `providerDefinition` upsert fails with:
```
ON CONFLICT clause does not match any PRIMARY KEY or UNIQUE constraint
```

This happens because the seed files try to upsert on a field组合 that doesn't have a unique
constraint in the Prisma schema. The `provider_definition` table uses `cuid()` IDs, and the
seed upserts may be targeting `name` or `slug` without a proper unique index.

## Interface

### Fix options (choose one):
1. **Schema fix:** Ensure `provider_definition` has `@@unique([name])` or `@@unique([slug])`
   if seeds upsert on those fields
2. **Seed fix:** Change seed upserts to use the actual unique field (likely `slug`)
3. **Store fix:** Change `ProviderStoreImpl.upsertDefinition()` to use the correct unique field
