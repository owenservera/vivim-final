# ADR-015: Session 1 Closure — Alpha P1s Verified Closed

- Status: accepted
- Date: 2026-08-07
- Decision-maker: Session 1 development sprint
- Supersedes: ADR-001-run-2026-08-06-A1 (FIX-A1-1), ADR-002-run-2026-08-06-A1 (FIX-A1-2), ADR-003-run-2026-08-06-B1 (FIX-B1-1), ADR-004-run-2026-08-06-B1 (FIX-B1-2)

## Context

The 2026-08-06 review run produced 5 alpha-in-scope P1 findings (FIX-A1-1,
FIX-A1-2, FIX-B1-1, FIX-B1-2, FIX-B2-1). Session 1 was convened to close them
and unblock the alpha release. This ADR records the closure decisions for 4 of
the 5; the 5th (FIX-B2-1) is deferred per ADR-014.

## Decision

The following 4 P1s are **CLOSED** in session 1. Each was verified by direct
inspection of the current source tree (not by re-running the review system,
which requires a full `bun docs/review-system/scripts/run.ts` invocation that
should be performed as the final pre-release gate).

### FIX-A1-1 — Split `bootstrap-engines.ts` ✅

**Was:** single ~112-LOC god-wiring function with 25+ imports and 8-deep nesting.
**Now:** `src/server/bootstrap-engines.ts` is an 11-LOC facade that re-exports
`orchestrateBootstrap` from `src/server/bootstrap/orchestrator.ts`. The actual
wiring lives in 5 phase modules under `src/server/bootstrap/phases/`:
`seeds.ts`, `stores.ts`, `knowledge.ts`, `capabilities.ts`, `lifecycle.ts`.
**Closed by:** WP-10 source upgrade (commit `bf9ecd4`, 2026-08-06).
**Verified:** `wc -l src/server/bootstrap-engines.ts` → 11 lines. `ls src/server/bootstrap/phases/` → 5 phase files present.

### FIX-A1-2 — Single boot graph + config-loading split ✅

**Was:** two-layer bootstrap duplication between `src/server/index.ts` and the
old `bootstrap-engines.ts`, with implicit phase ordering.
**Now:**
- `src/server/bootstrap/orchestrator.ts` IS the canonical boot graph — phase
  order is documented at lines 8–13: `seeds → stores → knowledge → capabilities → lifecycle`.
- `src/server/index.ts` exposes exactly two entry points: `createServer`
  (minimal, db-only — for tooling/tests) and `createServerWithEngines` (full
  boot — for production). Both are documented with the `BootPhase` type
  (`'db-only' | 'seeds-done' | 'engines-ready' | 'fully-booted'`).
- `createServerWithEngines` calls `bootstrapEngines(port)` exactly once; no
  duplicate capability registration exists.
- New invariant `checkB13_BootGraphCanon()` in `devops/invariants.ts` verifies
  that only `createServerWithEngines` calls `bootstrapEngines` — preventing
  future regression.
**Closed by:** WP-10 upgrade (orchestrator extraction) + session 1 (documentation, invariant).
**Verified:** `grep bootstrapEngines src/server/index.ts` → 1 hit (line 491).

### FIX-B1-1 — Split `catalog.ts` NL patterns ✅

**Was:** 1,783-LOC god-module containing all NL pattern definitions.
**Now:** `src/engines/nlcl/catalog.ts` is 59 LOC — a thin registry that imports
from 16 category modules under `src/engines/nlcl/categories/`: `app.ts`,
`automation.ts`, `browser.ts`, `canvas.ts`, `channel.ts`, `conversation.ts`,
`email.ts`, `file.ts`, `llm.ts`, `memory.ts`, `opencode.ts`, `provider-cap.ts`,
`session.ts`, `system.ts`, `workflow.ts`, `builder.ts`. Plus a `_generate.ts`
helper.
**Closed by:** WP-10 source upgrade.
**Verified:** `wc -l src/engines/nlcl/catalog.ts` → 59 lines. `ls src/engines/nlcl/categories/` → 17 files.

### FIX-B1-2 — ChromeGovernor boundary invariant ✅

**Was:** no architectural lint enforcing "only ChromeGovernor touches CDP".
**Now:** `checkB1_GovernorCanon()` at `devops/invariants.ts:255` scans all
`.ts` files under `src/engines/` for imports of `BunCdpClient`,
`executor/cdp`, or `cdp-transport`, excluding `chrome-governor.ts` (the
canonical owner). Any match produces a category-B blocking violation.
The protocol-descriptor modules (`cdp-discovery`, `cdp-capability-registrar`,
`cdp-artifact-cleaner`, `cdp-watchdog`) are intentionally NOT flagged — they
are registrars/helpers, not socket transports.
**Closed by:** invariant already existed in `devops/invariants.ts`; session 1
added arch test `tests/arch/boundary-cdp.test.ts` that runs the check and
asserts zero violations, so the invariant is now exercised by the test suite.
**Verified:** `grep -n 'checkB1_GovernorCanon' devops/invariants.ts` → defined at line 255, called at line 821.

## Consequences

**Positive:**
- Alpha release is unblocked. `docs/ALPHA.md` updated to **ALPHA-READY (clean)**.
- 4 ADRs (`ADR-001-run-2026-08-06-A1`, `ADR-002-run-2026-08-06-A1`,
  `ADR-003-run-2026-08-06-B1`, `ADR-004-run-2026-08-06-B1`) are now
  SUPERSEDED — see status updates in those files.
- New invariant `checkB13_BootGraphCanon` prevents the boot-graph duplication
  from regressing.

**Negative / risk:**
- The closure was verified by direct code inspection, not by re-running the
  review system. A final `bun docs/review-system/scripts/run.ts --depth quick`
  should be run before tagging the alpha release to confirm 0 P1 findings.
- FIX-B2-1 (Prisma schema split) is deferred per ADR-014. Schema continues to
  grow in single-file form during alpha bug-fix cycles.
