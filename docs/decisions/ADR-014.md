# ADR-014: Dual-Store Architecture (SQLite + Cozo)

**Status:** APPROVED
**Date:** 2026-07-18
**Author:** vivim-final
**Related Units:** Phase 0, Node-layer v2, ACU system

## Problem Statement

vivim-final needs graph math (union-find clusters, multi-hop entity traversal), 1536-dim vector similarity search, and live context composition — all while remaining local-first, single-user, zero-server.

## Context

The OG `edge-pwa` backend solves this with a 3-tier embedded architecture:
1. **redb** (records) → equivalent to our **SQLite/Prisma**
2. **Cozo** (graph + vectors) → embedded Datalog DB with `<F32;1536>` columns
3. **In-memory snapshot** (warm view) → precomputed for sub-second composition

Postgres was considered and rejected: it requires a server process per peer, breaking local-first + P2P.

## Options Considered

### Option A: SQLite only + JS graph math
**Pros:** Zero new deps. Simple.
**Cons:** Union-find, multi-hop traversal, and 1536-dim cosine all written in JS over SQLite rows. Performance at 20k conversations is unverified; code complexity is high.

### Option B: SQLite (records) + Cozo (graph + vectors)
**Pros:** Battle-tested from OG. Cozo handles Datalog graph queries + vector columns natively. Embedded — no server. Rebuildable from SQLite.
**Cons:** New dependency (cozo-node). Must maintain projection sync.

### Option C: Postgres
**Pros:** Full SQL + pgvector.
**Cons:** Server process required. Breaks local-first + P2P model.

## Decision

**Selected Option: B** — SQLite (records) + Cozo (graph + vectors).

**Rationale:**
- OG validates this architecture at scale (20k+ conversations).
- Cozo is embedded — no server, no process management.
- SQLite remains source of truth; Cozo is a rebuildable projection.
- Fail-open: Cozo errors are logged, never propagated to callers.

## Consequences

1. **Write path:** SQLite commit first, then project to Cozo. Cozo write failure is non-fatal.
2. **Rebuild:** `rebuildGraphFromNodes()` can reconstruct all Cozo relations from SQLite at any time.
3. **Schema:** 17 Cozo relations (12 graph + 5 LCG) mirror the OG `cozo_layer.rs` + `lcg/schema.rs`.
4. **Dependency:** `cozo-node@0.7.6` (native N-API, auto-downloads prebuilt binary via node-pre-gyp).
5. **ACU fields:** Extended Prisma `Node` with `acuType`, `lineageKind`, `extractorVersion`, `parserVersion`, `valueScore`, `isHighValue` to support high-value targeting.

## Verification

- [x] `cozo-node` installs + loads on Bun (Windows x86_64)
- [x] `<F32;1536>` vector columns work (create, insert, read back)
- [x] File-backed sqlite persistence survives restart
- [x] Param binding (JS array → DataValue::List → `<F32;N>`)
- [x] Full OG schema (17 relations) created successfully
- [x] Entity + ConvMeta with 1536-dim vectors inserted and queried
