# ADR-016: OpenCode Serve Contract Snapshot + Weekly Drift Check

- Status: accepted
- Date: 2026-08-08
- Decision-maker: Agent (vivim opencode integration)

## Context

vivim's `OpenCodeClient` (`src/engines/opencode/opencode-client.ts`) talks to a
local `opencode serve` subprocess supervised by `OpenCodeSupervisor`
(`src/engines/opencode/opencode-supervisor.ts`). The serve exposes a full
OpenAPI 3.1 spec at `GET /doc` — measured **478 KB, 162 paths**, ~1.1 MB pretty-
printed — which is the authoritative contract for every endpoint the client and
ingest depend on:

- `GET /doc` — readiness probe (`OpenCodeSupervisor.waitForReady`)
- `POST /session` — session create (`createSession`, body `{ model: {id, providerID} }`)
- `GET /session` — session list (`listSessions`, shape `[{id, slug, title, directory, model, tokens, time, version, agent}]`)
- `GET /session/:id/message` — authoritative transcript (`getSessionMessages`,
  shape `[{info:{id, sessionID, role, parentID, time, modelID, providerID}, parts:[{id, messageID, type, text}]}]`)
- `POST /session/:id/prompt_async` — streaming prompt (`sendPrompt`, body `{ parts: [{type:'text',text}] }`)
- `POST /session/:id/message` — blocking send (`sendMessage`, returns `{ info, parts }`)
- `GET /event?session=:id` — SSE event stream (`subscribe`, frames via `parseOpencodeJson`)
- `POST /session/:id/permissions/:permissionID` — permission reply (`respondPermission`)
- `GET /session/:id/diff` — working tree diff (`getDiff`)

These shapes were reverse-engineered by probing the live server (v1.18.4) and
are hardcoded in the client with comments. **There is no drift protection** — if a
future opencode release renames an operation, changes a request/response schema,
or moves an endpoint, the client fails silently or with a confusing error.

Because the contract "does not change much" between releases, we want a cheap
signal, not continuous validation.

## Decision

1. **Keep a full copy of the serve contract in vivim.** The complete `GET /doc`
   OpenAPI spec is snapshotted to `devops/opencode/contract-snapshot.json`
   (committed). This is the stored source of truth for "what opencode serve
   v1.18.4 exposes".

2. **Weekly drift check, not per-call validation.** A health probe compares the
   *live* `GET /doc` against the snapshot and reports **per-endpoint PASS/FAIL
   on the dependency surface** (the paths above) plus a summary of any
   added/removed/changed paths anywhere in the spec. Run it on a weekly cadence
   (the contract rarely changes; a weekly diff is enough to catch a release bump).

3. **Snapshot refresh is a deliberate, reviewed act.** Updating the snapshot
   happens only after the new contract is verified against the client (not an
   automatic background write). Auto-refresh was explicitly considered and
   deferred — see Consequences.

## Consequences

Positive:
- A release-bump that breaks `OpenCodeClient` is caught within a week of the
  serve upgrade, with a precise list of which endpoint/schema drifted.
- The stored snapshot is a reference any future opencode work (parsers, new
  endpoints, the F-gap closure) can diff against without a live server.

Negative / risk:
- The snapshot is a point-in-time artifact; it must be regenerated when opencode
  is upgraded. Without a manual regen the check is comparing against a stale
  baseline (which is exactly the *intended* failure — it flags drift).
- Full-spec byte-diff is noisy; the probe must narrow to the dependency surface
  for the PASS/FAIL verdict and only summarize the global diff.

Deferred / follow-up:
- **Auto-snapshot on boot was skipped on purpose** (decision here): a silent
  background overwrite would hide the drift the check exists to catch. Revisit
  only if we later pin opencode to a specific version.
- Wiring: expose as a devops action (`devops opencode-contract <check|snapshot>`)
  and/or a `cap:opencode:contract.*` capability + `GET /api/opencode/contract`,
  driven from the live serve port (supervisor handle or netstat port scan).
- Contract-check implementation is the immediate next work item; the snapshot
  artifact already exists at `devops/opencode/contract-snapshot.json`.
