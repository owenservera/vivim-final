# Unit 5.9 — Provider discovery v2 (UI-driven)

**Source:** v3 Overview §1.6; `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.9
**Design Doc:** `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.9
**Depends on:** 3.13, Phase 3
**Produces:** Discovery operable from the workspace UI.

---

## Context

A user pastes a URL into a "Discover new provider" panel. The existing `ProviderDiscoveryEngine` runs, produces a manifest draft, and opens an **approval canvas** (3.2/3.3). The user edits the manifest inline (a canvas-bound form, 3.4), approves → the provider is registered + seeded via `ProviderRegistrar`. No CLI required (acceptance).

## Existing Baseline

- `src/engines/provider-discovery.ts` — `ProviderDiscoveryEngine` with `DiscoverySession` (id, url, status, `manifestDraft`, `detectedCapabilities`, `interactiveElements`). We add a `discoverFromUrl(url)` entry that returns a draft manifest.
- `ProviderRegistrar` (5.x/Phase 1) — `registerManifest(manifest)` writes the DB rows; the approval flow calls it.
- `CanvasSpawner` (3.3) + `CanvasBinder` (3.4) — the approval canvas is a spawned instance with a bound form; submit emits `canvas:action` → `capability_bootstrap`/workspace action.
- `ConversationSurface`/`AgentFrontendSurface` (4.4/4.5) — host the discovery panel; the capability `provider_discover` (registered here) is invokable from the palette (4.6).

## Interface

### Extension in `src/engines/provider-discovery.ts`

```typescript
export interface DiscoveryDraftResult {
  sessionId: string
  manifestDraft: ProviderManifestDraft
  confidence: number
}

export class ProviderDiscoveryEngine {
  // ... existing session logic ...

  async discoverFromUrl(url: string): Promise<DiscoveryDraftResult> {
    const session = await this.startSession({ url, shapeHint: 'provider' })
    // existing CDP/network probing fills session.manifestDraft
    const draft = await this.buildManifestDraft(session.id)
    return { sessionId: session.id, manifestDraft: draft, confidence: session.confidence }
  }
}
```

### New capability (registered in `capability-bootstrap.ts` / a `provider-capabilities.ts`)

```typescript
registry.register(cap({
  id: 'cap:provider:discover',
  slug: 'provider_discover',
  name: 'Discover Provider',
  description: 'Run discovery on a URL and open an approval canvas.',
  category: 'provider',
  inputSchema: { type: 'object', properties: { url: { type: 'string' } }, required: ['url'] },
  outputSchema: { type: 'object' },
  mcpToolName: 'provider_discover',
  apiEndpoint: { method: 'POST', path: '/api/providers/discover' },
  handler: async (i) => {
    const draft = await discovery.discoverFromUrl(String(i.url))
    // spawn an approval canvas bound to the draft form
    const inst = await spawner.spawn({ definitionId: 'cv:system:provider-approval', spawnedBy: 'system' })
    await binder.bind(inst.canvasId, approvalBinding(draft))
    return { sessionId: draft.sessionId, canvasId: inst.canvasId }
  },
}))
```

On approval (`canvas:action` from the bound form), the handler calls `ProviderRegistrar.registerManifest(draft.manifestDraft)` and seeds the provider.

## Acceptance Criteria

1. `discoverFromUrl(url)` returns a `manifestDraft` + `sessionId`.
2. The `provider_discover` capability spawns an approval canvas and binds its form to the draft.
3. Approving the form registers + seeds the provider via `ProviderRegistrar` (no CLI).
4. The capability is exported to MCP/UI/palette (acceptance: discoverable from UI).
5. `bun run devops gate` passes.
