# Unit 5.10 — Provider test harness

**Source:** v3 Overview §4; `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.10
**Design Doc:** `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.10
**Depends on:** 5.5
**Produces:** Automated provider-capability smoke tests.

---

## Context

Per-provider integration test that exercises each declared capability (from the 5.5 matrix) against the live site (or an API mock). Runs nightly in CI + on-demand via `bun run devops gate --include-integration`. Outcomes are recorded to `ProvenanceGraph` (Phase 8). Capability drift (a selector no longer matches) is detected → a `drift_event` row is written and the provider's health score takes a hit.

This is the backbone of Scenario C (self-healing) — the loop watches drift events and re-discovers.

## Existing Baseline

- `src/engines/provider-health.ts` — `ProviderHealth` computes a `healthScore`; this harness decrements it on drift.
- `ProviderCapability` rows (5.5) — the authoritative list of `providerId × capabilitySlug` to test.
- `src/engines/provider-discovery.ts` — re-discovery invoked on drift.
- `ProvenanceGraph` (Phase 8, future) — drift outcomes recorded there; this unit defines the `drift_event` table + the write contract now.
- `bun run devops gate` — harness plugs into the `--include-integration` flag.

### New file: `src/engines/provider-test-harness.ts`

```typescript
import type { ProviderCapabilityStore } from '../storage/contracts/provider-capability-store.js'
import type { CapabilityEventBus } from './capability-event-bus.js'
import type { ChromeGovernor } from './chrome-governor.js'

export interface HarnessOutcome {
  providerId: string
  capabilitySlug: string
  ok: boolean
  error?: string
  drift: boolean
}

export class ProviderTestHarness {
  constructor(
    private capStore: ProviderCapabilityStore,
    private governor: ChromeGovernor,
    private bus: CapabilityEventBus,
  ) {}

  async runAll(providers?: string[]): Promise<HarnessOutcome[]> {
    const bindings = await this.capStore.listBindings(providers)
    const outcomes: HarnessOutcome[] = []
    for (const b of bindings) {
      const outcome = await this.runOne(b)
      outcomes.push(outcome)
      if (outcome.drift) {
        await this.capStore.recordDrift({
          id: newId(), providerId: b.providerId, capabilitySlug: b.capabilitySlug,
          selector: b.selector, status: 'open',
        })
        // signal the self-healing loop (Scenario C)
        this.bus.emit('provider:drift_detected', { providerId: b.providerId, capabilitySlug: b.capabilitySlug })
      }
    }
    return outcomes
  }

  private async runOne(b: ProviderCapabilityRow): Promise<HarnessOutcome> {
    try {
      const slave = await this.governor.spawn(b.providerId, 'test', { visible: false })
      const res = await this.governor.cdp.send(slave.slaveId, 'Runtime.evaluate', {
        expression: `!!document.querySelector(${JSON.stringify(b.selector)})`,
        returnByValue: true,
      })
      const present = Boolean((res as { result?: { value?: boolean } }).result?.value)
      return { providerId: b.providerId, capabilitySlug: b.capabilitySlug, ok: present, drift: !present }
    } catch (err) {
      return { providerId: b.providerId, capabilitySlug: b.capabilitySlug, ok: false, drift: false, error: String(err) }
    }
  }
}
```

Wired: `bun run devops gate --include-integration` invokes `harness.runAll()`; nightly CI calls the same.

## Acceptance Criteria

1. `runAll()` iterates every `provider_capability` binding and reports an outcome per capability.
2. A binding whose `selector` no longer matches → `drift: true`, a `drift_event` row is written, and `provider:drift_detected` is emitted.
3. Outcomes are recorded to `ProvenanceGraph` (Phase 8 contract) — forward-compatible write.
4. A failing capability (exception) is reported as `ok:false` without aborting the run.
5. Runs both nightly (CI) and on-demand via `--include-integration`.
6. `bun run devops gate` passes.
