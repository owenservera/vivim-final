# Unit 5.1 — Local model provider (Ollama) first-class

**Source:** v3 Overview §1.10; `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.1
**Design Doc:** `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.1
**Depends on:** —
**Produces:** `seeds/providers/ollama.json` + adapter engine; local models appear in capability palette alongside cloud providers.

---

## Context

Local models must be **first-class**, not an airgap fallback. Ollama runs an HTTP server at `http://localhost:11434`. This unit adds the provider manifest + an adapter that wraps the existing `LocalModelAdapter` (already supports `'ollama'`) as a `ProviderPlugin` implementing `onAction` for `send_message` / `select_model`. The provider is marked `isLocal: true` and is preferred when `AirGapEngine` is enabled.

## Existing Baseline

- `src/engines/local-model-adapter.ts` — `LocalModelAdapter` with `LocalModelProvider = 'ollama' | 'llamacpp' | 'none'`; `isAvailable()`/`generate(prompt)`. We wrap, not rewrite.
- `src/engines/airgap.ts` — `AirGapEngine`; local providers get preferred routing when `airGapMode` is on.
- `src/engines/provider-registrar.ts` — reads manifest JSON from `seeds/providers/` (existing `chatgpt.json`, `claude.json`, …) and writes via `ProviderStore`. New `ollama.json` follows `ProviderManifestSchema` (`src/schema/provider-manifest.ts`: `provider_type` defaults `'llm'`, `auth_type` defaults `'browser'`, `endpoints[]`, `models[]`).
- `src/engines/unified-registry.ts` (1.3) — once registered, `send_message`/`select_model` show up in the palette (4.6).

### New file: `src/engines/provider-plugin-ollama.ts`

```typescript
import type { LocalModelAdapter, LocalModelConfig } from './local-model-adapter.js'

export interface ProviderPluginContext {
  providerId: string
  model: string
}

export interface ProviderPlugin {
  providerId: string
  onAction(action: string, input: Record<string, unknown>, ctx: ProviderPluginContext): Promise<unknown>
}

export class OllamaProviderPlugin implements ProviderPlugin {
  readonly providerId = 'ollama'
  private adapter: LocalModelAdapter

  constructor(endpoint = 'http://localhost:11434', model = 'llama3') {
    const cfg: LocalModelConfig = {
      provider: 'ollama', endpoint, model,
      timeoutMs: 60_000, maxTokens: 4096, temperature: 0.7,
    }
    this.adapter = new LocalModelAdapter(cfg)
  }

  async onAction(action: string, input: Record<string, unknown>): Promise<unknown> {
    switch (action) {
      case 'send_message':
        return this.adapter.generate(String(input.message ?? ''))
      case 'select_model':
        this.adapter = new LocalModelAdapter({ ...this.adapter['config'], model: String(input.model) })
        return { ok: true, model: input.model }
      default:
        throw new EngineError(`Ollama plugin: unsupported action ${action}`)
    }
  }
}
```

Wired: `ProviderRegistrar` loads `ollama.json`; on boot, if `isLocal`, instantiate `OllamaProviderPlugin` and register its `send_message`/`select_model` as capabilities (1.3) with `surface` incl. `ui`/`mcp`.

## Acceptance Criteria

1. `ollama.json` passes `ProviderManifestSchema` validation.
2. After boot, `ollama` appears in `registry.list()` capability palette (4.6) within ~1s.
3. `onAction('send_message', {message})` routes to `LocalModelAdapter.generate`.
4. `select_model` swaps the adapter's model config.
5. When `AirGapEngine.airGapMode` is on, `ollama` is preferred over cloud providers.
6. `bun run devops gate` passes.

## Tests

- `select_model` → adapter reconfigured.
