# Unit 5.3 — API-direct providers (OpenAI, Anthropic, OpenRouter)

**Source:** v3 Overview §1.10; `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.3
**Design Doc:** `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.3
**Depends on:** —
**Produces:** `seeds/providers/openai-api.json`, `anthropic-api.json`, `openrouter.json`.

---

## Context

These providers skip Chrome entirely and call the cloud API directly. `auth_type: "api_key"`, no browser endpoints (or virtual endpoints), and parsers reuse the existing inline SSE logic (`src/engines/stream-parser.ts`). The account row stores an `apiKeyRef` (a reference into the OS keychain / env) instead of a `profileDir`.

## Existing Baseline

- `src/engines/provider-registrar.ts` — writes `ProviderConfigRow` with `authType`; we set `authType: 'api_key'` and store `apiKeyRef` on the account row (no `profileDir`).
- `src/engines/stream-parser.ts` — inline SSE parser reused for streaming responses.
- `src/engines/local-model-adapter.ts` — contrast: API providers are *not* local; `isLocal: false`.
- `src/schema/provider-manifest.ts` — `ProviderManifestSchema` (existing seeds `001_openai_sse.ts`/`002_openai_delta.ts` show the SSE seed convention).
- `McpClientAdapter` (2.9) is unrelated; these are direct HTTP, not MCP.

## Interface

`anthropic-api.json` → `https://api.anthropic.com/v1/messages`, env `ANTHROPIC_API_KEY`. `openrouter.json` → `https://openrouter.ai/api/v1/chat/completions`, env `OPENROUTER_API_KEY`, multiple models.

### New file: `src/engines/api-provider-adapter.ts`

```typescript
export interface ApiProviderConfig {
  baseUrl: string
  keyRef: string // env var name holding the key
  providerId: string
}

export class ApiProviderAdapter {
  constructor(private cfg: ApiProviderConfig) {}

  async send(message: string, model: string, onToken: (t: string) => void): Promise<string> {
    const key = process.env[this.cfg.keyRef]
    if (!key) throw new EngineError(`Missing API key for ${this.cfg.providerId} (${this.cfg.keyRef})`)
    const res = await fetch(this.cfg.baseUrl, {
      method: 'POST',
      headers: { 'content-type': 'application/json', authorization: `Bearer ${key}` },
      body: JSON.stringify({ model, messages: [{ role: 'user', content: message }], stream: true }),
    })
    // Reuse stream-parser inline SSE logic to fan tokens to onToken.
    return parseSseStream(res.body, onToken)
  }
}
```

`parseSseStream` delegates to `src/engines/stream-parser.ts` (no new eval path).

## Acceptance Criteria

1. All three `*api.json` manifests validate against `ProviderManifestSchema`.
2. `auth_type: "api_key"`; account rows carry `apiKeyRef` (env name), not `profileDir`.
3. `ApiProviderAdapter.send` reads the key from `process.env[keyRef]`; missing key → throws.
4. Streaming responses are parsed by the existing SSE parser (no `new Function`/eval).
5. `isLocal: false` so `AirGapEngine` does not prefer them.
6. `bun run devops gate` passes.
