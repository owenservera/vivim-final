# Unit 5.4 — Capability taxonomy v2 — full coverage

**Source:** v3 Overview §1.2; `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.4
**Design Doc:** `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.4
**Depends on:** 1.3
**Produces:** ~60 capability taxonomy rows covering every common AI-site action.

---

## Context

The taxonomy is currently *implicit* in seed JSON. Phase 5 formalizes it into an explicit, versioned catalog: every common AI-site action gets a full definition (id, slug, name, category, intent patterns, UI contract fields, input/output schema, surfaces). This becomes the single source the palette (4.6), binding matrix (5.5), and MCP exposure (5.7) read from.

Capability list (sample, ~60 total): `send_message`, `select_model`, `edit_message`, `regenerate_response`, `delete_chat`, `rename_chat`, `create_new_chat`, `navigate_chat`, `upload_file`, `toggle_extended_thinking`, `toggle_web_search`, `toggle_tools`, `deep_research`, `export_conversation`, `clear_context`, `browse_with_bing`, `view_artifacts`, `run_code`, `analyze_image`, `transcribe_audio`, … Each gets the **21-field UI contract** + intent patterns.

## Existing Baseline

- `src/engines/unified-registry.ts` (1.3) — `UnifiedCapability` is the runtime shape; this unit seeds the *catalog* that `registerDefaultCapabilities` (1.3) reads from.
- `src/engines/capability-shape-registry.ts` — `CapabilityShape` + `extendsShape`/`overrides` (lines 46–47) let the 60 rows share a base shape and override per action. This is the natural home for the taxonomy.
- `seeds/providers/*.json` — existing `capabilities: [...]` arrays are the informal predecessor; 5.4 supersedes them with the formal catalog.

## Interface

### New file: `src/engines/capability-taxonomy.ts`

```typescript
// Formalized v2 taxonomy — the canonical catalog of AI-site actions.
export interface CapabilityTaxonomyEntry {
  id: string
  slug: string
  name: string
  category: 'conversation' | 'model' | 'tools' | 'context' | 'export' | 'media' | 'navigation'
  intentPatterns: string[]   // NL phrasings that map to this cap
  inputSchema: Record<string, unknown>
  outputSchema: Record<string, unknown>
  uiContract: Record<string, unknown> // the 21-field UI contract
  surfaces: CapabilitySurface[]
  baseShape?: string // extendsShape reference
}

export const CAPABILITY_TAXONOMY_V2: CapabilityTaxonomyEntry[] = [
  {
    id: 'cap:conversation:send_message', slug: 'send_message', name: 'Send Message',
    category: 'conversation',
    intentPatterns: ['send a message', 'reply', 'ask the model'],
    inputSchema: { type: 'object', properties: { message: { type: 'string' } }, required: ['message'] },
    outputSchema: { type: 'object' },
    uiContract: { /* 21 fields: label, placeholder, hotkey, ... */ control: 'composer' },
    surfaces: ['cli', 'ui', 'workflow', 'mcp', 'api'],
  },
  // ... ~59 more entries, grouped by category, each with intentPatterns + uiContract ...
  {
    id: 'cap:tools:run_code', slug: 'run_code', name: 'Run Code',
    category: 'tools', intentPatterns: ['execute this code', 'run the snippet'],
    inputSchema: { type: 'object', properties: { code: { type: 'string' }, lang: { type: 'string' } } },
    outputSchema: { type: 'object' }, uiContract: { control: 'code-runner' },
    surfaces: ['cli', 'ui', 'workflow', 'mcp', 'api'],
  },
]
```

`registerDefaultCapabilities` (1.3) is extended to iterate `CAPABILITY_TAXONOMY_V2` and register each (using `CapabilityShapeRegistry.extendsShape` where a `baseShape` is set), replacing the hand-listed defaults for conversation/model/tools.

## Acceptance Criteria

1. `CAPABILITY_TAXONOMY_V2.length >= 60`.
2. Every entry has `id`, `slug`, `name`, `category`, `intentPatterns`, `inputSchema`, `uiContract`, and all 5 surfaces.
3. Categories are drawn from the fixed enum; no orphan categories.
4. `registerDefaultCapabilities` registers the full taxonomy (palette 4.6 shows 60+).
5. Entries with `baseShape` resolve via `CapabilityShapeRegistry.extendsShape`.
6. `bun run devops gate` passes.

## Tests

`tests/unit/engines/capability-taxonomy.test.ts`:
- length >= 60; every entry has the required fields.
- slugs unique across the catalog.
- every `baseShape` reference resolves to an existing shape.
