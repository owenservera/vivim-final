# Unit 5.6 — MCP server discovery + auto-registration

**Source:** v3 Overview §1.3; `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.6
**Design Doc:** `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.6
**Depends on:** 2.9
**Produces:** MCP servers in `mcp_server_config` auto-register their tools as live capabilities.

---

## Context

An external MCP server (e.g. a user's local filesystem server) should appear in the capability palette within seconds of being enabled — no manual capability authoring. On startup, `McpClientAdapter` connects to each enabled server, fetches its tool list, and registers each tool as a `LiveCapability` with `handlerSpec.kind: 'mcp'`. Tool slugs become `mcp:{serverName}:{toolName}`.

## Existing Baseline

- `src/engines/mcp-client-adapter.ts` — `McpClientAdapter.connect(serverId, url)` (verified), `callTool(serverId, ...)`, `disconnect(serverId)`. `connect` is idempotent (returns early if already connected).
- `src/engines/live-capability-registry.ts` (2.7) — `LiveCapabilitySpec.handlerSpec.kind: 'mcp'`; the registry's `specToUnifiedCapability` (2.9) already forwards `mcp` specs to `callTool`.
- `src/engines/unified-registry.ts` (1.3) — `register` / `exportForMcp` make the auto-registered tools visible.
- `mcp_server_config` table — existing config store for enabled servers (verify exact contract before impl).

## Interface

### New file: `src/engines/mcp-discovery.ts`

```typescript
import type { McpClientAdapter } from './mcp-client-adapter.js'
import type { LiveCapabilityRegistry } from './live-capability-registry.js'
import type { McpServerConfigStore } from '../storage/contracts/mcp-server-config.js'

export interface McpToolInfo {
  name: string
  description: string
  inputSchema: Record<string, unknown>
}

export class McpDiscovery {
  constructor(
    private mcp: McpClientAdapter,
    private live: LiveCapabilityRegistry,
    private configStore: McpServerConfigStore,
  ) {}

  async registerServer(serverId: string, url: string): Promise<string[]> {
    await this.mcp.connect(serverId, url)
    const tools = await this.mcp.listTools(serverId) // tools the adapter fetched on connect
    const slugs: string[] = []
    for (const tool of tools) {
      const slug = `mcp:${serverId}:${tool.name}`
      await this.live.registerLive({
        id: `cap:${slug}`,
        slug,
        name: tool.name,
        description: tool.description,
        category: 'mcp',
        inputSchema: tool.inputSchema,
        outputSchema: { type: 'object' },
        handlerSpec: { kind: 'mcp', serverId, toolName: tool.name },
        surfaces: ['cli', 'ui', 'workflow', 'mcp', 'api'],
      })
      slugs.push(slug)
    }
    return slugs
  }

  async unregisterServer(serverId: string): Promise<void> {
    await this.live.revokeLiveByServer(serverId)
    await this.mcp.disconnect(serverId)
  }

  // Called at boot for every enabled row in mcp_server_config.
  async registerAll(): Promise<void> {
    const enabled = await this.configStore.listEnabled()
    for (const s of enabled) {
      try { await this.registerServer(s.serverId, s.url) } catch { /* log, continue */ }
    }
  }
}
```

## Acceptance Criteria

1. `registerServer` connects, lists tools, and registers one `LiveCapability` per tool with `handlerSpec.kind: 'mcp'`.
2. Tool slug format is exactly `mcp:{serverId}:{toolName}`.
3. Registered tools appear in `registry.exportForMcp()` (palette 4.6, acceptance: within 5s).
4. `unregisterServer` revokes the live caps and disconnects.
5. `registerAll` processes every enabled `mcp_server_config` row; a failing server does not abort the others.
6. `bun run devops gate` passes; MCP path ≥80% covered with mocked adapter.
