# Unit 6.4 — Cross-conversation synthesis v2

**Source:** v3 Overview §1.5; `docs/master-plan-v3/PHASE-06-memory-knowledge.md` §6.4
**Design Doc:** `docs/master-plan-v3/PHASE-06-memory-knowledge.md` §6.4
**Depends on:** 6.1, 6.2
**Produces:** `CrossConversationSynthesizer.synthesize` produces real answers grounded in actual embeddings + entities + decisions.

---

## Context

The current `CrossConversationSynthesizer.synthesize` returns "LLM not configured" — a stub. This unit wires it to a real LLM: a **local** model (Ollama, 5.1) by default, with a cloud-LLM option. Synthesis retrieves grounding via `SemanticSearchEngine` (6.1 real embeddings) + the entity/decision graph, then prompts the LLM. Output includes **source attribution**, **confidence**, and **gap detection** ("I don't have enough to answer X"). Surfaced via `/api/knowledge/synthesize` and capability `synthesize_across_conversations`.

## Existing Baseline

- `src/engines/cross-conversation-synthesis.ts` — `CrossConversationSynthesizer` with `SynthesisLlmProvider` interface (`synthesize(prompt, style)` → `{ text, confidence }`) and `synthesize(query: SynthesisQuery): Promise<SynthesisResult>`. We replace the stub body.
- `src/engines/semantic-search.ts` — `SemanticSearchEngine` `search(query, k)` (now real via 6.1) supplies grounding passages.
- `src/engines/memory-engine.ts` — `MemoryEngine` recalls entities/decisions for grounding.
- `SynthesisLlmProvider` is satisfied by wrapping `OllamaProviderPlugin.onAction('send_message')` (5.1) or a cloud adapter (5.3).

## Interface

### Extension in `src/engines/cross-conversation-synthesis.ts`

```typescript
export interface SynthesisResult {
  text: string
  confidence: number
  sources: Array<{ type: string; id: string; snippet: string }>
  gaps: string[] // questions the synthesis could NOT answer
}

export class CrossConversationSynthesizer {
  constructor(
    private store: CrossConversationSynthesizeStore,
    private semantic: SemanticSearchEngine,
    private memory: MemoryEngine,
    private llm: SynthesisLlmProvider, // Ollama by default (6.1/5.1)
  ) {}

  async synthesize(query: SynthesisQuery): Promise<SynthesisResult> {
    const passages = await this.semantic.search(query.text, 8)
    const entities = await this.memory.recallEntities(query.text)
    const grounding = [...passages, ...entities]
    if (grounding.length === 0) {
      return { text: 'No relevant memory found.', confidence: 0, sources: [], gaps: [query.text] }
    }
    const prompt = buildSynthesisPrompt(query.text, grounding)
    const { text, confidence } = await this.llm.synthesize(prompt, query.style ?? 'concise')
    return {
      text,
      confidence: confidence * groundingConfidence(grounding),
      sources: grounding.map((g) => ({ type: g.type, id: g.id, snippet: g.snippet })),
      gaps: detectGaps(text, query.text),
    }
  }
}
```

## Acceptance Criteria

1. `synthesize` with no grounding returns `gaps` populated, `confidence: 0`, no LLM call.
2. With grounding, it calls `llm.synthesize` with a prompt built from real embeddings + entities.
3. Result carries `sources` (attribution) + `confidence` (<1 unless fully grounded) + `gaps`.
4. Default LLM is local (Ollama); cloud option selectable.
5. Surfaced via `/api/knowledge/synthesize` and the `synthesize_across_conversations` capability.
6. `bun run devops gate` passes.

## Tests
