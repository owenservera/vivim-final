# Unit 7.3 — HITL v2: proactive clarification

**Source:** v3 Overview §1.8; `docs/master-plan-v3/PHASE-07-autonomous-orchestration.md` §7.3
**Design Doc:** `docs/master-plan-v3/PHASE-07-autonomous-orchestration.md` §7.3
**Depends on:** 4.5
**Produces:** `agent:clarify` prompts (open question / option / file / URL); `AgentFrontendSurface` renders each gate type.

---

## Context

HITL today is approve/deny/skip only. This unit adds **proactive clarification**: the agent can ask an open-ended question ("Which file should I write this to?"), an option-selection ("SQLite or Postgres?"), a file picker, or a URL input — mid-task, not just at approval gates. `AgentFrontendSurface` (4.5) renders the correct control per gate type.

## Existing Baseline

- `src/engines/autonomous-execution.ts:58` — `HitlGate.{gateType, options, defaultValue, response}` already exists; `GateType` is the enum to extend.
- `src/engines/autonomous-execution.ts` — `AutonomousExecutionEngine` manages gates (the `gateWaiters` map). We add a `clarify()` path that emits `agent:clarify`.
- `docs/atomic-v3/phase-04-workspace-ui/4.5-agent-frontend-surface.md` — `AgentFrontendSurface` gate renderer; extend with the four new gate controls.
- `src/engines/capability-event-bus.ts` — event substrate for `agent:clarify`.

## Interface

### Change in `src/engines/autonomous-execution.ts`

```typescript
export type GateType =
  | 'approval'          // approve / deny / skip (existing)
  | 'question'          // open-ended text answer
  | 'option'            // choose one from `options`
  | 'file'              // file picker -> path
  | 'url'               // URL input

export class AutonomousExecutionEngine {
  // ...
  async clarify(step: AutonomousStep, prompt: string, kind: GateType, opts?: { options?: string[]; defaultValue?: string }): Promise<string> {
    const gate: HitlGate = {
      id: ulid(), taskId: step.taskId, stepId: step.id,
      gateType: kind, prompt, options: opts?.options ?? [], defaultValue: opts?.defaultValue ?? null,
      status: 'pending', resolvedBy: null, resolvedAt: null, response: null,
      createdAt: Date.now(), expiresAt: null,
    }
    this.bus.emit('agent:clarify', gate)
    return this.waitForGate(gate)
  }
}
```

### New control in `web/src/surfaces/AgentFrontendSurface.tsx` (4.5)

```tsx
function GateControl({ gate }: { gate: HitlGate }) {
  switch (gate.gateType) {
    case 'question': return <TextInput onSubmit={(v) => resolve(gate.id, v)} />
    case 'option':   return <RadioGroup options={gate.options} onPick={(v) => resolve(gate.id, v)} />
    case 'file':    return <FilePicker onPick={(p) => resolve(gate.id, p)} />
    case 'url':     return <UrlInput onSubmit={(u) => resolve(gate.id, u)} />
    default:        return <ApproveDeny gate={gate} />
  }
}
```

## Acceptance Criteria

1. `GateType` includes `question` | `option` | `file` | `url` in addition to `approval`.
2. `clarify()` emits `agent:clarify` and resolves with the user's response (awaited).
3. `AgentFrontendSurface` renders a distinct control for each of the four gate types.
4. `option` gates render `gate.options`; `file`/`url` return a path/URL string into `gate.response`.
5. Approval gates keep their existing approve/deny/skip behavior (no regression).
6. `bun run devops gate` passes (root + `web/`).
