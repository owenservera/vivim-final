# Unit 10.1 — Typed SDK v2 (`sdk/`)

**Source:** v3 Overview §3; `docs/master-plan-v3/PHASE-10-polish-sdk.md` §10.1
**Design Doc:** `docs/master-plan-v3/PHASE-10-polish-sdk.md` §10.1
**Depends on:** all
**Produces:** `sdk/` is a publishable NPM package with full TypeScript types + Zod schemas + WebSocket client.

---

## Context

External integrators need a first-class client, not raw `fetch`. This unit builds `sdk/` as a publishable package: typed methods for every HTTP endpoint, Zod-validated responses, WebSocket subscription helpers, and capability-invocation helpers (`client.invoke('canvas_spawn', {...})`). Replaces any thin client.

## Existing Baseline

- `src/server/*-router.ts` — `index.ts`, `autonomous-router.ts`, `conversation-router.ts`, `knowledge-router.ts`, `memory-viz-router.ts`, `mux-router.ts`, `setup-router.ts`, `websocket.ts`, `auth-gate.ts`, `response.ts`. These define the surface the SDK wraps.
- `src/schema/` — Zod schemas (the SDK reuses them for request/response validation).
- `package.json` — add `sdk/` as a workspace/publishable package (`exports`, `types`).
- `src/server/` WebSocket handshake (for the SDK WS client).

## Interface

### New package: `sdk/src/client.ts` (sketch)

```typescript
import { z } from 'zod'
import { capabilityResponseSchema } from '../schema/capability.js'

export class VivimClient {
  constructor(private baseUrl: string, private token?: string) {}

  async invoke<T = unknown>(capabilitySlug: string, input: unknown): Promise<T> {
    const res = await fetch(`${this.baseUrl}/api/capability/${capabilitySlug}`, {
      method: 'POST', headers: authHeaders(this.token), body: JSON.stringify({ input }),
    })
    const json = await res.json()
    return capabilityResponseSchema.parse(json) as T
  }

  ws(): VivimWebSocket {
    return new VivimWebSocket(`${this.baseUrl}/ws`, this.token)
  }

  // typed convenience:
  canvas = {
    spawn: (o: CanvasSpawnInput) => this.invoke('canvas_spawn', o),
    mutate: (o: CanvasMutateInput) => this.invoke('canvas_mutate', o),
  }
}
```

## Acceptance Criteria

1. `sdk/` builds (`tsup`/`tsc`) and exposes `VivimClient` with typed `invoke` + `ws`.
2. Every HTTP endpoint in `src/server/*-router.ts` has a corresponding typed SDK method.
3. Responses are validated with Zod (reusing `src/schema/*`); bad payloads throw a typed `SdkValidationError`.
4. `ws()` returns a WebSocket helper with subscription methods matching `websocket.ts`.
5. `client.invoke('canvas_spawn', {...})` works end-to-end against a running server.
6. `bun run devops gate` passes; `sdk/` typechecks independently.

## Tests

`tests/sdk/client.test.ts` (mock server or `Bun.serve`):
- `invoke` posts to `/api/capability/{slug}` and returns parsed body.
- invalid response → `SdkValidationError`.
- `ws()` connects to `/ws` and receives frames.
