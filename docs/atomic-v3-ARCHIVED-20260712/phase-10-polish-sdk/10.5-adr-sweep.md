# Unit 10.5 — ADR sweep

**Source:** v3 Overview (referenced throughout); `docs/master-plan-v3/PHASE-10-polish-sdk.md` §10.5
**Design Doc:** `docs/master-plan-v3/PHASE-10-polish-sdk.md` §10.5
**Depends on:** all
**Produces:** ADRs for every cross-cutting decision made in v3.

---

## Context

Every non-trivial v3 decision needs a recorded ADR. This unit produces the minimum set (8 ADRs) capturing the cross-cutting choices, each following the ADR workflow (create → ≥2 options → ≥2 review rounds → decide → approve). 13 ADRs already exist in `docs/decisions/`; this fills the v3-specific gaps.

## Existing Baseline

- `docs/decisions/` — 13 existing ADRs; new ones follow the same `ADR-NNN-title.md` format.
- `AGENTS.md` — ADR workflow: `bun run devops decision create/review/decide/approve`; status flow PROPOSED→…→APPROVED.
- The 8 required ADRs (from PHASE-10): 001 SQLite dialect unification, 002 field vs DB encryption (exists via 9.2), 003 canvas iframe vs web component, 004 sandbox vm vs WASM, 005 sync conflict strategy, 006 intent template vs LLM-only, 007 provenance storage model, 008 local-first default.

## Interface

### New ADRs (the v3 set)

| ADR | Title | Key options |
|-----|-------|--------------|
| 001 | SQLite SQL dialect unification | Postgres-only → SQLite-portable queries |
| 002 | Field-level vs DB-level encryption | `EncryptionEngine` field vs SQLCipher full-DB |
| 003 | Canvas iframe vs web component | host iframe vs in-app webview |
| 004 | Sandbox vm vs WASM | `node:vm` vs WASM sandbox |
| 005 | Sync conflict resolution | last-write-wins vs CRDT vs manual queue |
| 006 | Intent template vs LLM-only planning | static templates vs `IntentDecomposer` LLM |
| 007 | Provenance storage model | edge table vs adjacency + `trace_span` |
| 008 | Local-first default | opt-in cloud vs airgap-by-default |

### Each ADR body (template)

```markdown
# ADR-NNN: <title>
## Status: PROPOSED
## Context: <why this decision mattered>
## Options:
- A) <option> — pros/cons
- B) <option> — pros/cons
## Decision: <chosen>, with rationale + goal alignment
## Review: round 1 (AI), round 2 (human)
## Consequences: <what follows>
```

## Acceptance Criteria

1. ADR-001…008 all exist in `docs/decisions/` with ≥2 options each.
2. Each passes `bun run devops decision review` (≥2 rounds) and `decide` + `approve`.
3. ADR-002 (field vs DB) reflects 9.2's decision; ADR-008 reflects 9.4's airgap-by-default.
4. Decisions are referenced from the units that implement them (e.g. 9.2 → ADR-002).
5. No cross-cutting v3 decision lacks an ADR.
6. `bun run devops gate` passes.
