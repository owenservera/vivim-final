# Unit 3.2 — Built-in canvas templates

**Source:** v3 Overview §1.6; `docs/master-plan-v3/PHASE-03-html-canvas.md` §3.2
**Design Doc:** `docs/master-plan-v3/PHASE-03-html-canvas.md` §3.2
**Depends on:** 3.1
**Produces:** 8 system-defined canvases seeded at startup.

---

## Context

Agents and users should not start from a blank page. v3 ships eight built-in canvas definitions (`createdBy: 'system'`) that cover the common frontend shapes: a chat pane, a model selector, a markdown viewer, a generic form, a dashboard grid, a code block, an image gallery, and a data table. Each is a self-contained HTML+CSS bundle (~50 lines) using `data-cap-bind` hooks so 3.4 can bind capability I/O without custom code per canvas.

The seed runs at startup (idempotent — skip if a system canvas of that name already exists).

## Existing Baseline

- `seeds/` — existing seed convention lives here (provider manifests, etc.). New files follow the same `seeds/<domain>/*.ext` layout the master plan prescribes.
- `CanvasRegistry.define` (3.1) is the insertion path; seeds call it with `createdBy: 'system'`.
- `src/ids.ts` — `newId()` for stable ids; system canvases use a deterministic slug-derived id (e.g. `cv:system:chat-pane`) so re-seeding is idempotent.

## Interface

### New files: `seeds/canvases/*.html`

Each file is a complete, self-contained HTML document with inline `<style>` and `data-cap-bind` attributes. Example `chat-pane.html` skeleton (binding hooks highlighted):

```html
<!doctype html>
<html lang="en">
<head><meta charset="utf-8"><title>Chat Pane</title>
<style>/* ~50 lines of CSS: message list, composer, send button */</style>
</head>
<body>
  <div class="messages" data-cap-bind="messages" data-cap-emit="false"></div>
  <form class="composer">
    <textarea data-cap-bind="draft" data-cap-emit="input"></textarea>
    <button data-cap-bind="send" data-cap-emit="click" data-cap-action="send_message">Send</button>
  </form>
</body>
</html>
```

The eight seeded files:

| File | Name | `data-cap-bind` hooks |
|------|------|------------------------|
| `chat-pane.html` | chat-pane | messages, draft, send |
| `model-selector.html` | model-selector | models, select |
| `markdown-viewer.html` | markdown-viewer | content |
| `form-generic.html` | form-generic | (dynamic fields) |
| `dashboard-grid.html` | dashboard-grid | widgets |
| `code-block.html` | code-block | code, lang |
| `image-gallery.html` | image-gallery | images |
| `data-table.html` | data-table | rows, columns |

### New file: `seeds/canvases/index.ts`

```typescript
import { readFileSync } from 'node:fs'
import { join } from 'node:path'
import type { CanvasRegistry } from '../../src/engines/canvas-registry.js'

interface BuiltinCanvas {
  id: string
  name: string
  description: string
  htmlFile: string
  cssFile?: string
  jsFile?: string
  bindingSpec: unknown
  requiredCapabilities: string[]
}

const BUILTINS: BuiltinCanvas[] = [
  {
    id: 'cv:system:chat-pane',
    name: 'chat-pane',
    description: 'Conversation viewer with composer.',
    htmlFile: 'chat-pane.html',
    bindingSpec: {
      outputs: [{ capabilityOutputKey: 'messages', selector: '[data-cap-bind="messages"]', attribute: 'innerHTML' }],
      inputs: [{ selector: '[data-cap-bind="send"]', event: 'click', capabilityInputKey: 'send_message' }],
    },
    requiredCapabilities: ['conversation_send'],
  },
  // ... seven more entries ...
]

export async function seedCanvases(registry: CanvasRegistry): Promise<void> {
  for (const c of BUILTINS) {
    const existing = await registry.get(c.id)
    if (existing) continue // idempotent
    const html = readFileSync(join(import.meta.dir, c.htmlFile), 'utf8')
    await registry.define({
      id: c.id,
      name: c.name,
      description: c.description,
      htmlTemplate: html,
      cssTemplate: c.cssFile ? readFileSync(join(import.meta.dir, c.cssFile), 'utf8') : '',
      jsTemplate: c.jsFile ? readFileSync(join(import.meta.dir, c.jsFile), 'utf8') : null,
      bindingSpecJson: JSON.stringify(c.bindingSpec),
      requiredCapabilities: c.requiredCapabilities,
      createdBy: 'system',
    })
  }
}
```

Wired into `createServerWithEngines` after `registerDefaultCapabilities`, before the fleet boot.

## Acceptance Criteria

1. `seedCanvases` inserts 8 rows with `createdBy: 'system'`.
2. Re-running is idempotent (no duplicate system canvases).
3. Every system canvas has a non-empty `htmlTemplate` and valid `bindingSpecJson`.
4. None of the seeded HTML files contain inline `<script>` tags.
5. `bun run devops gate` passes.

## Tests

`tests/integration/seeds/canvases.test.ts`:
- after seeding, `registry.list({ createdBy: 'system' }).length === 8`.
- second seed run → still 8 (idempotent).
- each builtin's `bindingSpecJson` parses and contains at least one `outputs`/`inputs` entry.
