# Unit 9.2 — Database-level encryption (SQLCipher)

**Source:** v3 Overview §1.10; `docs/master-plan-v3/PHASE-09-sovereign-data.md` §9.2
**Design Doc:** `docs/master-plan-v3/PHASE-09-sovereign-data.md` §9.2
**Depends on:** 9.1
**Produces:** Alternative to field-level: full-DB encryption via SQLCipher (or sqlite-wasm encryption extension).

---

## Context

Some users prefer **transparent** full-DB encryption over selective field-level. This unit adds that option: at first run the user chooses field-level (selective, slower per query) or full-DB (transparent, requires `PRAGMA key`). ADR-002 documents the trade-off. The choice is persisted and applied at bootstrap.

## Existing Baseline

- `src/engines/encryption.ts` — `EncryptionEngine` underpins field-level (9.1).
- `prisma/schema.prisma` — SQLite datasource. Full-DB requires an encrypted SQLite driver (SQLCipher) instead of the default `bun:sqlite`.
- `docs/decisions/` — ADR-002 is the decision record for this trade-off (create if absent).
- `src/config.ts` — `ConfigManager` persists the `encryptionMode` choice.

## Interface

### New file: `src/storage/db-encryption.ts`

```typescript
export type DbEncryptionMode = 'field' | 'full'

export interface DbEncryptionChoice {
  mode: DbEncryptionMode
  passphrase: string
}

export function applyDbEncryption(choice: DbEncryptionChoice): void {
  if (choice.mode === 'field') {
    // 9.1 field-level; no driver change
    return
  }
  // full-DB: SQLCipher requires the key via PRAGMA before any query
  process.env.SQLITE_ENCRYPTION_KEY = choice.passphrase
  // Bun's sqlite must be swapped for a SQLCipher build (driver config)
  setDriver('sqlcipher')
}
```

### ADR-002 (new)

```markdown
# ADR-002: Field-level vs Full-DB encryption
- **Options:** (A) Field-level AES-256-GCM via EncryptionEngine. (B) Full-DB SQLCipher.
- **Decision:** Support both; default field-level (no driver swap, selective).
- **Trade-off:** Field-level is slower per sensitive query but leaves non-secret data plaintext (faster search). Full-DB is transparent but requires a SQLCipher driver + key at open.
```

## Acceptance Criteria

1. At first run the user is offered `field` or `full` mode; the choice persists in config.
2. `full` mode applies the key via `PRAGMA key` / SQLCipher driver before queries.
3. `field` mode reuses `EncryptionEngine` (9.1) with no driver change.
4. ADR-002 records the trade-off (options + decision + rationale).
5. Switching modes requires a one-time re-key/migration prompt (no silent downgrade).
6. `bun run devops gate` passes.

## Tests

- `applyDbEncryption({mode:'full'})` → `SQLITE_ENCRYPTION_KEY` set + `setDriver('sqlcipher')` called.
- ADR-002 file exists with both options documented.
