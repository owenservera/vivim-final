# Unit 9.3 — Multi-device sync v2

**Source:** v3 Overview §1.10; `docs/master-plan-v3/PHASE-09-sovereign-data.md` §9.3
**Design Doc:** `docs/master-plan-v3/PHASE-09-sovereign-data.md` §9.3
**Depends on:** 9.1
**Produces:** `SyncEngine` actually syncs across devices via a relay; conflict resolution via last-write-wins + manual queue.

---

## Context

`SyncEngine` (sync.ts) exists with relay fetch logic but pairing + conflict handling are stubbed. This unit makes it real: each device pairs via a 6-digit code, changes are recorded in `sync_log`, periodic sync pushes encrypted log entries to the relay + pulls peer entries (applied chronologically). Conflicts (same record edited on two devices) land in a manual resolution queue.

## Existing Baseline

- `src/engines/sync.ts` — `class SyncEngine` with `SyncConfig` (`relayUrl`, `syncIntervalMs`, `enabled`), `SyncPeer`, `SyncLogEntry`, `SyncStore`, `SyncResult`. We add pairing + conflict resolution.
- `src/engines/encryption.ts` (9.1) — log entries are encrypted before relay push.
- `src/schema/types.js` — `sync_log` table (`recordId`, `deviceId`, `ts`, `op`, `encryptedPayload`).
- `src/engines/telemetry-audit-interceptor.ts` (8.4) — relay calls still pass through consent (relay is a consented host).

## Interface

### Change in `src/engines/sync.ts`

```typescript
export class SyncEngine {
  // ...existing relay push/pull...

  async pairWithCode(code: string): Promise<SyncPeer> {
    const res = await fetch(`${this.config.relayUrl}/pair`, {
      method: 'POST', body: JSON.stringify({ code, deviceId: this.config.deviceId }),
    })
    if (!res.ok) throw new EngineError(`Pair failed: ${res.status}`)
    const peer = (await res.json()) as SyncPeer
    await this.store.upsertPeer(peer)
    return peer
  }

  async syncOnce(): Promise<SyncResult> {
    const local = await this.store.getUnsynced(this.config.deviceId)
    const encrypted = local.map((e) => ({ ...e, payload: this.enc.encryptField(e.payload) }))
    await this.push(encrypted)
    const remote = await this.pull()
    const conflicts = await this.applyChronological(remote)
    return { pushed: encrypted.length, pulled: remote.length, conflicts: conflicts.length }
  }

  private async applyChronological(entries: SyncLogEntry[]): Promise<SyncLogEntry[]> {
    const conflicts: SyncLogEntry[] = []
    for (const e of entries.sort((a, b) => a.ts - b.ts)) {
      const existing = await this.store.getRecord(e.recordId)
      if (existing && existing.ts > e.ts) { conflicts.push(e); await this.queueConflict(e); continue }
      await this.store.upsertRecord(e) // last-write-wins
    }
    return conflicts
  }
}
```

## Acceptance Criteria

1. `pairWithCode(6-digit)` registers a `SyncPeer` via the relay.
2. `syncOnce` pushes encrypted local `sync_log` entries and pulls peer entries.
3. Remote entries applied in **chronological** order; last-write-wins by `ts`.
4. Same `recordId` modified on two devices → the loser goes to a **manual conflict queue** (not silently overwritten).
5. Log payloads are encrypted (via 9.1) before leaving the device.
6. `bun run devops gate` passes.
