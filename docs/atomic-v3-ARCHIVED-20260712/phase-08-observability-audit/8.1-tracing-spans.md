# Unit 8.1 — Distributed tracing (spans)

**Source:** v3 Overview §1.5; `docs/master-plan-v3/PHASE-08-observability-audit.md` §8.1
**Design Doc:** `docs/master-plan-v3/PHASE-08-observability-audit.md` §8.1
**Depends on:** 2.14
**Produces:** Span wrapper around every capability execution, CDP call, LLM call.

---

## Context

Today there is no end-to-end trace tying a user action to its capability calls, CDP sends, and LLM calls. This unit introduces spans: `conversation.send → capability.execute → selector.try → cdp.send`, each with `traceId, spanId, parentSpanId, name, ts, durationMs, attributes`. Stored in `trace_span` (extension of the existing `trace_entry`).

- `src/schema/types.js` — `trace_entry` table (the extension point for `trace_span`).

## Interface

### New file: `src/engines/trace-span.ts`

```typescript
export interface TraceSpan {
  traceId: string
  spanId: string
  parentSpanId: string | null
  name: string
  ts: number
  durationMs: number | null
  attributes: Record<string, unknown>
}

export class Tracer {
  private active = new Map<string, TraceSpan>()
  constructor(private store: TraceStore) {}

  start(name: string, parentSpanId: string | null, attributes: Record<string, unknown> = {}): string {
    const span: TraceSpan = {
      traceId: parentSpanId ? this.traceIdOf(parentSpanId) : ulid(),
      spanId: ulid(),
      parentSpanId, name, ts: Date.now(), durationMs: null, attributes,
    }
    this.active.set(span.spanId, span)
    return span.spanId
  }

  async end(spanId: string, extra?: Record<string, unknown>): Promise<void> {
    const span = this.active.get(spanId)
    if (!span) return
    span.durationMs = Date.now() - span.ts
    if (extra) span.attributes = { ...span.attributes, ...extra }
    this.active.delete(spanId)
    await this.store.upsertTraceSpan(span)
  }

  // span(name, parent, fn) — auto start/end around async work
  async span<T>(name: string, parent: string | null, fn: () => Promise<T>, attrs?: Record<string, unknown>): Promise<T> {
    const id = this.start(name, parent, attrs)
    try { return await fn() } finally { await this.end(id) }
  }
}
```

### Wrap points (illustrative)

```typescript
// in capability handler dispatch:
await tracer.span('capability.execute', traceRoot, () => handler(input), { capabilityId })

// in SelectorHealer.heal:
await tracer.span('selector.try', parent, () => healer.heal(params))

// in ChromeGovernor cdp.send:
await tracer.span('cdp.send', parent, () => slave.send(payload), { method })
```

## Acceptance Criteria

1. A capability execution produces a `capability.execute` span with `traceId`, `spanId`, `parentSpanId`, `ts`, and a populated `durationMs` on end.
2. Nested calls (`conversation.send → capability.execute → cdp.send`) share one `traceId` and form a parent/child chain.
3. Spans persist to `trace_span` (via `upsertTraceSpan`).
4. `tracer.span()` auto-ends on both success and thrown error (finally).
5. `bun run devops gate` passes.

## Tests

`tests/unit/engines/trace-span.test.ts` (mock `TraceStore`):
- `span()` around an async fn → one span persisted, `durationMs` set, `parentSpanId` correct.
- nested `span()` → shared `traceId`, child's `parentSpanId` = parent's `spanId`.
- fn throws → span still ended + persisted.
