# Unit 4.10 — Built-in surface: DevopsConsoleSurface

**Source:** v3 Overview §3; `docs/master-plan-v3/PHASE-04-workspace-ui.md` §4.10
**Design Doc:** `docs/master-plan-v3/PHASE-04-workspace-ui.md` §4.10
**Depends on:** 4.3
**Produces:** In-app devops console.

---

## Context

A read-only in-app view of the devops tooling so the user can dogfood the build loop: `bun run devops report`, `devops invariants check`, and `devops truth scan`. Shows the current unit being worked on (if any), gate status, and coverage numbers.

Implement as React component at `builtinSurfaceId: 'devops-console'`. It shells out to the existing `devops` CLI (1.3 / `devops/index.ts`) via a small backend proxy route (we do NOT expose raw shell to the browser).

## Existing Baseline

- `devops/index.ts` + `devops/select.ts` — the devops orchestrator; `select` returns the current unit (currently `PLAN_PAUSED = true` → null, see `devops/select.ts`). The console surfaces that state honestly.
- `bun run devops gate` — full gate (typecheck + lint + test + invariants); the proxy wraps it.
- `WorkspaceManager` (4.1) — built-in surface id `devops-console`.
- `src/server/index.ts` — proxy route calls `Bun.spawn(['bun','run','devops', ...])` server-side.

## Interface

### New file: `web/workspace/src/surfaces/DevopsConsoleSurface.tsx`

```typescript
import { useEffect, useState } from 'react'

interface DevopsVM {
  currentUnit: string | null   // from `devops select` (may be null while paused)
  gate: { passed: boolean; lines: string[] }
  coverage: { pct: number; files: number }
  invariants: { violations: number; category: string }[]
}

export function DevopsConsoleSurface() {
  const [data, setData] = useState<DevopsVM | null>(null)
  useEffect(() => {
    fetch('/api/devops/snapshot').then((r) => r.json()).then(setData)
  }, [])

  async function rerun() {
    const r = await fetch('/api/devops/gate', { method: 'POST' })
    setData(await r.json())
  }

  return (/* current unit banner + gate status + coverage bar + invariants table + rerun button */)
}
```

### New route: `src/server/routes/devops-console.ts`

```typescript
import { spawnSync } from 'node:child_process'

export function devopsConsoleRouter() {
  return {
    routes: [
      { method: 'GET', path: '/api/devops/snapshot',
        handler: () => {
          const sel = spawnSync('bun', ['run', 'devops', 'select'], { encoding: 'utf8' })
          const gate = spawnSync('bun', ['run', 'devops', 'gate', '--report'], { encoding: 'utf8' })
          return { currentUnit: parseCurrentUnit(sel.stdout), gate: gate.stdout, coverage: parseCoverage(gate.stdout) }
        } },
      { method: 'POST', path: '/api/devops/gate',
        handler: () => ({ gate: spawnSync('bun', ['run', 'devops', 'gate'], { encoding: 'utf8' }).stdout }) },
    ],
  }
}
```

Server-side only — the browser never sees a shell.

## Acceptance Criteria

1. Console renders the current unit (or "paused" when `devops select` returns null).
2. `GET /api/devops/snapshot` returns gate status + coverage parsed from `devops gate --report`.
3. Rerun button POSTs `/api/devops/gate` and refreshes.
4. No shell invocation happens in the browser bundle (proxy only).
5. Renders without error against a seeded DB.
6. `bun run devops gate` passes.
