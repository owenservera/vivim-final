# Unit 4.3 — Workspace frontend host

**Source:** v3 Overview §3; `docs/master-plan-v3/PHASE-04-workspace-ui.md` §4.3
**Design Doc:** `docs/master-plan-v3/PHASE-04-workspace-ui.md` §4.3
**Depends on:** 4.1, 3.9
**Produces:** The shell React app that hosts panels + iframes for canvases.

---

## Context

The workspace host is a lightweight single-page app that turns a persisted `WorkspaceLayout` (4.1) into a live, rearrangeable UI. It renders built-in surfaces as React components (4.4–4.10) and canvases inside **sandboxed iframes** with the canvas-runtime (3.9) injected. It subscribes to the WebSocket protocol (3.11) for layout + canvas events and supports drag-and-drop panel rearrangement.

This is the project's first frontend: `web/` does not exist yet. React + Vite + Zustand are **new dependencies** to add to `package.json` (no UI framework is currently installed — see `dependencies` in `package.json`).

## Existing Baseline

- `web/canvas-runtime/index.js` (3.9) — the trusted script injected into every canvas iframe; the host loads it via `<script src>` (CSP `script-src 'self'` from 3.12).
- `WorkspaceManager` (4.1) — `getLayout`/`setLayout`/`rearrange` are the data source; REST calls hit `/api/workspace/*` (added here).
- `CanvasWsHub` (3.11) — `subscribe(client, canvasId)` is the realtime feed the host connects to.
- `src/server/index.ts` — serves static assets from `web/` in dev (Vite middleware or a static route).

### `web/workspace/src/store.ts` (sketch)

```typescript
import { create } from 'zustand'

export interface PanelVM {
  id: string
  kind: 'canvas' | 'builtin'
  canvasInstanceId?: string
  builtinSurfaceId?: string
  position: number
}

interface WorkspaceState {
  layoutName: string
  panels: PanelVM[]
  setLayout: (name: string, panels: PanelVM[]) => void
  rearrange: (orderedIds: string[]) => Promise<void> // POST /api/workspace/rearrange
}

export const useWorkspace = create<WorkspaceState>((set, get) => ({
  layoutName: 'default',
  panels: [],
  setLayout: (name, panels) => set({ layoutName: name, panels }),
  rearrange: async (orderedIds) => {
    await fetch('/api/workspace/rearrange', {
      method: 'POST',
      body: JSON.stringify({ layoutName: get().layoutName, orderedIds }),
    })
    // WS `workspace:layout_changed` will update panels reactively
  },
}))
```

### New route: `src/server/routes/workspace.ts`

```typescript
import type { WorkspaceManager } from '../../engines/workspace-manager.js'

export function workspaceRouter(manager: WorkspaceManager) {
  return {
    routes: [
      { method: 'GET', path: '/api/workspace/layout',
        handler: async (req) => ({ layout: await manager.getLayout(req.userId, req.query.name) }) },
      { method: 'POST', path: '/api/workspace/rearrange',
        handler: async (req) => ({ layout: await manager.rearrange(req.userId, req.body.orderedIds, req.body.layoutName) }) },
    ],
  }
}
```

## Acceptance Criteria

1. `web/workspace/` builds with Vite; React + Zustand resolve (new deps installed).
2. App renders the layout tree from `GET /api/workspace/layout`.
3. Canvas panels render as `<iframe sandbox="allow-scripts">` pointing at `vivim://canvas/<id>` with canvas-runtime loaded.
4. Built-in surface panels mount the matching component from `surfaces/index.ts`.
5. Drag-and-drop rearrange calls `rearrange`; a `workspace:layout_changed` WS frame updates the store.
6. `bun run devops gate` passes (biome covers `web/` once configured).
