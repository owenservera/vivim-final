# Unit 4.4 — Built-in surface: ConversationSurface

**Source:** v3 Overview §3; `docs/master-plan-v3/PHASE-04-workspace-ui.md` §4.4
**Design Doc:** `docs/master-plan-v3/PHASE-04-workspace-ui.md` §4.4
**Depends on:** 4.3
**Produces:** Conversation list + active conversation view + composer.

---

## Context

The primary surface most users open first: a list of conversations (grouped by project/topic — grouping lands in Phase 6 but the surface reads whatever the conversation store returns) plus an active-conversation transcript and a composer. The composer supports text, file upload, and capability quick-actions; it integrates with `AgenticConversationLoop` (2.11) to show live agent progress inline.

Implemented as a React component mounted by the workspace host (4.3) under `builtinSurfaceId: 'conversation-list'`.

## Existing Baseline

- `src/engines/conversation-manager.ts` — `ConversationManager` provides list/get/send primitives the surface calls via REST (`/api/conversations`).
- `src/engines/agentic-loop.ts` (2.11) — `AgenticConversationLoop` emits progress; the surface subscribes to `agent:state_changed` (from 4.5's event family) to render streaming updates.
- `WorkspaceManager` (4.1) — built-in surface registry maps `conversation-list` → this component.
- `src/server/index.ts` — REST layer; conversation endpoints already exist in 1.3's `conversation_list`/`conversation_send` capabilities.

## Interface

### New file: `web/workspace/src/surfaces/ConversationSurface.tsx`

```typescript
import { useEffect, useState } from 'react'

interface Conversation { id: string; title: string; providerId: string; updatedAt: number }
interface Message { id: string; role: 'user' | 'assistant' | 'system'; content: string; streaming?: boolean }

export function ConversationSurface() {
  const [conversations, setConversations] = useState<Conversation[]>([])
  const [activeId, setActiveId] = useState<string | null>(null)
  const [messages, setMessages] = useState<Message[]>([])
  const [draft, setDraft] = useState('')

  useEffect(() => {
    fetch('/api/conversations').then((r) => r.json()).then((d) => setConversations(d.conversations ?? d))
  }, [])

  // Live progress: append/stream assistant messages on agent:state_changed.
  useEffect(() => {
    const ws = new WebSocket(`${WS_BASE}/canvas`) // reuse app WS; filter by channel
    ws.onmessage = (e) => {
      const f = JSON.parse(e.data)
      if (f.type === 'agent:state_changed' && f.conversationId === activeId) {
        setMessages((m) => upsertStreaming(m, f))
      }
    }
    return () => ws.close()
  }, [activeId])

  async function send() {
    if (!activeId || !draft.trim()) return
    await fetch(`/api/conversations/${activeId}/send`, {
      method: 'POST', body: JSON.stringify({ message: draft }),
    })
    setDraft('')
  }

  return (/* list pane + transcript pane + composer with file input + capability chips */)
}
```

Capability quick-actions are rendered from `GET /api/capabilities?category=conversation` and POST to the capability endpoint (1.3).

## Acceptance Criteria

1. Surface lists conversations from `GET /api/conversations`.
2. Selecting a conversation loads its messages; composer `send` POSTs to `/api/conversations/:id/send`.
3. Assistant messages stream in via the `agent:state_changed` WS channel (no full reload).
4. Composer supports a file `<input type="file">` and capability quick-action chips.
5. Renders without error against a seeded DB (acceptance: all 7 built-in surfaces render).
6. `bun run devops gate` passes.
