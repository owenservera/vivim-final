# Unit 2.8 — LiveCapabilityRegistry — inline handler sandbox

**Source:** v3 Overview §1.3, §1.9; `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.8
**Design Doc:** `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.8
**Depends on:** 2.7, 2.13
**Produces:** Inline handlers execute in `SandboxRunner` with permission tokens.

---

## Context

A live capability may carry an `inline` handler (`handlerSpec.kind === 'inline'`, `code` string). This code must **never** run via the unguarded `new Function(...)` path that `StreamParserEngine.loadInlineParser` uses today (`src/engines/stream-parser.ts:195`). Instead it runs inside `SandboxRunner` (2.13), which enforces CPU/memory budgets and capability-based permission tokens, and writes a `sandbox_audit` row for every invocation.

## Existing Baseline

- `src/engines/live-capability-registry.ts` — `LiveCapabilitySpec.handlerSpec.kind: 'inline'` + `code` (2.7).
- `src/engines/stream-parser.ts` — `loadInlineParser` (line 190) uses `new Function('module','exports',code)` (line 195): the **attack surface** this unit must avoid. Inline live handlers MUST NOT use this.
- `src/engines/sandbox-runner.ts` — `SandboxRunner.run(code, input, permissions)` (2.13) returns `{ ok, output, error, auditId }`.

## Interface

### Extension in `src/engines/live-capability-registry.ts`

```typescript
import type { SandboxRunner } from './sandbox-runner.js'

export class LiveCapabilityRegistry extends UnifiedCapabilityRegistry {
  constructor(
    private liveStore: LiveCapabilityStore,
    private bus: CapabilityEventBus,
    private sandbox: SandboxRunner,           // injected (2.13)
  ) { super() }

  private specToUnifiedCapability(spec: LiveCapabilitySpec, id: string): UnifiedCapability {
    if (spec.handlerSpec.kind === 'inline') {
      const code = spec.handlerSpec.code!
      const permissions = this.permissionsFor(spec)
      return {
        ...base,
        handler: async (input) => {
          const res = await this.sandbox.run(code, input, permissions)
          if (!res.ok) throw new EngineError(`Inline handler failed: ${res.error}`)
          return res.output
        },
      }
    }
    // mcp / http handled in 2.9 / 2.10
  }

  private permissionsFor(spec: LiveCapabilitySpec) {
    return { canFetch: [], canReadFile: [], canWriteFile: [], canUseClipboard: true }
  }
}
```

## Acceptance Criteria

1. An `inline` live capability's handler executes inside `SandboxRunner` (never `new Function` directly).
2. Every invocation produces a `sandbox_audit` row (`auditId` returned).
3. A handler exceeding its CPU/memory budget is aborted and surfaces an error (no process crash).
4. A handler lacking the required permission token fails closed.
5. `bun run devops gate` passes; `invariants check --category F` (no eval outside SandboxRunner) passes for this path.

## Tests

`tests/unit/engines/live-capability-inline.test.ts`:
- inline handler returning a value → `registry.execute` returns it; `sandbox.run` called exactly once.
- handler that calls a forbidden global → throws, audit row written.
- budget-exceeding handler → `ok:false`, error surfaced.
