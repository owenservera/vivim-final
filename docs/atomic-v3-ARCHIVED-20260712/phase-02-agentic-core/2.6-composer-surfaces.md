# Unit 2.6 — CapabilityComposer — surface export (CLI/UI/MCP/API)

**Source:** v3 Overview §1.2; `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.6
**Design Doc:** `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.6
**Depends on:** 2.4
**Produces:** Composites auto-exported to all five surfaces.

---

## Context

A composite registered via `CapabilityComposer.registerComposite` (2.4) must behave like any other capability: registering it in `UnifiedCapabilityRegistry` automatically generates a CLI command, UI action, MCP tool, API endpoint, and workflow node. No extra wiring should be needed — this is what makes composites first-class.

## Existing Baseline

- `src/engines/unified-registry.ts` — `UnifiedCapability` carries `cliCommand`, `uiAction`, `mcpToolName`, `apiEndpoint`, `workflowNodeType` (lines 29–33) and `register()` (line 65) validates surface requirements. `exportForCli()` (129), `exportForMcp()` (137) produce surface payloads.
- `docs/atomic-v3/phase-01-stabilization/1.3-capability-bootstrap.md` — `registerDefaultCapabilities` already demonstrates auto surface export for leaf capabilities (`makeCapability` defaults `surfaces: ['cli','ui','workflow','mcp','api']`).

## Interface

### Extension in `src/engines/capability-composer.ts`

```typescript
import type { UnifiedCapability, CapabilitySurface } from './unified-registry.js'

export class CapabilityComposer {
  /** Build the UnifiedCapability for a composite, auto-filling all five surfaces. */
  private toUnifiedCapability(c: CompositeCapability): UnifiedCapability {
    const surfaces: CapabilitySurface[] = ['cli', 'ui', 'workflow', 'mcp', 'api']
    return {
      id: `composite:${c.id}`,
      slug: c.slug,
      name: c.name,
      description: c.description,
      category: 'composite',
      surfaces,
      inputSchema: { type: 'object', properties: {} },
      outputSchema: { type: 'object' },
      handler: (input, ctx) => this.execute(c.id, input, ctx),
      cliCommand: { name: `composite ${c.slug}`, aliases: [], examples: [] },
      uiAction: { component: 'composite-run', position: 'palette', order: 0 },
      workflowNodeType: `composite:${c.slug}`,
      mcpToolName: c.slug,
      apiEndpoint: { method: 'POST', path: `/api/composite/${c.slug}` },
      isAsync: true,
      requiresConfirmation: false,
      tags: ['composite'],
      isComposite: true,
      compositeId: c.id,
    }
  }
}
```

## Acceptance Criteria

1. After `registerComposite`, `registry.exportForCli()`, `exportForMcp()`, and the API router all expose the composite.
2. The composite's `mcpToolName` equals its slug and resolves via `registry.getBySlug()`.
3. Surface metadata matches `UnifiedCapability` validation (no `EngineError` on `register`).
4. Removing (`unregister`) the composite purges it from all five surfaces.
5. `bun run devops gate` passes; surface-export path ≥80% covered.
