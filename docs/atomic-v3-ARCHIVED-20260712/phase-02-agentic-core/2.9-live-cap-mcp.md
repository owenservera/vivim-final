# Unit 2.9 — UnifiedCapabilityRegistry — MCP handler kind

**Source:** v3 Overview §1.3; `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.9
**Design Doc:** `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.9
**Depends on:** 2.7
**Produces:** Live capability whose handler is an MCP tool call.

---

## Context

A live capability may delegate to an external MCP tool: `handlerSpec = { kind: 'mcp', serverId, toolName }`. Execution forwards to `McpClientAdapter.callTool`, with connection lifecycle managed by the registry (connect on first use, reuse, disconnect on revoke).

## Existing Baseline

- `src/engines/live-capability-registry.ts` — `LiveCapabilitySpec.handlerSpec.kind: 'mcp'` (2.7).
- `src/engines/mcp-client-adapter.ts` — `McpClientAdapter` exposes `callTool(serverId, toolName, args)` and connection management. (Verify the exact signature before implementation; the contract here is `callTool(toolName, args)` against a connected server.)

## Interface

### Extension in `src/engines/live-capability-registry.ts`

```typescript
import type { McpClientAdapter } from './mcp-client-adapter.js'

export class UnifiedCapabilityRegistry extends UnifiedCapabilityRegistry {
  constructor(
    private liveStore: LiveCapabilityStore,
    private bus: CapabilityEventBus,
    private sandbox: SandboxRunner,
    private mcp: McpClientAdapter,
  ) { super() }

  private specToUnifiedCapability(spec: LiveCapabilitySpec, id: string): UnifiedCapability {
    if (spec.handlerSpec.kind === 'mcp') {
      const { serverId, toolName } = spec.handlerSpec
      return {
        ...base,
        handler: async (input) => {
          const conn = await this.mcp.connect(serverId)
          return this.mcp.callTool(conn, toolName!, input)
        },
      }
    }
    // inline (2.8) / http (2.10) handled elsewhere
  }
}
```

On `revokeLive`, the registry disconnects any held MCP connection for that capability.

## Acceptance Criteria

1. An `mcp` live capability's handler calls `mcp.callTool` with the configured `serverId`/`toolName`.
2. The MCP connection is established lazily and reused across invocations.
3. `revokeLive` disconnects the associated MCP connection.
4. MCP tool failure is surfaced as a capability error (no silent success).
5. `bun run devops gate` passes; MCP path ≥80% covered with a mocked `McpClientAdapter`.
