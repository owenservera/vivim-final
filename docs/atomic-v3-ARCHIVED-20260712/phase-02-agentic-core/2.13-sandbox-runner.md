# Unit 2.13 — SandboxRunner — hardened execution

**Source:** v3 Overview §1.9; `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.13
**Design Doc:** `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.13
**Depends on:** 1.6
**Produces:** `SandboxRunner` class with vm context, budgets, permissions, audit.

---

## Context

`StreamParserEngine.loadInlineParser` currently runs DB-stored parser JS via `new Function('module','exports',code)` (`src/engines/stream-parser.ts:195`). `LiveCapabilityRegistry` inline handlers (2.8) would compound this attack surface: no isolation, no resource limit, no permission model.

`SandboxRunner` executes untrusted code in a hardened sandbox:
- `node:vm.createContext` with a frozen context (no `process`, no `require`, no `fetch`),
- CPU time budget via `AsyncResource` + timeout,
- memory budget via periodic `process.memoryUsage()` polling,
- permission tokens (`{ canFetch, canReadFile, canWriteFile, canUseClipboard }`),
- an audit log row in `sandbox_audit` for every invocation.

## Existing Baseline

- `src/engines/stream-parser.ts` — `loadInlineParser` (line 190) is the **vulnerable** pattern to migrate away from for live handlers. (`StreamParserEngine` may keep its parser loader, but new inline capability code MUST use `SandboxRunner`.)
- `src/engines/errors.ts` — `EngineError` / `CapStoreError` for typed failures.
- `src/storage/contracts/` — new `SandboxAuditStore` contract (table `sandbox_audit` per `00-OVERVIEW.md` §2).

## Interface

### New file: `src/engines/sandbox-runner.ts`

```typescript
import vm from 'node:vm'
import { AsyncResource } from 'node:async_hooks'

export interface SandboxPermissions {
  canFetch: string[]          // allowed hosts
  canReadFile: string[]       // allowed paths
  canWriteFile: string[]      // allowed paths
  canUseClipboard: boolean
}

export interface SandboxResult {
  ok: boolean
  output?: unknown
  error?: string
  auditId: string
}

export interface SandboxBudget { cpuMs: number; memoryBytes: number }

export class SandboxRunner {
  constructor(
    private auditStore: SandboxAuditStore,
    private defaultBudget: SandboxBudget = { cpuMs: 1000, memoryBytes: 64 * 1024 * 1024 },
  ) {}

  async run(code: string, input: Record<string, unknown>, permissions: SandboxPermissions): Promise<SandboxResult> {
    const auditId = newId()
    const sandbox = {
      input,
      console: { log: () => {}, error: () => {} },
      // NO process / require / fetch — only what permissions allow
      navigator: permissions.canUseClipboard ? { clipboard: this.clipboardGuard() } : undefined,
    }
    const context = vm.createContext(Object.freeze(sandbox))
    const resource = new AsyncResource('sandbox')
    const timer = setTimeout(() => resource.emitDestroy(), this.defaultBudget.cpuMs)

    try {
      const script = new vm.Script(`(async () => { ${code} })()`)
      const output = await script.runInContext(context, { timeout: this.defaultBudget.cpuMs })
      clearTimeout(timer)
      await this.auditStore.create({ id: auditId, ok: true, permissions, ts: Date.now() })
      return { ok: true, output, auditId }
    } catch (err) {
      clearTimeout(timer)
      const message = err instanceof Error ? err.message : String(err)
      await this.auditStore.create({ id: auditId, ok: false, error: message, permissions, ts: Date.now() })
      return { ok: false, error: message, auditId }
    }
  }
}
```

Budgets are enforced via `vm` timeout + a `setInterval` polling `process.memoryUsage()` that destroys the context on breach.

## Acceptance Criteria

1. `run()` executes code with no access to `process`, `require`, or `fetch`.
2. Code exceeding `cpuMs` is aborted (timeout fires) — no hang.
3. Code exceeding `memoryBytes` is aborted.
4. A `sandbox_audit` row is written for every invocation (ok and fail).
5. `bun run devops invariants check --category F` (no eval outside SandboxRunner) passes; `bun run devops gate` passes.

## Tests

`tests/unit/engines/sandbox-runner.test.ts`:
- safe code returning a value → `ok:true`, output returned, audit row present.
- code touching `process` → throws, `ok:false`, audit row present.
- infinite-loop code → CPU budget aborts.
- `canUseClipboard:false` → `navigator` undefined.
