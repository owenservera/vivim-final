# Unit 2.3 — IntentDecomposer engine — clarification flow

**Source:** v3 Overview §1.1; `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.3
**Design Doc:** `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.3
**Depends on:** 2.2
**Produces:** Interactive clarification when confidence < threshold.

---

## Context

When neither the template (2.1) nor LLM (2.2) strategy produces a confident DAG, `IntentDecomposer` emits an `intent:clarify` event on the `CapabilityEventBus` with proposed options. The frontend (Phase 4) renders it as an inline prompt. A timeout defaults to the most-likely interpretation and logs an audit entry.

This is the third strategy in the chain: template → LLM → clarification.

## Existing Baseline

- `src/engines/capability-event-bus.ts` — `CapabilityEventBus.emit(type, payload)`. New event type `intent:clarify` is added here.
- `src/engines/intent-decomposer.ts` — `decompose` (2.1) and `decomposeWithLlm` (2.2) feed this flow.
- `src/engines/unified-registry.ts` — candidate capabilities for clarification options come from `registry.list({ category })`.

## Interface

### Extension in `src/engines/intent-decomposer.ts`

```typescript
import type { CapabilityEventBus } from './capability-event-bus.js'

export interface ClarificationOption {
  label: string
  capabilitySlug: string
  inputMapping: Record<string, unknown>
}

export interface IntentClarification {
  goal: string
  question: string
  options: ClarificationOption[]
  timeoutMs: number
}

export class IntentDecomposer {
  constructor(
    private store: IntentDecomposerStore,
    private registry: UnifiedCapabilityRegistry,
    private llm: LocalModelAdapter,
    private bus: CapabilityEventBus,
  ) {}

  /** Emits intent:clarify and returns the proposed options (frontend resolves). */
  async clarify(goal: string, ctx: DecomposeContext, confidence: number): Promise<IntentClarification> {
    if (confidence >= this.threshold) {
      throw new Error('clarify called with sufficient confidence')
    }
    const options = await this.proposeOptions(goal, ctx)
    const clarification: IntentClarification = {
      goal, question: this.questionFor(goal, options), options, timeoutMs: 30_000,
    }
    this.bus.emit({ type: 'intent:clarify', clarification, ts: Date.now() })
    return clarification
  }

  private proposeOptions(goal: string, ctx: DecomposeContext): Promise<ClarificationOption[]> { /* top-N candidate slugs */ }
  private questionFor(goal: string, options: ClarificationOption[]): string { /* ... */ }
}
```

The `intent:clarify` event payload type is registered in `capability-event-bus.ts`.

## Acceptance Criteria

1. When `confidence < threshold`, `clarify()` emits exactly one `intent:clarify` event carrying ≥2 options.
2. Each option's `capabilitySlug` resolves via `registry.getBySlug()`.
3. No `intent:clarify` is emitted when confidence ≥ threshold (guarded).
4. On timeout the caller defaults to `options[0]` and writes an audit log entry (see `AuditTrail`).
5. `bun run devops gate` passes; clarification path ≥80% covered.
