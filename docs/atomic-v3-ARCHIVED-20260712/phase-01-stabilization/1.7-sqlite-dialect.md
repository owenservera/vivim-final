# Unit 1.7 — Fix TelemetryAggregator SQL dialect (Postgres → SQLite)

**Source:** v3 Overview observed issue; `src/storage/impl/telemetry-store-impl.ts` uses `$1, $2...` params + `ON CONFLICT DO NOTHING ON CONSTRAINT "table_pkey" DO UPDATE SET ...` which is Postgres syntax
**Design Doc:** `docs/master-plan-v3/PHASE-01-stabilization.md` §1.7
**Depends on:** —
**Produces:** `TelemetryAggregator.runAllCycles()` actually executes against SQLite without error.

---

## Context

The Prisma datasource is SQLite (`prisma/schema.prisma:6` declares `provider = "sqlite"`). But `TelemetryStoreImpl` uses Postgres-style parameter placeholders (`$1, $2`) and `ON CONFLICT` syntax that SQLite parses differently.

SQLite uses `?` for placeholders and supports `ON CONFLICT(column) DO UPDATE SET ...` (without `ON CONSTRAINT` and without `EXCLUDED` table reference — it uses the column names directly or `excluded.column` lowercase).

The current code would throw on every cycle. The devops gate doesn't catch it because the cycles never actually run during the gate (the aggregator is not started in test mode).

## Files to Modify

1. `src/storage/impl/telemetry-store-impl.ts` — rewrite raw SQL.
2. `src/engines/telemetry-aggregator.ts:buildScheduleSql` — verify generated SQL is SQLite-compatible (it should be, since it doesn't use `$N` params directly, but the column-quoting uses `"col"` which SQLite accepts).
3. `tests/unit/engines/telemetry-aggregator.test.ts` — add a test that actually executes a cycle against an in-memory SQLite DB seeded with sample data.

## Specific Changes

### `TelemetryStoreImpl.executeAggregationQuery`

**Before:**
```typescript
async executeAggregationQuery(sql: string, params: unknown[]): Promise<Row[]> {
  const rows = (await this.p.$queryRawUnsafe(sql, ...params)) as Row[] | null
  return rows ?? []
}
```

This passes positional params but `$queryRawUnsafe` on SQLite Prisma expects `?` placeholders, not `$N`. The SQL string must use `?` and params are positional.

**After:**
```typescript
async executeAggregationQuery(sql: string, params: unknown[]): Promise<Row[]> {
  // SQLite Prisma: $queryRawUnsafe accepts ? placeholders + positional params.
  const sqliteSql = sql.replace(/\$(\d+)/g, '?')
  const rows = (await this.p.$queryRawUnsafe(sqliteSql, ...params)) as Row[] | null
  return rows ?? []
}
```

This is a minimal fix. ADR-001 (Phase 10) will document whether to keep the translation layer or commit fully to `?` syntax in the engine.

### `TelemetryStoreImpl.upsertRows`

**Before (Postgres):**
```typescript
const updates = columns.map((c) => `"${c}" = EXCLUDED."${c}"`).join(', ')
const sql =
  `INSERT INTO "${table}" (${cols.join(', ')}) VALUES (${placeholders.join(', ')}) ` +
  `ON CONFLICT DO NOTHING ON CONSTRAINT "${table}_pkey" DO UPDATE SET ${updates}`
```

**After (SQLite):**
```typescript
const updates = columns.map((c) => `"${c}" = excluded."${c}"`).join(', ')
const sql =
  `INSERT INTO "${table}" (${cols.join(', ')}) VALUES (${placeholders.map((_, i) => '?').join(', ')}) ` +
  `ON CONFLICT DO UPDATE SET ${updates}`
```

Notes:
- Placeholders change from `$1, $2...` to `?, ?...`.
- `ON CONFLICT DO NOTHING ON CONSTRAINT "x_pkey"` becomes `ON CONFLICT DO UPDATE` (SQLite infers the conflict target from the primary key automatically; if you want to be explicit, use `ON CONFLICT(id)`).
- `EXCLUDED."col"` becomes `excluded."col"` (SQLite is case-insensitive but lowercase is conventional).

### `TelemetryStoreImpl.getHealthHistory`, `getSelectorHealthHistory`, `getDailySummary`, `getCrossProviderSummary`

Same pattern: `$N` → `?` placeholder translation. Can be done via the same regex replacement in `executeAggregationQuery` (already handles it).

### `TelemetryStoreImpl.countRows`, `deleteRows`

`LIMIT` on `DELETE` is not supported in SQLite. Replace:

**Before:**
```typescript
let sql = `DELETE FROM "${table}" WHERE ${where}`
if (maxRows != null) sql += ` LIMIT ${maxRows}`
```

**After:**
```typescript
let sql = `DELETE FROM "${table}" WHERE rowid IN (SELECT rowid FROM "${table}" WHERE ${where} LIMIT ${maxRows ?? -1})`
```

(SQLite's `rowid` is implicit on every row-backed table.)

## Acceptance Criteria

1. `TelemetryAggregator.runCycle('health_snapshot')` executes against a seeded SQLite DB without throwing.
2. `TelemetryAggregator.runCycle('capability_telemetry')` writes ≥1 row to `capability_telemetry`.
3. `TelemetryAggregator.runAllCycles()` returns 4 `CycleResult` rows with no `error` field.
4. `TelemetryAggregator.runRetention()` deletes rows past retention without error.
5. `bun run devops gate` passes.

## Tests

`tests/unit/engines/telemetry-aggregator.test.ts` — extend:

```typescript
import { describe, test, expect, beforeAll, afterAll } from 'bun:test'
import { TelemetryAggregator } from '@/engines/telemetry-aggregator'
import { TelemetryStoreImpl } from '@/storage/impl/telemetry-store-impl'
import { ConfigManager } from '@/engines/config-manager'
import { getDb, closeDb } from '@/storage/db'

describe('TelemetryAggregator SQLite execution', () => {
  let agg: TelemetryAggregator
  
  beforeAll(async () => {
    const db = getDb()
    // Seed sample data into outcome, provider_health, etc.
    await db.prisma.outcome.create({ data: { /* ... */ } })
    
    const store = new TelemetryStoreImpl(db.prisma as never)
    const configMgr = new ConfigManager(/* mock store */)
    agg = new TelemetryAggregator(store, configMgr)
  })
  
  afterAll(async () => { await closeDb() })
  
  test('runCycle health_snapshot succeeds', async () => {
    const result = await agg.runCycle('health_snapshot')
    expect(result.error).toBeUndefined()
    expect(result.rowsWritten).toBeGreaterThanOrEqual(0)
  })
  
  test('runCycle capability_telemetry writes rows', async () => {
    const result = await agg.runCycle('capability_telemetry')
    expect(result.error).toBeUndefined()
    // rowsWritten depends on seeded data
  })
  
  test('runAllCycles returns 4 results', async () => {
    const results = await agg.runAllCycles()
    expect(results.length).toBe(4)
    for (const r of results) {
      expect(r.error).toBeUndefined()
    }
  })
  
  test('runRetention deletes without error', async () => {
    const results = await agg.runRetention()
    expect(Array.isArray(results)).toBe(true)
  })
})
```
