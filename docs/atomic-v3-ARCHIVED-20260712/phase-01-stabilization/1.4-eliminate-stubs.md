# Unit 1.4 — Eliminate all stub markers in engines

**Source:** v3 Overview §1.7; `devops/truth/scanner.ts` MIXED/STUB classifications
**Design Doc:** `docs/master-plan-v3/PHASE-01-stabilization.md` §1.4
**Depends on:** —
**Produces:** Every `src/engines/*.ts` file classified REAL by `bun run devops truth scan`.

---

## Context

The truth scanner classifies files as REAL/STUB/MIXED/INTERFACE_ONLY based on heuristics. The current state shows several MIXED and STUB files in `src/engines/`. Each represents an unfinished implementation that future v3 work would otherwise inherit.

## Known Stubs to Fix

Run `bun run devops truth scan --verbose` to get the live list. As of the v3 planning session, the following stubs are known:

1. **`src/engines/harness-runtime.ts:evaluateCondition`** — returns `cond.type === 'selector_exists'` always. Needs real evaluation via `SemanticGroundingEngine.resolve` for selector_exists, `getPageState().url` regex for url_matches, etc.

2. **`src/engines/provider-discovery.ts:screenshot`** — returns `Buffer.from('placeholder-screenshot')`. Needs `governor.cdp.captureScreenshot(slaveId)`.

3. **`src/engines/provider-discovery.ts:getAccessibilityTree`** — returns a placeholder root node. Needs CDP `Accessibility.getFullAXTree` call (pattern from `semantic-grounding.ts`).

4. **`src/engines/agentic-loop.ts`** — the engine exists but is "in a parallel universe" — never invoked from `ConversationManager`. The engine itself is real but disconnected. Wiring happens in Unit 2.12; this unit only ensures the engine's internals are real.

5. **`src/engines/conversation-manager.ts:createConversation`** — uses a fake `providerSessionId` of `session_${providerId}_${Date.now()}`. Should resolve or create a real `ProviderSession` row.

6. **`src/engines/conversation-manager.ts:truncate`** — calls `store.deleteConversation(msg.id)` on individual messages; should call a `deleteMessage` method (which ConversationStoreImpl doesn't have — add it).

7. **`src/engines/stream-parser.ts:loadInlineParser`** — uses `new Function('module', 'exports', code)` (security concern; full hardening is Unit 2.13, but this unit ensures the surrounding logic is complete: cache key handling, error reporting).

## Implementation Pattern

For each stub:

1. Locate the stub via `devops truth scan --verbose | Select-String STUB,MIXED`.
2. Read the engine's interface contract (its own `export interface` block).
3. Implement the missing logic to satisfy the contract.
4. Write a unit test that exercises the previously-stubbed path.
5. Verify the file reclassifies as REAL: `bun run devops truth scan --verbose | Select-String "<filename>"`.

## Acceptance Criteria

1. `bun run devops truth scan` reports zero STUB files in `src/engines/`.
2. `bun run devops truth scan` reports zero MIXED files in `src/engines/`.
3. For each previously-stubbed method, a unit test exists that exercises it.
4. `bun run devops gate` passes.

## Tests

Add `tests/unit/engines/<engine>.test.ts` entries for each previously-stubbed method. Each test:
- Constructs the engine with mock dependencies.
- Invokes the previously-stubbed method.
- Asserts a non-stub output (e.g., real Buffer from screenshot, real AXTree from getAccessibilityTree).
