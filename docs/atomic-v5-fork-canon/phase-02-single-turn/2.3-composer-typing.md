# Unit 2.3 — Provider-Specific Composer Typing via CDP

**Phase:** 2 | **ID:** 2.3 | **Dependencies:** 2.2

## Problem

Each provider has a different composer element type and requires different typing strategies:
- ChatGPT: `<textarea id="prompt-textarea">` — standard textarea, `el.value = text` works
- Claude: `<div contenteditable>` — React-managed, requires `document.execCommand('insertText')` or React synthetic events
- Gemini: `<div class="ql-editor" contenteditable>` — Quill editor, requires different event dispatch

## Spec

### Provider Typing Strategies

```typescript
enum ComposerType {
  TEXTAREA = 'textarea',
  CONTENT_EDITABLE = 'contenteditable',
  QUILL = 'quirl',
  CODEMIRROR = 'codemirror',
}

// From endpoint manifest: endpoint.composer_type
// seeds/providers/chatgpt.json: composer_type: "textarea"
// seeds/providers/claude.json: composer_type: "contenteditable"
// seeds/providers/gemini.json: composer_type: "contenteditable" (Quill)
```

### Typing Implementation

```typescript
// conversation-manager.ts or a new helper

async function typeMessage(
  governor: ChromeGovernor,
  slaveId: string,
  selector: string,
  text: string,
  composerType: string,
): Promise<void> {
  const safeSelector = JSON.stringify(selector)
  const safeText = JSON.stringify(text)

  let expression: string

  switch (composerType) {
    case 'textarea':
      // Standard textarea — set value + dispatch events
      expression = `(() => {
        const el = document.querySelector(${safeSelector});
        if (!el) throw new Error('Composer not found');
        el.focus();
        const nativeInputValueSetter = Object.getOwnPropertyDescriptor(
          window.HTMLTextAreaElement.prototype, 'value'
        )?.set;
        nativeInputValueSetter?.call(el, ${safeText});
        el.dispatchEvent(new Event('input', { bubbles: true }));
        el.dispatchEvent(new Event('change', { bubbles: true }));
      })()`
      break

    case 'contenteditable':
      // ContentEditable div — focus + execCommand
      expression = `(() => {
        const el = document.querySelector(${safeSelector});
        if (!el) throw new Error('Composer not found');
        el.focus();
        // Clear existing
        el.textContent = '';
        // Use execCommand for React compatibility
        document.execCommand('insertText', false, ${safeText});
      })()`
      break

    case 'quill':
      // Quill editor — use Quill API
      expression = `(() => {
        const el = document.querySelector(${safeSelector});
        if (!el) throw new Error('Composer not found');
        const quill = el.__quill || el.closest('.ql-container')?.__quill;
        if (quill) {
          quill.setContents([]);
          quill.insertText(0, ${safeText});
        } else {
          el.focus();
          el.textContent = ${safeText};
          el.dispatchEvent(new Event('input', { bubbles: true }));
        }
      })()`
      break

    default:
      // Generic fallback — try textarea approach
      expression = `(() => {
        const el = document.querySelector(${safeSelector});
        if (!el) throw new Error('Composer not found');
        el.focus();
        el.value = ${safeText};
        el.dispatchEvent(new Event('input', { bubbles: true }));
      })()`
  }

  await governor.cdp.send(slaveId, 'Runtime.evaluate', { expression })
}
```

### Getting Composer Type from Resolution

The `ResolvedCapability` from `CapabilityResolutionEngine.resolve()` contains composer information. The endpoint manifest specifies `composer_type` for each endpoint:

```typescript
// In conversation-manager.ts send():
const composerCap = resolved.composer[0]
const selector = composerCap?.selector ?? 'textarea'

// Get composer type from endpoint manifest
const endpoints = await db.getProviderEndpoints(conv.providerId)
const chatEndpoint = endpoints.find(e => e.endpoint_type === 'chat')
const composerType = chatEndpoint?.composer_type ?? 'textarea'

await typeMessage(this.governor, slaveId, selector, message, composerType)
```

### Selector from Capability

The `ResolvedCapability` has a `selector` field but it may not be populated correctly. The endpoint manifest is the source of truth:

```typescript
// From seeds/providers/chatgpt.json endpoints:

```
