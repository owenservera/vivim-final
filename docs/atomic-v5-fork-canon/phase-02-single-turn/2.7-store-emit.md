# Unit 2.7 — Store Message + Blocks + Emit Events

**Phase:** 2 | **ID:** 2.7 | **Dependencies:** 2.6

## Problem

The store + emit step in `conversation-manager.ts:253` works but has gaps:
1. The user's message is never stored — only the assistant response is persisted
2. WebSocket events are emitted but the WebSocket bridge doesn't forward to connected frontends
3. The conversation's message count increments but doesn't track user vs assistant messages

## Spec

### WebSocket Event Forwarding

The WebSocket bridge in `websocket.ts` subscribes to events but doesn't automatically forward `conversation:*` events to connected frontends. Add automatic forwarding:

```typescript
// In server bootstrap, after creating the event bus:
eventBus.on('conversation:complete', (event) => {
  // Forward to all connected WebSocket clients subscribed to this conversation
  for (const [ws, session] of wsSessions) {
    if (session.subscriptions.has(`conversation:${event.conversationId}`)) {
      ws.send(JSON.stringify(event))
    }
  }
})

eventBus.on('conversation:block', (event) => {
  // Forward streaming blocks
  for (const [ws, session] of wsSessions) {
    if (session.subscriptions.has(`conversation:${event.conversationId}`)) {
      ws.send(JSON.stringify(event))
    }
  }
})

eventBus.on('conversation:error', (event) => {
  for (const [ws, session] of wsSessions) {
    if (session.subscriptions.has(`conversation:${event.conversationId}`)) {
      ws.send(JSON.stringify(event))
    }
  }
})
```

### WebSocket Session Registry Enhancement

The current `handleWebSocket` has a sessions map but it's module-scoped. Export it for the event forwarder:

```typescript
// websocket.ts
export const wsSessions = new Map<string, WsSession>()

// In open():
wsSessions.set(wsId, session)

// In close():
wsSessions.delete(wsId)
```

### Event Flow

```
ConversationManager.send()
  → store.createMessage(user)
  → store.createMessage(assistant)
  → blocks.storeBlocks()
  → store.updateConversation()
  → eventBus.emit('conversation:complete', { conversationId, message })
    → WebSocket forwarder picks up
      → ws.send(JSON.stringify(event)) to subscribed frontends
```
