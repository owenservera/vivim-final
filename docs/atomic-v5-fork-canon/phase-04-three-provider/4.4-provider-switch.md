# Unit 4.4 — Multi-Provider Conversation Switching in Frontend

**Phase:** 4 | **ID:** 4.4 | **Dependencies:** 4.1, 4.2, 4.3

## Problem

The user should be able to have active conversations with all three providers simultaneously and switch between them in the frontend. Currently, the sandbox has no conversation list or provider switcher.

## Spec

### Conversation List Component

```tsx
// web/sandbox/src/features/conversation-list.tsx

interface ConversationListItem {
  id: string
  providerId: string
  title: string | null
  messageCount: number
  lastMessageAt: number
}

export function ConversationList({ onSelect }: { onSelect: (id: string) => void }) {
  const [conversations, setConversations] = useState<ConversationListItem[]>([])
  const [selected, setSelected] = useState<string | null>(null)

  useEffect(() => {
    fetch('/api/conversations')
      .then(r => r.json())
      .then(setConversations)
  }, [])

  const handleNew = async (providerId: string) => {
    const resp = await fetch('/api/conversations', {
      method: 'POST',
      body: JSON.stringify({ providerId })
    })
    const conv = await resp.json()
    setConversations(prev => [conv, ...prev])
    onSelect(conv.id)
    setSelected(conv.id)
  }

  return (
    <div className="w-64 border-r p-2 overflow-y-auto">
      {/* New conversation buttons */}
      <div className="flex gap-1 mb-2">
        <button onClick={() => handleNew('chatgpt')} title="New ChatGPT">🤖</button>
        <button onClick={() => handleNew('claude')} title="New Claude">🪨</button>
        <button onClick={() => handleNew('gemini')} title="New Gemini">💎</button>
      </div>
      
      {/* Conversation list */}
      {conversations.map(conv => (
        <button
          key={conv.id}
          onClick={() => { onSelect(conv.id); setSelected(conv.id) }}
          className={`w-full text-left p-2 rounded mb-1 ${
            selected === conv.id ? 'bg-blue-100' : 'hover:bg-gray-100'
          }`}
        >
          <div className="flex items-center gap-2">
            <ProviderIcon providerId={conv.providerId} />
            <span className="truncate text-sm">
              {conv.title || `${conv.providerId} conversation`}
            </span>
          </div>
          <div className="text-xs text-gray-400">
            {conv.messageCount} messages
          </div>
        </button>
      ))}
    </div>
  )
}
```

### Provider-Specific Active State

Each provider conversation has its own Chrome slave. The slave must be alive when the user switches to that conversation. The FleetSupervisor manages multiple slaves simultaneously.

### No State Bleed

When switching from ChatGPT to Claude:
1. ChatGPT slave stays running (don't kill it)
2. Claude slave starts (or is already running)
3. Frontend loads Claude conversation messages
4. Chrome page shows Claude's UI
5. No ChatGPT DOM or state leaks into Claude conversation

## Test

```typescript
test('multiple provider conversations coexist', async () => {
  const conv1 = await cm.createConversation('chatgpt')
  const conv2 = await cm.createConversation('claude')
  
  await cm.send(conv1.id, 'Hello from ChatGPT')
  await cm.send(conv2.id, 'Hello from Claude')
  
  // Both should work independently
  const msgs1 = await cm.getMessages(conv1.id)
  const msgs2 = await cm.getMessages(conv2.id)
  
  expect(msgs1.length).toBeGreaterThan(0)
  expect(msgs2.length).toBeGreaterThan(0)
})
```
