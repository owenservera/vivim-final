# Phase 23 — Logged-in Provider Discovery CLI (Roadmap + Atomic Task List)

> Generated by `devops-roadmap` research pass (2026-07-12).
> Goal: run a **full capability-discovery session against a logged-in provider** from the CLI —
> launch the real Chrome profile, interact with the provider, capture the live stream, and
> **align the streaming-parse logic** against what the provider actually emits — before any UI
> work. This is the "Stratus" capability: provider discovery that is verifiable end-to-end via CLI.

### 1.2 Missing tools — assessment
**Q: Do we need Puppeteer?**
**No.** The Governor Canon (INVARIANTS.md) forbids any engine but `ChromeGovernor` from touching CDP,
and `ChromeGovernor` already wraps a native Bun CDP client (`CDPTransport`). Adding Puppeteer would
(a) duplicate the CDP path, (b) violate the canon, (c) pull a heavyweight dependency. The only
browser-automation tool we *might* add later is Playwright for **headless E2E of the UI** — but that
already exists (MCP). Conclusion: **no new browser-automation dependency required.**

What is actually missing:
1. **Stream-capture interceptor** — nothing reads the *live* response body of the provider's
   streaming endpoint and feeds it back into `StreamParserEngine` to verify the parser. The
   discovery engine's `startObservation` enables `Network` but never reads bodies.
2. **Streaming-parse alignment logic** — no code compares "what the parser produced" vs "what the
   provider actually streamed" and reports drift / suggests a corrected `deltaPath`.
3. **End-to-end orchestration** — `ProviderDiscoveryEngine` exposes methods but nothing ties
   navigate -> probe -> capture -> align -> manifest into one reproducible run.
4. **CLI surface** — `providers` only does `list/show` over HTTP; there is no command to *drive* a
   discovery session against a logged-in profile.

### 1.3 CLI capabilities to add
| Command | Purpose |
|---|---|
| `vivim discovery run <slug> --url <u> --account <id> --profile <dir> --message "hi"` | Launch logged-in profile, navigate, probe, capture stream, align parser, emit manifest draft |
| `vivim discovery interact <slug> --account <id> --profile <dir> --message "..."` | Send a single message and stream the raw response to stdout (interact without UI) |
| `vivim discovery align <slug> --file captured.txt` | Feed a captured stream file through `StreamAlignmentEngine` and print the alignment report |
| `vivim discovery list` / `vivim discovery show <id>` | List / inspect stored discovery sessions |
| `vivim discovery manifest <id>` | Print the inferred provider manifest draft (JSON) |

## 4. Acceptance criteria ("fully capable Stratus")
1. `vivim discovery run claude --account me --profile ./chrome-profiles/claude` launches the
   logged-in profile, sends a probe, captures the real stream, and prints an alignment report.
2. The alignment report states: parser used, inferred vs configured format, detected `deltaPath`,
   confidence, and any mismatch with concrete fix suggestions.
3. Running `vivim discovery align` on a captured file reproduces the same report offline.
4. `bun test` and `bun run typecheck` pass.
