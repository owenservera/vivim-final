# Unit 23.5: Canvas config + kernel capabilities

**Phase:** 23 | **File:** `src/canvas/canvas-agent-tools.ts`
**Depends:** 23.1 ConfigUniversalSurface, 23.2 kernel command surface | **Source:** PRD §User Stories 10-12, 36

## Purpose
FRONTEND = BACKEND. Expose the kernel oracle + universal config as vivim-canvas
capabilities so the UI can trigger them exactly like a CLI user. This makes the
canvas a first-class command surface.

## New capabilities (same plane as canvas_spawn etc.)
```
cap:kernel:query    — { op, filter?, limit? }  → oracle.query
cap:kernel:heal     — { issueId }               → oracle.actuator.heal
cap:kernel:visibility — {}                      → oracle.visibility
cap:kernel:manifest   — {}                      → oracle.buildManifest
cap:config:list     — {}                         → configSurface.listScopes
cap:config:get      — { scope, key }            → configSurface.get
cap:config:set      — { scope, key, value }     → configSurface.set
```

## Implementation
Add to `registerCanvasCapabilities()` in canvas-agent-tools.ts. Each is a
`canvasCap(...)` (surfaces: cli/ui/workflow/mcp/api) calling the kernel/oracle/
config surface passed in `CanvasCapabilityServices`. Extend that services interface
with `oracle: OracleReader` (already there) + `kernelOracle` + `configSurface`.

## Tests
- `cap:config:get` returns a value; `cap:config:set` round-trips
- `cap:kernel:visibility` returns OracleVisibility shape
