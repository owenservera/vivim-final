# Unit 23.3: CapabilityAutoBridge (wire syncCliFromUnified)

**Phase:** 23 | **File:** `src/cli/index.ts` (startup change)
**Depends:** 18.2 registry-bridge (`syncCliFromUnified` exists, unwired) | **Source:** PRD §Implementation Decisions (module 3)

## Purpose
The single highest-leverage fix: after `UnifiedCapabilityRegistry` is constructed,
invoke `syncCliFromUnified(registry, cliRegistry)` so EVERY registered capability
becomes a CLI command. Today the function is defined but never called → capabilities
are NOT live CLI commands.

## Change
In `src/cli/index.ts` CLI bootstrap, after registry construction:
```typescript
import { syncCliFromUnified } from './commands/registry-bridge.js'
syncCliFromUnified(registry, cliRegistry)
```
Ensure `registry` (UnifiedCapabilityRegistry) is available at CLI startup
(wire it through ServerContext / CLI deps).

## Tests
- After startup, `vivim capability list` includes canvas_spawn, canvas_observe, nlcl:* commands
- Executing a bridged capability routes to registry.execute

## Gate
- `bun run typecheck` passes; integration test confirms capabilities appear as CLI commands
