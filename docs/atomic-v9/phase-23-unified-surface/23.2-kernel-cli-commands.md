# Unit 23.2: Kernel CLI Commands (oracle + config)

**Phase:** 23 | **File:** `src/cli/commands/kernel.ts`
**Depends:** 23.1 ConfigUniversalSurface, kernel.context().oracle | **Source:** PRD §User Stories 1-22, 23-40

## Purpose
Register `vivim kernel` (or alias `vivim k`) with subcommands that expose the
kernel Oracle and the universal config surface. This is the missing
"system-level CLI" the platform was designed for.

## Subcommands
```
vivim kernel oracle query  --op <health|topology|capability|config|all> [--filter '{}'] [--limit N]
vivim kernel oracle heal   --issueId <id>
vivim kernel oracle scan
vivim kernel oracle events [--tail N]
vivim kernel oracle visibility
vivim kernel oracle manifest
vivim kernel oracle policy [get|set --key val]
vivim kernel oracle explain --target <traceId>
vivim kernel config list
vivim kernel config get  <scope>.<key>
vivim kernel config set  <scope>.<key> <value>
vivim kernel config snapshot
vivim kernel config rollback <id>
```

## Implementation
- `kernel` command registered in `src/cli/index.ts` command registry.
- Reads `kernel` + `configSurface` from ServerContext (kernel already carried in ctx).
- `oracle query` → `kernel.context().oracle.query.query({type, filter, limit})`.
- `oracle heal` → `kernel.context().oracle.actuator.heal(issueId)`.
- `oracle scan` → `kernel.context().oracle.diagnostic.scan()`.
- `oracle events` → `kernel.context().oracle.events.getRecentEvents(N)`.
- `config *` → delegate to ConfigUniversalSurface.

## Tests
- `vivim kernel oracle query --op health` prints aggregate score
- `vivim kernel config get autoheal.stalledEngineRestart.enabled` returns bool
- `vivim kernel config set ...` round-trips
