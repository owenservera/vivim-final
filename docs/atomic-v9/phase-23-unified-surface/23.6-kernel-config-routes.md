# Unit 23.6: Kernel / Config REST routes

**Phase:** 23 | **File:** `src/server/kernel-router.ts`
**Depends:** 23.1, 23.2 | **Source:** PRD §API Contracts

## Purpose
Expose the kernel oracle + universal config over HTTP so the frontend and any
external agent can operate/configure the system programmatically.

## Routes (all under /api/kernel)
```
POST /api/kernel/oracle/query   { type, filter?, limit? }   → QueryResult
POST /api/kernel/oracle/heal    { issueId }                 → HealAction
POST /api/kernel/oracle/scan                                  → DiagnosticIssue[]
GET  /api/kernel/oracle/events?limit=N                       → OracleEvent[]
GET  /api/kernel/oracle/visibility                             → OracleVisibility
GET  /api/kernel/oracle/manifest                               → CanvasManifest
GET  /api/kernel/oracle/policy                                → AutoHealPolicy
PUT  /api/kernel/oracle/policy                                → AutoHealPolicy
GET  /api/kernel/config/scopes                                → ConfigScope[]
GET  /api/kernel/config/:scope/:key                           → ConfigValue
PUT  /api/kernel/config/:scope/:key  { value }                → ConfigValue (Zod-validated)
POST /api/kernel/config/snapshot                              → { id }
POST /api/kernel/config/rollback { id }                       → ok
```

## Implementation
- `createKernelRouter({ kernel, configSurface })` returns a `(req, url) => Response|null` handler.
- Mount in `src/server/index.ts` alongside canvas-router.
- Auth via existing `auth-gate` (Bearer token).

## Tests
- GET /api/kernel/oracle/visibility returns providers/engines/...
- PUT /api/kernel/config/:scope/:key validates via Zod and rejects bad values (400)
- config:changed event fires on PUT

## Gate
- `bun run typecheck` passes; route tests green
