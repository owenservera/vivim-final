# 15.2 — OracleDiagnosticEngine

**Phase:** 15 · **Domain:** Kernel Oracle · **Status:** DRAFT

## Purpose

Detect problems — stubs, broken wires, missing deps, stalled engines, health degradation,
schema mismatches, missing config. The oracle's "immune system" — continuously scans for
issues and generates actionable diagnostic reports.

## Interface

```typescript
export interface DiagnosticIssue {
  id: string
  severity: 'critical' | 'warning' | 'info'
  category: 'stub' | 'broken-wire' | 'missing-dep' | 'stalled' | 'health-degraded' | 'config-missing' | 'schema-mismatch'
  engineId: string
  description: string
  evidence: string[]
  suggestedFix: string
  autoFixable: boolean
  detectedAt: number
}

export class OracleDiagnosticEngine {
  scan(): Promise<DiagnosticIssue[]>
  scanEngine(engineId: string): Promise<DiagnosticIssue[]>
  getIssue(id: string): Promise<DiagnosticIssue | null>
  getIssuesBySeverity(severity: string): Promise<DiagnosticIssue[]>
  getIssuesByEngine(engineId: string): Promise<DiagnosticIssue[]>

  checkStubs(): Promise<DiagnosticIssue[]>
  checkWiring(): Promise<DiagnosticIssue[]>
  checkHealth(): Promise<DiagnosticIssue[]>
  checkSchema(): Promise<DiagnosticIssue[]>
  checkConfig(): Promise<DiagnosticIssue[]>
}
```

## Design

### Diagnostic Checks

#### 1. Stub Check (`checkStubs`)

Scans engine methods for incomplete implementations:
```typescript
// Known stubs to detect:
- 'throw new Error("not implemented")'
- 'throw new Error("not yet implemented")'
- '// TODO:'
- '// FIXME:'
- methods that return `undefined` or empty objects for critical paths
```

**Known stubs from codebase:**
- `ChromeGovernor.executeHarnessPlan()` at `src/engines/chrome-governor.ts:192`

#### 2. Wire Check (`checkWiring`)

Verifies all declared dependencies exist and are registered:
```typescript
for (const engine of registry.listEngines()) {
  for (const dep of engine.dependencies) {
    if (!registry.getEngine(dep)) {
      issues.push({ category: 'missing-dep', ... })
    }
    if (registry.getEngine(dep)?.status === 'error') {
      issues.push({ category: 'broken-wire', ... })
    }
  }
}
```

#### 3. Health Check (`checkHealth`)

Identifies engines with degraded health:
```typescript
for (const engine of registry.listEngines()) {
  if (engine.health?.status === 'unhealthy') {
    issues.push({ category: 'health-degraded', severity: 'critical', ... })
  }
  if (engine.health?.status === 'degraded') {
    issues.push({ category: 'health-degraded', severity: 'warning', ... })
  }
}
```

#### 4. Schema Check (`checkSchema`)

Verifies DB tables match expected Prisma schema:
```typescript
// Compare kernel_spans, kernel_provenance, kernel_topology, kernel_events
// against Prisma introspection results
```

#### 5. Config Check (`checkConfig`)

Identifies engines with missing required config:
```typescript
for (const engine of registry.listEngines()) {
  const required = engine.metadata.requiredConfig ?? []
  for (const key of required) {
    if (!engine.config[key]) {
      issues.push({ category: 'config-missing', ... })
    }
  }
}
```

### Issue Lifecycle

```
detected → reported → (auto-healed) → resolved
                   └→ (manual fix) → resolved
                   └→ (ignored) → dismissed
```
