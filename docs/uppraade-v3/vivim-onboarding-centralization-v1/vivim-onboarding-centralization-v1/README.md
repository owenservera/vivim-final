# Vivim Onboarding & Install — Centralization Pack v1

**Generated**: 2026-08-03
**Source repo**: `https://github.com/owenservera/vivim-final` (commit `e9f7417`)

---

## What this pack is

A self-contained implementation brief for an agentic engineer (or agent loop) to execute against the vivim-final repo. It is derived from a deep audit of the onboarding subsystem and the install/setup flow. Every task is:

- **Scoped** — touches a known set of files
- **Spec'd** — includes the exact code/shape to write
- **Verifiable** — has acceptance criteria you can run
- **Ordered** — explicit dependencies on prior tasks

## What "centralize" means here

The audit found three things called "onboarding" that don't talk to each other, two competing first-run UIs mounted at once, six missing API routes, a missing shared-types module, broken install paths, and a snapshot-restore path that's unreachable. This pack **centralizes** by:

1. Picking **one canonical first-run UI** (GuidedLanding wins; OnboardingTour defers).
2. Putting all onboarding **types and step definitions in one module** (`shared/onboarding.ts`).
3. Putting all onboarding **state behind one store contract** (`OnboardingStore`) with a Prisma-backed implementation.
4. Putting all setup-wizard HTTP surface **behind `/api/setup/*`** that proxies to the already-existing `setup-router.ts`.
5. Putting all install-time DB bootstrap **behind one path** (`config.dbPath`) so dev, NSIS, and Tauri paths all read the same DB.
6. Putting all env-var documentation **in one `.env.example`** that matches what the code reads.

## How to use this pack

1. Read `00-SUMMARY.md` for the executive overview.
2. Read `02-DECISIONS.md` for the architectural choices that drive the tasks.
3. Work through `tasks/` in order (01 → 13). Each task lists its dependencies.
4. Use `templates/` for code you can drop in (review before committing).
5. Run through `verification/acceptance-checklist.md` when done.
6. Reference `audit/` for the original findings if you need context.

## Scope guardrails

**In scope** (this pack):
- Making the existing onboarding/install code paths actually work
- Centralizing types, stores, routes, env vars
- Fixing the broken NSIS install path
- Wiring the OnboardingTour to coordinate with GuidedLanding

**Out of scope** (future packs):
- New onboarding features (e.g. SSO, mobile onboarding)
- Rewriting the devops `onboard-provider.ts` pipeline (separate concern)
- Chrome slave fleet scaling
- Multi-tenant workspace onboarding
- Provider parser improvements
