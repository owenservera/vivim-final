# Unit 1.1 — Static capability catalog + offline discover

**Source:** PRD R1, R8; Scenario A, E
**Depends on:** none
**Produces:** A committed/regenerable static capability catalog enabling `discover --offline`
without a running server, closing the plan-time chicken-egg.

---

## Context

`discover` (and the agent's planning step) currently requires a running backend
(`GET /api/capabilities`). To plan a *new* capability the agent must first compile + boot the
server — impossible when code is broken, and a dead-end for an autonomous loop that self-spawns a
server (which then fails to boot). `discover-cdp` already proves the "catalog fallback" pattern
works; we mirror it for capabilities.

## Interface

### New command: `devops/runtime-test/cap-catalog.ts`
- `generateCatalog(): { ok, capabilities: CatalogCap[], source: 'source' }` — statically parses
  `src/engines/capability-bootstrap.ts` for `makeCapability({ id: '...', slug: '...', ... })` blocks
  via bounded regex; writes `.runtime/capability-catalog.json`.
- `readCatalog(): { ok, capabilities, source: 'file'|'none' }` — reads the JSON if present.

### Extended: `devops/runtime-test/discover.ts`
- `discover({ offline?: boolean })` — when `offline`, returns catalog capabilities instead of
  hitting the server. CLI flag `--offline`.

### New CLI flag
- `bun run devops runtime-test discover --offline` → `{ ok:true, backendCapabilities:[...from catalog], offline:true, schemaTables:null }`

## Steps
1. Implement `cap-catalog.ts` (regex extractor, bounded, no server).
2. Add `discover --offline` path.
3. Wire `catalog-gen` subcommand (`bun run devops runtime-test catalog-gen`) to regenerate the file.
4. Export from barrel.

## Acceptance
- `discover --offline` returns capabilities with `ok:true` and **no network call** (kill server, still works).
- Catalog includes `id` + `slug` for every `makeCapability` in `capability-bootstrap.ts`.
- `typecheck` clean.
