# Unit 1.3 — Capability codegen recipe (`build backend --cap=`)

**Source:** PRD R2, R8; Scenario A
**Depends on:** 1.1 (catalog shape)
**Produces:** `build backend --cap=<slug>` emits a compilable `makeCapability` skeleton using the
exact field shape from `src/engines/capability-bootstrap.ts`, so thin agents don't drift.

---

## Context

`scaffoldBackend()` was a no-op ("backend is source; scaffold validates structure"). An autonomous
agent therefore free-handed the `makeCapability(...)` call and frequently omitted `cliCommand`,
`ui`, `mcpToolName`, or `apiEndpoint` — breaking cross-surface parity. The fix emits a skeleton
with every required field, derived from the slug.

## Interface

### Extended: `devops/runtime-test/build-backend.ts`
- `scaffoldBackend(opts?: { cap?: string })` — when `cap` is set, delegates to `scaffoldCapability`.

### New file: `devops/runtime-test/capability-codegen.ts`
- `scaffoldCapability(slug): CodegenResult` — writes `src/engines/generated/<slug>.ts` with a
  `makeCapability` returning `cap:<category>:<action>`, `slug`, `name`, `inputSchema`,
  `outputSchema`, `cliCommand`, `ui`, `mcpToolName`, `apiEndpoint`, and a TODO handler.

### New CLI flag
- `bun run devops runtime-test build backend --cap=<slug>` → `{ok, path, snippet}`

## Steps
1. Implement `capability-codegen.ts` (slug → id/category/action; emit file).
2. Extend `build-backend.ts` + `build` case in `devops/index.ts`.
3. Document in SKILL.md.

## Acceptance
- `build backend --cap=conversation_summarize` writes a file that typechecks against the real
  `makeCapability` signature (all required fields present).
- `typecheck` clean.
