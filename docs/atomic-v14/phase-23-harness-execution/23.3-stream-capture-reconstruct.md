# Unit 23.3 — Stream capture / reconstruction (cap-store stream → vivim block store)

**Design Doc:** `docs/atomic-v14/SYNTHESIS.md` §2.3
**Depends on:** 23.1
**Produces:** `src/engines/harness/stream-capture.ts` — adapts cap-store
`stream-capture.ts` / `stream-reconstructor.ts` / `stream-detector.ts` to write blocks
into vivim-final's existing `StreamBlockStore` and emit `streamBlock` events on
`CapabilityEventBus`.

---

## Context

cap-store captures the provider's streamed reply and reconstructs blocks, publishing
them via WS. vivim-final already owns `StreamBlockStore` + `StreamParserEngine`. This
adapter routes cap-store-style capture into the vivim block store, reusing the existing
parser instead of reimplementing reconstruction.

## Existing Baseline

- `src/engines/stream-block-store.ts` — `StreamBlockStore` (append block).
- `src/engines/stream-parser.ts` — `StreamParserEngine`.
- `src/engines/capability-event-bus.ts` (or `conversation-manager.ts`) — `CapabilityEventBus`.
- cap-store `src/executor/stream-*.ts` (reference for capture semantics).

## Interface

### `src/engines/harness/stream-capture.ts`

```typescript
import type { StreamBlockStore } from '../stream-block-store.js'
import type { CapabilityEventBus } from './conversation-manager.js'

export interface StreamCaptureSink {
  blockStore: StreamBlockStore
  eventBus: CapabilityEventBus
  bindingId: string
  messageId: string
}

/** cap-store publishStreamBlock → vivim block store + event bus. */
export function captureBlock(sink: StreamCaptureSink, sequence: number, block: unknown): void {
  sink.blockStore.append(sink.bindingId, sink.messageId, sequence, block)
  sink.eventBus.emit({ type: 'capability:streamBlock', bindingId: sink.bindingId, messageId: sink.messageId, sequence, block })
}

export function captureDone(sink: StreamCaptureSink, reason: 'complete' | string): void {
  sink.eventBus.emit({ type: 'capability:streamDone', bindingId: sink.bindingId, messageId: sink.messageId, reason })
}
```

### Wiring

`HarnessExecutorEngine` (23.1) substitutes its `HarnessSink` default with one that calls
`captureBlock`/`captureDone`, so fine-grained streaming matches cap-store semantics while
stored in vivim's block store.

## Acceptance Criteria

1. `captureBlock` appends to `StreamBlockStore` and emits `capability:streamBlock`.
2. `captureDone` emits `capability:streamDone`.
3. No duplication of cap-store reconstruction logic — reuses `StreamParserEngine`.
4. `typecheck` passes.
