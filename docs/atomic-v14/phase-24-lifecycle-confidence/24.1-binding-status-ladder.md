# Unit 24.1 — Binding status ladder (cap-store ladder → vivim `CapabilityBindingRow.status`)

**Design Doc:** `docs/atomic-v14/SYNTHESIS.md` §2.4
**Depends on:** 23.1
**Produces:** `src/engines/harness/binding-ladder.ts` — the cap-store
`prospect→test-1→test-2→stable→flaky→broken→retired` state machine, typed over
vivim-final's `CapabilityBindingRow.status` (currently free-form). Pure functions,
mirroring cap-store `lifecycle/index.ts`.

---

## Context

cap-store proves a strict status ladder with legal transitions. vivim-final's
`CapabilityBindingRow.status` is currently an untyped string. This unit types it to the
cap-store ladder and enforces legal transitions, giving binding maturity a rigorous
model instead of ad-hoc `healthy`/`broken`.

## Existing Baseline

- `src/storage/contracts/capability-store.ts` — `CapabilityBindingRow.status`,
  `updateBindingHealth`.
- cap-store `src/lifecycle/index.ts` — `VALID_TRANSITIONS`, `autoStatus` (reference).

## Interface

### `src/engines/harness/binding-ladder.ts`

```typescript
export type BindingStatus = 'prospect' | 'test-1' | 'test-2' | 'stable' | 'flaky' | 'broken' | 'retired'

const VALID_TRANSITIONS: Record<BindingStatus, BindingStatus[]> = {
  prospect: ['test-1', 'broken', 'retired'],
  'test-1': ['test-2', 'flaky', 'broken', 'retired'],
  'test-2': ['stable', 'flaky', 'broken', 'retired'],
  stable: ['flaky', 'broken', 'retired'],
  flaky: ['stable', 'broken', 'retired'],
  broken: ['stable', 'retired'],
  retired: [],
}

export function isValidTransition(from: BindingStatus, to: BindingStatus): boolean {
  return VALID_TRANSITIONS[from]?.includes(to) ?? false
}

export interface BindingConfidenceInputs { oks: number; fails: number; confidence: number }

/** Port of cap-store autoStatus. */
export function autoStatus(status: BindingStatus, ci: BindingConfidenceInputs): BindingStatus {
  if (status === 'retired') return 'retired'
  if (ci.fails > 0 && (status === 'stable' || status === 'broken')) return 'broken'
  if (status === 'prospect' && ci.oks >= 1) return 'test-1'
  if (status === 'test-1' && ci.oks >= 2) return 'test-2'
  if (status === 'test-2' && ci.oks >= 3 && ci.confidence >= 0.65) return 'stable'
  return status
}
```

### Wiring

`HarnessExecutorEngine` (23.1) computes the next status via `autoStatus` and writes it
through `updateBindingHealth` (validated by `isValidTransition`; illegal → `broken`).

## Acceptance Criteria

1. `BindingStatus` union + `VALID_TRANSITIONS` mirror cap-store ladder.
2. `autoStatus` promotes by oks/confidence exactly like cap-store.
3. `isValidTransition` guards writes; illegal moves force `broken`.
4. `typecheck` passes.
