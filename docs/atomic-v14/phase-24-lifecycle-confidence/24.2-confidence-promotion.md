# Unit 24.2 — Confidence promotion (cap-store `confidence` → vivim `healthScore` + resolution gate)

**Design Doc:** `docs/atomic-v14/SYNTHESIS.md` §2.4
**Depends on:** 24.1
**Produces:** `src/engines/harness/confidence.ts` — port of cap-store `confidence()` +
`shouldEscalate()`; derives `CapabilityBindingRow.healthScore` and feeds
`bindingConfidence` / `bindingStatus` into `CapabilityResolutionEngine` (which already
reads them) so low-maturity bindings are not surfaced as capabilities.

---

## Context

cap-store computes a confidence score from `confidence_inputs` and uses it both to
promote bindings and to decide escalation. vivim-final's `CapabilityResolutionEngine`
already consumes `bindingConfidence` + `bindingStatus`. This unit ports the score so the
resolution layer becomes a **maturity gate** (proven cap-store behaviour).

## Existing Baseline

- `src/engines/capability-resolution.ts` — `ResolvedCapability.bindingConfidence`,
  `bindingStatus`.
- 24.1 `autoStatus`, `BindingConfidenceInputs`.
- cap-store `src/confidence.ts` (reference).

## Interface

### `src/engines/harness/confidence.ts`

```typescript
import type { BindingConfidenceInputs } from './binding-ladder.js'

/** Port of cap-store confidence(). Returns 0..1. */
export function confidence(ci: BindingConfidenceInputs): number {
  const total = ci.oks + ci.fails
  if (total === 0) return 0
  const base = ci.oks / total
  const replayBonus = ci.replay_verified ? 0.1 : 0
  return Math.min(1, base * 0.9 + replayBonus)
}

/** Port of cap-store shouldEscalate — gates resolution surfacing. */
export function shouldEscalate(status: string, ci: BindingConfidenceInputs): boolean {
  const c = confidence(ci)
  if (status === 'broken') return true
  if (status === 'stable' && c < 0.65) return true
  return false
}
```

### Wiring

- `HarnessExecutorEngine` (23.1) writes `healthScore = confidence(ci)` on outcome.
- `CapabilityResolutionEngine` calls `shouldEscalate(bindingStatus, ci)` to drop
  low-maturity bindings from the resolved UI contract.

## Acceptance Criteria

1. `confidence` returns 0..1 from oks/fails (+ replay bonus).
2. `shouldEscalate` matches cap-store escalation rules.
3. `CapabilityResolutionEngine` uses it as a surfacing gate (no low-maturity bindings).
4. `typecheck` passes; existing resolution tests updated, not broken.
