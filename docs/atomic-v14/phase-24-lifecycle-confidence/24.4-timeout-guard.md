# Unit 24.4 — Timeout guard (cap-store `applyTimeoutGuard` promotion cron)

**Design Doc:** `docs/atomic-v14/SYNTHESIS.md` §2.4
**Depends on:** 24.2
**Produces:** `src/engines/harness/timeout-guard.ts` + a scheduler hook — ports cap-store
`checkTimeoutGuard`/`applyTimeoutGuard` so bindings stuck in `test-1`/`test-2` too long
are auto-promoted if confidence thresholds are met (periodic, not per-execution).

---

## Context

cap-store runs a timeout guard (e.g. hourly) to promote bindings that passed but were
never advanced. This unit ports it as a pure function + a scheduler entry that the
existing `automation/scheduler.ts` (vivim) can call.

## Existing Baseline

- `src/executor/scheduler.ts` or `src/engines/automation/*` — vivim scheduler (reference).
- 24.1 `autoStatus`; 24.2 `confidence`.
- cap-store `src/lifecycle/index.ts: checkTimeoutGuard` (reference).

## Interface

### `src/engines/harness/timeout-guard.ts`

```typescript
import type { BindingStatus } from './binding-ladder.js'
import { confidence } from './confidence.js'

const TEST1_TIMEOUT_MS = 24 * 60 * 60 * 1000
const TEST2_TIMEOUT_MS = 7 * 24 * 60 * 60 * 1000

export interface TimeoutGuardInput { status: BindingStatus; enteredAt: number; oks: number; confidenceInputs: { oks: number; fails: number; replay_verified?: boolean } }

export function checkTimeoutGuard(b: TimeoutGuardInput, now = Date.now()): { promote: boolean; reason: string } {
  if (b.status === 'test-1' && (now - b.enteredAt) > TEST1_TIMEOUT_MS && b.oks >= 1)
    return { promote: true, reason: `test-1 timeout: ${b.oks} ok(s)` }
  if (b.status === 'test-2' && (now - b.enteredAt) > TEST2_TIMEOUT_MS && b.oks >= 2 && confidence(b.confidenceInputs) >= 0.65)
    return { promote: true, reason: `test-2 timeout: conf ok` }
  return { promote: false, reason: '' }
}
```

### Wiring

Scheduler calls `checkTimeoutGuard` per binding; on promote, writes the advanced status
via `updateBindingHealth` (validated by 24.1).

## Acceptance Criteria
