# Unit 22.1 — Program schema (extend `CapabilityProgramRow` to carry typed programs)

**Design Doc:** `docs/atomic-v14/SYNTHESIS.md` §2.1
**Depends on:** 21.4
**Produces:** Prisma migration + `ActionProgram` persistence on `CapabilityProgramRow`
— `configJson` now holds a validated `ActionProgram` (21.3 shape). No new table; extend
the existing row vivim-final already has.

---

## Context

vivim-final already has `CapabilityProgramRow` (`id, bindingId, version, status,
configJson`). It is the direct analog of cap-store's `ActionProgram`. This unit makes
`configJson` a **validated program** (via 21.3 schema) and adds a `programKind` to
distinguish legacy selector programs from recipe programs.

## Existing Baseline

- `src/storage/contracts/capability-store.ts` — `CapabilityProgramRow`,
  `getProgram(bindingId)`, `getPrograms(bindingId)`.
- `prisma/schema.prisma` — `CapabilityProgram` model.

## Interface

### `prisma/schema.prisma` (extend `CapabilityProgram`)

```prisma
model CapabilityProgram {
  id           String   @id
  bindingId    String
  version      Int
  status       String   // cap-store ladder later (24.1); 'draft'|'active' now
  programKind  String   @default("recipe")   // 'recipe' | 'selector'
  configJson   String   // validated ActionProgram (21.3)
  createdAt    BigInt
  updatedAt    BigInt
}
```

### Validation helper — `src/storage/capability-program-validate.ts`

```typescript
import { ActionProgramSchema } from '../engines/harness/recipe-types.js'
export function validateProgramConfig(configJson: string) {
  return ActionProgramSchema.parse(JSON.parse(configJson))
}
```

## Acceptance Criteria

1. Migration adds `programKind` to `CapabilityProgram`; existing rows default
   `'recipe'`.
2. `validateProgramConfig` parses `configJson` with the 21.3 schema; throws on bad JSON.
3. `bunx prisma migrate dev` applies cleanly; `typecheck` passes.
