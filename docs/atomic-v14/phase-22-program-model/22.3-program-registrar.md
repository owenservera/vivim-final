# Unit 22.3 — Program registrar (data-driven late binding, like `ProviderRegistrar`)

**Design Doc:** `docs/atomic-v14/SYNTHESIS.md` §2
**Depends on:** 22.2
**Produces:** `src/engines/capability-program-registrar.ts` — seeds `ActionProgram`
rows from `seeds/programs/*.json` into the program store, binding them to a
capability+provider. This is the cap-store "register a program" step, vivim-styled.

---

## Context

cap-store capabilities are **data**, not code — you insert a program row to add
behaviour without redeploy. `ProviderRegistrar` already shows the vivim pattern for
seeding provider manifests. This unit mirrors it for programs: seed programs, attach
to `CapabilityBindingRow` as `best_program_id` (cap-store semantics).

## Existing Baseline

- `src/engines/provider-registrar.ts` — manifest seeding pattern (atomic multi-table).
- 22.2 `CapabilityProgramStore.setBest`.
- `src/engines/capability.ts` — `getBinding(capId, providerId)`.
- `src/ids.ts` — `newId`.

## Interface

### `src/engines/capability-program-registrar.ts`

```typescript
import { readdir, readFile } from 'node:fs/promises'
import { newId } from '../ids.js'
import { ActionProgramSchema } from './harness/recipe-types.js'
import type { CapabilityStore } from '../storage/contracts/capability-store.js'
import type { CapabilityProgramStore } from '../storage/contracts/capability-program-store.js'

export interface ProgramSeed {
  capabilitySlug: string
  providerId: string
  version?: number
  configJson: string   // validated ActionProgram
}

export class CapabilityProgramRegistrar {
  constructor(private capStore: CapabilityStore, private progStore: CapabilityProgramStore,
              private seedsDir = `${import.meta.dir}/../../seeds/programs`) {}

  async register(seed: ProgramSeed): Promise<string> {
    const program = ActionProgramSchema.parse(JSON.parse(seed.configJson))
    const cap = await this.capStore.getCapabilityBySlug(seed.capabilitySlug)
    if (!cap) throw new Error(`capability not found: ${seed.capabilitySlug}`)
    const binding = await this.capStore.getBinding(cap.id, seed.providerId)
    if (!binding) throw new Error(`binding not found: ${cap.id}/${seed.providerId}`)
    const id = newId()
    await this.progStore.upsertProgram({
      id, bindingId: binding.id, version: seed.version ?? 1,
      status: 'active', programKind: 'recipe', configJson: seed.configJson,
    })
    await this.progStore.setBest(binding.id, id)
    return id
  }

  async seedAll(): Promise<Array<{ id: string; ok: boolean; error?: string }>> {
    const files = await readdir(this.seedsDir)
    const out = []
    for (const f of files.filter((x) => x.endsWith('.json'))) {
      try {
        const seed = JSON.parse(await readFile(`${this.seedsDir}/${f}`, 'utf8')) as ProgramSeed
        out.push({ id: await this.register(seed), ok: true })
      } catch (e) { out.push({ id: f, ok: false, error: String(e) }) }
    }
    return out
  }
}
```

## Acceptance Criteria

1. `register` validates config via 21.3 schema, resolves capability+binding, upserts
   program, sets it best.
2. `seedAll` reads `seeds/programs/*.json` and registers each.
3. Missing capability/binding → throws (fail-fast, like ProviderRegistrar).
4. `typecheck` passes.
