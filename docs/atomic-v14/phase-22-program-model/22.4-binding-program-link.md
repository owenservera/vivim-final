# Unit 22.4 — Binding↔program link (cap-store `best_program_id` into vivim truth)

**Design Doc:** `docs/atomic-v14/SYNTHESIS.md` §0 (table)
**Depends on:** 22.2
**Produces:** a `bestProgramId` accessor on `CapabilityStore` contract + impl, and a
migration adding `bestProgramId` to `CapabilityBindingRow`. This is the exact cap-store
`ProviderBinding.best_program_id` seam that 23.1 reads to choose what to execute.

---

## Context

cap-store's `executeBinding` loads `binding.best_program_id` to pick the program.
vivim-final's `CapabilityBindingRow` has no such column today (programs are linked via
`CapabilityProgramRow.bindingId`). This unit adds the forward pointer so resolution is
O(1) and matches cap-store's proven lookup.

## Existing Baseline

- `src/storage/contracts/capability-store.ts` — `CapabilityBindingRow`,
  `getBinding(capabilityId, providerId)`.
- 22.2 `setBest`.

## Interface

### `prisma/schema.prisma` (extend `CapabilityBinding`)

```prisma
model CapabilityBinding {
  id              String   @id
  capabilityId    String
  providerId      String
  selectorStrategyId String?
  bestProgramId   String?            // NEW — cap-store best_program_id
  status          String
  healthScore     Float    @default(0)
  lastSuccessAt   BigInt?
  lastFailureAt   BigInt?
  createdAt       BigInt
  updatedAt       BigInt
}
```

### `src/storage/contracts/capability-store.ts` (add)

```typescript
getBestProgramId(bindingId: string): Promise<string | null>
setBestProgramId(bindingId: string, programId: string): Promise<void>
```

Impl delegates to Prisma; `setBest` in 22.2 calls `setBestProgramId`.

## Acceptance Criteria

1. Migration adds `bestProgramId` nullable; existing bindings default null.
2. Contract gains the two methods; impl implements them.
3. `getBestProgramId` backs `getProgram(bestProgramId)` resolution in 23.1.
4. `typecheck` passes; capability-store tests green.
