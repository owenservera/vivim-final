# Unit 25.3 — Observability streaming (fine-grained blocks on `CapabilityEventBus`)

**Design Doc:** `docs/atomic-v14/SYNTHESIS.md` §2.3, §3
**Depends on:** 23.3, 25.1
**Produces:** wiring so harness execution emits cap-store-style fine-grained stream
blocks (`capability:streamBlock` / `capability:streamDone`) through the existing
`CapabilityEventBus`, complementing the coarse `capability:executed`/`failed` events.
This gives the kernel/oracle (vivim) the granular signal cap-store gets via WS.

---

## Context

vivim-final's oracle (kernel sub-system) observes coarse capability events today.
cap-store proves fine-grained block streaming is essential for UX + diagnosis. This
unit makes the harness emit both granular (per block) and coarse (per outcome) events
on the same bus.

## Existing Baseline

- `src/engines/capability-event-bus.ts` or `conversation-manager.ts` — `CapabilityEventBus`.
- 23.3 `captureBlock` / `captureDone`.
- `src/engines/kernel/...oracle-*` — consumers of the bus.

## Interface

### Event contract addition (documented, no new type needed)

```typescript
// Emitted by HarnessExecutorEngine via captureBlock/captureDone (23.3):
type CapabilityStreamEvent =
  | { type: 'capability:streamBlock'; bindingId: string; messageId: string; sequence: number; block: unknown }
  | { type: 'capability:streamDone'; bindingId: string; messageId: string; reason: 'complete' | string }
```

### Wiring

`HarnessExecutorEngine` (23.1) default `HarnessSink` = `{ onBlock: (b,s)=>captureBlock(sink,b,s), onDone: (r)=>captureDone(sink,r), onError: (e)=>captureDone(sink,e) }`
where `sink` is built from `StreamBlockStore` + `eventBus` (23.3).

## Acceptance Criteria

1. Harness execution emits `capability:streamBlock` per recipe step + `capability:streamDone`.
2. Blocks are also appended to `StreamBlockStore` (23.3).
3. Coarse `capability:executed` still emitted (no regression).
4. `typecheck` passes.
