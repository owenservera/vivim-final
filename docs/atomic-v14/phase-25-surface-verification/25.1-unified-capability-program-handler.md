# Unit 25.1 — Unified capability program handler (One Entry Point → harness)

**Design Doc:** `docs/atomic-v14/SYNTHESIS.md` §1 (invariant 3), §3
**Depends on:** 23.1, 22.4
**Produces:** a `makeHarnessCapability` factory that builds a `UnifiedCapability` whose
`handler` delegates to `HarnessExecutorEngine`. This keeps the **One Entry Point**
invariant: every program capability is still a `UnifiedCapability` surfaced across all 5
surfaces, but its body executes the proven cap-store recipe injection.

---

## Context

vivim-final requires every operation to be a `UnifiedCapability` registered once and
exported to cli/ui/workflow/mcp/api. The harness executor (23.1) must be reachable
through that same path. This unit bridges them: a capability's `handler` calls the
executor, no new transport.

## Existing Baseline

- `src/engines/unified-registry.ts` — `UnifiedCapability`, `UnifiedCapabilityRegistry`.
- `src/engines/cdp-capability-registrar.ts` — pattern of capability-from-descriptor.
- 23.1 `HarnessExecutor`.

## Interface

### `src/engines/harness/make-harness-capability.ts`

```typescript
import type { UnifiedCapability, CapabilityContext } from '../unified-registry.js'
import type { HarnessExecutor } from './harness-contract.js'

export function makeHarnessCapability(opts: {
  id: string; slug: string; name: string; description: string; category: string
  executor: HarnessExecutor
  surfaces: UnifiedCapability['surfaces']
}): UnifiedCapability {
  return {
    id: opts.id, slug: opts.slug, name: opts.name, description: opts.description,
    category: opts.category, surfaces: opts.surfaces,
    inputSchema: { type: 'object', properties: { input: { type: 'object' } }, required: [] },
    outputSchema: { type: 'object' },
    handler: async (input: Record<string, unknown>, ctx: CapabilityContext) => {
      const providerId = String(ctx.providerId ?? input.providerId ?? '')
      const accountId = String(ctx.accountId ?? input.accountId ?? '')
      return opts.executor.execute({
        capabilitySlug: opts.slug, providerId, accountId,
        input: input as Record<string, unknown>,
      })
    },
    cliCommand: opts.surfaces.includes('cli') ? { name: opts.slug, aliases: [], examples: [opts.slug] } : undefined,
    mcpToolName: opts.surfaces.includes('mcp') ? opts.slug : undefined,
    apiEndpoint: opts.surfaces.includes('api') ? { method: 'POST', path: `/api/capabilities/${opts.id}/execute` } : undefined,
    ui: opts.surfaces.includes('ui') ? { component: 'HarnessCapabilitySlot', position: 'composer', order: 0 } : undefined,
    isAsync: true, requiresConfirmation: false, tags: ['harness'],
  }
}
```

### Invariant guards

- Handler delegates to `HarnessExecutor` only (which is governor-gated) — no CDP here.
- Surface parity validated by `UnifiedCapabilityRegistry.register` (existing).

## Acceptance Criteria

1. `makeHarnessCapability` returns a valid `UnifiedCapability` whose handler calls the executor.
2. Surface blocks (`cliCommand`/`mcpToolName`/`apiEndpoint`/`ui`) are set per `surfaces`.
3. Registering via `UnifiedCapabilityRegistry` passes existing parity validation.
4. `typecheck` passes.
