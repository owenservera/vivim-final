# Unit 1.7 — Headless Slave Reuse of Saved Login Profile

**Phase:** 1 | **ID:** 1.7 | **Dependencies:** 1.6

## Problem

When ConversationManager calls `governor.ensureRunning(slaveId)`, FleetSupervisor may spawn a new Chrome instance. This instance must reuse the same profile directory that was used during login. Currently, FleetSupervisor's `spawn()` calls `ProfileAllocator.allocate()` which creates a fresh directory if the path doesn't match.

## Spec

### FleetSupervisor.spawn: Use Persisted Profile

The key change: FleetSupervisor must look up the persisted account and use its `profileDir` instead of allocating a new one.

```typescript
// In FleetSupervisor.spawn()
async spawn(providerSlug, accountId, opts?) {
  // Check if account has persisted profile
  let profileDir: string
  
  // The store should have getAccount method
  // If account exists with profileDir, reuse it
  const accountKey = `${providerSlug}_${accountId}`
  
  // ProfileAllocator.getPath uses the same pattern as setup
  profileDir = this.profileAllocator.getPath(providerSlug, accountId)
  
  // Ensure the directory exists (it should from setup, but just in case)
  await this.profileAllocator.allocate(providerSlug, accountId)
  
  // ... rest of spawn
}
```

### Headless Launch with Login Navigation

When spawning headless, the Chrome instance should navigate to the provider URL on launch:

```typescript
// In FleetSupervisor.spawn(), after Chrome is running:
const loginUrl = PROVIDER_URLS[providerSlug] ?? `https://${providerSlug}.com`

// Navigate to provider page
const cdp = new BunCdpClient(`ws://127.0.0.1:${debugPort}/devtools/browser`)
await cdp.connect()
await cdp.send('Target.createTarget', { url: loginUrl })
await cdp.disconnect()
```

### FleetSupervisor.ensureRunning Enhancement

```typescript
async ensureRunning(instanceId) {
  const instance = this.instances.get(instanceId)
  if (!instance) throw new SlaveNotRunningError(instanceId)
  
  if (instance.status === 'running') {
    // Verify Chrome is actually alive (not zombie)
    try {
      const cdp = new BunCdpClient(`ws://127.0.0.1:${instance.debugPort}/devtools/browser`)
      await cdp.connect()
      await cdp.send('Browser.getVersion')
      await cdp.disconnect()
      return instance
    } catch {
      // Chrome died — respawn
      instance.status = 'crashed'
    }
  }
  
  // ... rest of existing ensureRunning logic
}
```

## Invariant

**The `--user-data-dir` Chrome flag must point to the same directory in both visible (login) and headless (runtime) Chrome instances for the same provider+account pair.**

## Test

```typescript
test('headless Chrome reuses login profile', async () => {
  // Simulate: setup created profile at C:\test-ws\chatgpt\work
  // Governor spawned with same provider+account
  const slave = await governor.spawn('chatgpt', 'work', { visible: false })
  
  // The slave's profileDir should match
  expect(slave.profileDir).toContain('chatgpt')
  expect(slave.profileDir).toContain('work')
  
  // Chrome should be running
  const resp = await fetch(`http://127.0.0.1:${slave.debugPort}/json/version`)
  expect(resp.ok).toBe(true)
})
```
