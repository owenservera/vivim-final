# Unit 1.3 — Setup Wizard Workspace + Profile Path Flow

**Phase:** 1 | **ID:** 1.3 | **Dependencies:** 1.2

## Problem

The workspace path selected in the setup wizard is stored as a hint but never passed to the Governor's fleet config. When FleetSupervisor spawns headless Chrome, it uses its own `chromeProfileBase` (default: `chrome-profiles/`), which doesn't match the workspace path from setup. Login sessions don't carry over.

## Spec

### Fix 1: Governor Config Uses Workspace Path

In `createServerWithEngines()`, read the workspace hint and pass it to Governor config:

```typescript
const workspaceHint = await db.getWorkspaceHint()
const profileBase = workspaceHint ?? 'chrome-profiles'

const governor = new ChromeGovernor(govStore, {
  profileBaseDir: profileBase,  // ← pass workspace path
  portRange: [9300, 9400],
  // ... rest unchanged
})
```

### Fix 2: Setup Router Uses Same ProfileAllocator

In `setup-router.ts`, the `launch-visible` endpoint already creates a `ProfileAllocator(body.workspace)`. This is correct. But the `complete` endpoint must persist the exact profile path:

```typescript
// POST /api/setup/complete
const allocator = new ProfileAllocator(body.workspace)
const profileDir = allocator.getPath(body.providerId, body.accountSlug)

await ctx.db.upsertAccount({
  id: accountId,
  providerId: body.providerId,
  email: body.accountSlug,
  planTier: 'free',
  loginState: 'authenticated',
  profileDir,  // ← exact path
  debugPort: body.debugPort,
})
```

### Fix 3: FleetSupervisor Reuses Persisted Profile

In `FleetSupervisor.spawn()`, check if an account already has a profileDir and use it:

```typescript
async spawn(providerSlug, accountId, opts) {
  // Check if account has persisted profile
  const existingAccount = await this.store.getAccount?.(accountId)
  const profileDir = existingAccount?.profileDir 
    ?? await this.profileAllocator.allocate(providerSlug, accountId)
  
  // Use existing debug port if available
  const debugPort = opts?.debugPort ?? existingAccount?.debugPort ?? this.allocatePort()
  
  // ... rest of spawn logic
}
```

### Fix 4: Workspace Hint Must Be Set Before Governor Boot

The workspace hint must be persisted before the Governor boots. If no hint exists, the Governor uses the default `chrome-profiles/` directory. The first-run wizard ensures the hint is set before any Chrome operations.

## Invariant

**ProfileAllocator.getPath(provider, account) must return the same directory in all code paths.**

This means the `baseDir` passed to ProfileAllocator must be identical in:
1. Setup router (visible Chrome launch)
2. FleetSupervisor (headless Chrome spawn)
3. ChromeGovernor.deriveProfile()

## Test

```typescript
test('profile path consistent across setup and runtime', async () => {
  // Set workspace
  await fetch('/api/setup/workspace', {
    method: 'POST',
    body: JSON.stringify({ path: 'C:\\test-workspace' })
  })
  
  // Complete setup
  await fetch('/api/setup/complete', {
    method: 'POST',
    body: JSON.stringify({
      providerId: 'chatgpt',
      accountSlug: 'work',
      workspace: 'C:\\test-workspace',
      profileDir: 'C:\\test-workspace\\chatgpt\\work',
      debugPort: 9222
    })
  })
  
  // Governor should use same base
  const governor = ctx.governor!
  const derivedProfile = governor.deriveProfile('chatgpt', 'work')
  expect(derivedProfile).toContain('chatgpt')
  expect(derivedProfile).toContain('work')
})
```
