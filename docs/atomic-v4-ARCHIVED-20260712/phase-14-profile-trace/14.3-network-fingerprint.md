# Unit 14.3 — NetworkFingerprintEngine: TLS + HTTP Header Preservation

**Phase:** 14 | **ID:** 14.3 | **Dependencies:** 11.1

## Problem

Two network-layer detection vectors:

1. **TLS Fingerprint (JA3/JA4):** The TLS ClientHello message contains cipher suites, extensions, and curves in a specific order. This creates a hash that identifies the browser. The current launcher args (`--disable-background-networking`) change Chrome's network stack, producing a different JA3 hash from a normal Chrome installation.

2. **HTTP Header Order:** The order of HTTP/2 headers (SETTINGS frame, pseudo-headers) is browser-specific. Modified Chrome args can alter this order.

## Spec

### Strategy: Don't Modify the Network Stack

The primary defense is **removing the bot-signal args** from the launcher (done in Unit 11.1 — LaunchProfileEngine). With the args removed, Chrome uses its default network stack, producing the same JA3/JA4 hash as millions of other Chrome installations.

This module provides **additional verification and monitoring** — it doesn't modify the network stack itself (that would require kernel-level interception).

```typescript
// src/engines/stealth/network-fingerprint-engine.ts

export class NetworkFingerprintModule implements StealthModule {
  name = 'network_fingerprint'
  detectionVector = 'TLS fingerprinting (JA3/JA4) + HTTP/2 header ordering'
  description = 'Verifies TLS fingerprint matches stock Chrome; monitors for network anomalies'
  priority = 2 // early — verify before page scripts run

  configSchema = z.object({
    verifyOnApply: z.boolean().default(true),
    blockNonMatchingTls: z.boolean().default(false), // warn vs block
    expectedChromeVersion: z.string().default('120'), // major version to match
    monitorConnections: z.boolean().default(true),
  })

  private static CHROME_JA3_HASHES: Record<string, string[]> = {
    // Known JA3 hashes for Chrome versions
    // These are publicly available from ja3er.com or SSLHush
    '119': ['cd08e31494f9531f560d64c695473da9', '773906b0efdefa24a7f2b8eb6985bf37'],
    '120': ['e4f31b684c7f0bf7a09d3b0c8c1a5d3e', 'a0e9f5d6436fb1c2b8e7d9a3f4c5b6e7'],
    // Real values would be populated from a maintained database
  }

  async apply(config: Record<string, unknown>, ctx: StealthContext): Promise<void> {
    const cfg = this.configSchema.parse(config)

    if (cfg.verifyOnApply) {
      const tlsOk = await this.verifyTlsFingerprint(ctx, cfg.expectedChromeVersion)
      if (!tlsOk) {
        ctx.logger?.warn('TLS fingerprint does not match expected Chrome version', {
          expected: cfg.expectedChromeVersion,
        })

        if (cfg.blockNonMatchingTls) {
          throw new EngineError('TLS fingerprint mismatch — blocking navigation per policy')
        }
      }
    }

    if (cfg.monitorConnections) {
      await this.startConnectionMonitoring(ctx)
    }

    // Inject script to ensure HTTP headers are consistent
    // Note: JavaScript can't modify TLS or HTTP/2 SETTINGS frames
    // But we can ensure JavaScript-visible headers are correct
    const script = `
      (function() {
        // Ensure navigator.connection looks realistic
        if (!navigator.connection) {
          Object.defineProperty(navigator, 'connection', {
            get: function() {
              return {
                effectiveType: '4g',
                rtt: 50,
                downlink: 10,
                saveData: false,
              }
            }
          })
        }

        // Ensure navigator.onLine is true (bots sometimes run offline)
        Object.defineProperty(navigator, 'onLine', { get: function() { return true } })

        // Remove any WebSocket traces from CDP
        var origWebSocket = window.WebSocket
        window.WebSocket = function(url, protocols) {
          // Block connections to localhost debug ports
          if (/^ws?:\\/\\/127\\.0\\.0\\.1:(9[0-9]{3})\\//.test(url)) {
            console.warn('[blocked] WebSocket to debug port')
            return { send: function(){}, close: function(){}, readyState: 0 }
          }
          return new origWebSocket(url, protocols)
        }
        window.WebSocket.prototype = origWebSocket.prototype
      })();
    `

    await ctx.cdp.send(ctx.slaveId, 'Page.addScriptToEvaluateOnNewDocument', { source: script })
  }

  private async verifyTlsFingerprint(
    ctx: StealthContext,
    expectedVersion: string,
  ): Promise<boolean> {
    // We can't directly inspect TLS from CDP
    // But we can verify the Chrome binary's network behavior
    // by checking the Chrome version

    try {
      const result = await ctx.cdp.send(ctx.slaveId, 'Browser.getVersion', {})
      const version = (result as any)?.product ?? ''
      const majorMatch = version.match(/Chrome\/(\d+)/)
      const major = majorMatch?.[1] ?? '0'

      if (major !== expectedVersion) {
        ctx.logger?.warn('Chrome version mismatch', { actual: major, expected: expectedVersion })
        return false
      }

      // Check if networking-related flags were passed
      const metricsResult = await ctx.cdp.send(ctx.slaveId, 'Runtime.evaluate', {
        expression: `JSON.stringify({
          // If these are modified by flags, the values differ from stock Chrome
          webglVendor: (function() { try { var gl = document.createElement('canvas').getContext('webgl'); return gl?.getParameter(gl.VERSION) } catch(e) { return null } })(),
          networkInfo: navigator.connection?.effectiveType || 'unknown',
        })`,
        returnByValue: true,
      })

      return true // if version matches, TLS should match (assuming no modified args)
    } catch {
      return false
    }
  }

  private async startConnectionMonitoring(ctx: StealthContext): Promise<void> {
    // Enable Network domain for monitoring (not modifying)
    await ctx.cdp.send(ctx.slaveId, 'Network.enable', {}).catch(() => {})

    // Monitor for suspicious connection patterns
    // (e.g., connections to known bot-detection endpoints)
    const script = `
      (function() {
        // Monitor XMLHttpRequest for detection beacon calls
        var origOpen = XMLHttpRequest.prototype.open
        XMLHttpRequest.prototype.open = function(method, url) {
          // Log suspicious endpoints (but don't block — just record)
          if (url && /datadome|perimeterx|kasada|imperva|cloudflare/i.test(url)) {
            console.debug('[network] Detection beacon detected:', url)
          }
          return origOpen.apply(this, arguments)
        }

        // Monitor fetch for same
        var origFetch = window.fetch
        window.fetch = function(input, init) {
          var url = typeof input === 'string' ? input : input?.url
          if (url && /datadome|perimeterx|kasada|imperva|cloudflare/i.test(url)) {
            console.debug('[network] Detection fetch detected:', url)
          }
          return origFetch.apply(this, arguments)
        }
      })();
    `

    await ctx.cdp.send(ctx.slaveId, 'Page.addScriptToEvaluateOnNewDocument', { source: script })
  }

  async verify(ctx: StealthContext): Promise<boolean> {
    // Verify navigator.onLine is true
    const result = await ctx.cdp.send(ctx.slaveId, 'Runtime.evaluate', {
      expression: 'navigator.onLine === true && !!navigator.connection',
      returnByValue: true,
    })
    return (result as any)?.result?.value === true
  }
}
```

### Key Insight: The Best Defense Is No Modified Args

The most important thing this module does is **verify** that the network stack is unmodified. The actual defense happens in `LaunchProfileEngine.buildMinimalArgs()` (Unit 11.1) which doesn't include `--disable-background-networking`, `--disable-sync`, etc.

With stock Chrome networking:
- JA3 hash matches millions of Chrome installations
- HTTP/2 SETTINGS frame is standard
- Cipher suite ordering is standard
- TLS extension order is standard

No JavaScript injection can fix a modified TLS stack. The fix is at the launch level.

### Optional: Proxy Support

For geo-distribution or IP rotation:

```typescript
// In LaunchProfile config:
{
  "id": "stealth_proxied",
  "mode": "hidden",
  "chromeArgs": [
    "--proxy-server=socks5://user:pass@proxy.host:1080"
  ],
  "stealthProfileId": "stealth_maximum"
}
```

Chrome's `--proxy-server` flag routes all traffic through a SOCKS5/HTTP proxy. This doesn't affect TLS fingerprinting (the proxy sees encrypted traffic) but changes the IP address seen by the provider.
