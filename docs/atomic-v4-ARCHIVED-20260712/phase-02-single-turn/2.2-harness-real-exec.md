# Unit 2.2 — Implement Harness Plan Execution (Not Stub)

**Phase:** 2 | **ID:** 2.2 | **Dependencies:** 2.1

## Problem

`ChromeGovernor.cdp.executeHarnessPlan()` at `chrome-governor.ts:192` is a stub:
```typescript
async executeHarnessPlan(slaveId, _dag) {
  return { success: true, stepsCompleted: 0 }  // ← does nothing
}
```

The real DAG executor exists in `HarnessRuntime` but is never called. The ConversationManager builds a DAG but it's executed against the stub, so no CDP commands are sent.

## Spec

### Approach: Wire HarnessRuntime into CDPProxy

Replace the CDPProxy.executeHarnessPlan stub with real execution:

```typescript
// ChromeGovernor
private harnessRuntime: HarnessRuntime | null = null

setHarnessRuntime(eventBus: CapabilityEventBus): void {
  this.harnessRuntime = new HarnessRuntime(eventBus, this, undefined)
  this.registerDefaultHarnessModules()
}

private registerDefaultHarnessModules(): void {
  if (!this.harnessRuntime) return
  
  this.harnessRuntime.register({
    name: 'type_text',
    version: 1,
    inputSchema: {},
    outputSchema: {},
    preconditions: [],
    postconditions: [],
    async execute(input, ctx) {
      const { text, selector } = input as { text: string; selector: string }
      
      // Focus the element
      await ctx.query(selector)
      
      // Type text via CDP Runtime.evaluate
      // (Provider-specific typing logic handled in Unit 2.3)
      await ctx.emitTelemetry({
        type: 'dom_interaction',
        moduleId: 'type_text',
        data: { selector, textLength: text.length },
        ts: Date.now(),
      })
      
      return { ok: true, output: { typed: true } }
    }
  })
  
  this.harnessRuntime.register({
    name: 'submit',
    version: 1,
    inputSchema: {},
    outputSchema: {},
    preconditions: [],
    postconditions: [],
    async execute(input, ctx) {
      const { key } = input as { key?: string }
      // Submit logic handled in Unit 2.4
      return { ok: true, output: { submitted: true } }
    }
  })
}
```

### CDPProxy.executeHarnessPlan Delegates to HarnessRuntime

```typescript
// CDPProxy
async executeHarnessPlan(slaveId: string, dag: HarnessDAG): Promise<HarnessResult> {
  const slave = this.slaves.get(slaveId)
  if (!slave) throw new EngineError(`Slave not found: ${slaveId}`)
  
  const mutex = this.getMutex(slaveId)
  await mutex.acquire()
  try {
    // Create a harness runtime scoped to this slave
    const runtime = new HarnessRuntime(this.eventBus as any, this.governor, slaveId)
    // Register modules...
    return runtime.execute(dag)
  } finally {
    mutex.release()
  }
}
```

### Alternative: Execute Directly in ConversationManager

Instead of going through the HarnessDAG abstraction, execute CDP commands directly:

```typescript
// conversation-manager.ts send():
// [5] SEND — direct CDP commands
const composerSelector = resolved.composer[0]?.selector ?? 'textarea'
const sendSelector = resolved.composer[0]?.sendSelector

// Type the message
await this.governor.cdp.send(slaveId, 'Runtime.evaluate', {
  expression: `(() => {
    const el = document.querySelector('${composerSelector}');
    if (!el) throw new Error('Composer not found: ${composerSelector}');
    el.focus();
    el.value = ${JSON.stringify(message)};
    el.dispatchEvent(new Event('input', { bubbles: true }));
  })()`,
})

// Submit (press Enter or click send button)
if (sendSelector) {
  await this.governor.cdp.send(slaveId, 'Runtime.evaluate', {
    expression: `document.querySelector('${sendSelector}')?.click()`,
  })
} else {
  await this.governor.cdp.send(slaveId, 'Input.dispatchKeyEvent', {
    type: 'keyDown', key: 'Enter', code: 'Enter',
  })
  await this.governor.cdp.send(slaveId, 'Input.dispatchKeyEvent', {
    type: 'keyUp', key: 'Enter', code: 'Enter',
  })
}
```

**Recommendation: Use the direct approach for Phase 2.** It's simpler and gets us working faster. The full HarnessRuntime DAG executor can be wired in Phase 6.
