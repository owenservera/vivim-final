# Unit 2.1 — Fix SlaveId Derivation

**Phase:** 2 | **ID:** 2.1 | **Dependencies:** 1.1

## Problem

`conversation-manager.ts:90` derives slaveId as:
```
slave_{providerId}_{accountId}
```

But `FleetSupervisor.spawn()` creates instances with ID:
```
{providerSlug}_{accountId}_{timestamp}
```

These never match. `ensureRunning(slaveId)` always fails because the derived ID doesn't exist in the fleet.

## Root Cause Analysis

The ConversationManager doesn't spawn slaves — it expects one to already exist. The slave lifecycle is:
1. User completes setup → account persisted
2. First conversation send → `governor.ensureRunning(slaveId)` is called
3. If slave doesn't exist → **should** be spawned here

But `ensureRunning()` only works on existing instances. There's no "ensureRunning by provider+account" that auto-spawns if missing.

## Spec

### Fix: Governor.ensureRunning with Auto-Spawn

Add a new method to ChromeGovernor that derives the slave from provider+account, spawning if needed:

```typescript
// ChromeGovernor
async ensureRunningForAccount(
  providerId: string,
  accountId: string,
  opts?: LaunchOptions
): Promise<ChromeSlave> {
  // Check if any existing instance matches provider+account
  const existing = this.getAllSlaves({ providerId })
    .find(s => s.accountId === accountId)
  
  if (existing) {
    return this.ensureRunning(existing.slaveId)
  }
  
  // No existing slave — spawn one
  return this.spawn(providerId, accountId, opts)
}
```

### Fix: ConversationManager Uses Account-Based Lookup

```typescript
// conversation-manager.ts, in send():
// [2] DERIVE SLAVE — use account-based lookup
const slave = await this.governor.ensureRunningForAccount(
  conv.providerId,
  account.id,
)
const slaveId = slave.slaveId
```

This replaces the broken:
```typescript
const slaveId = deriveSlaveId(conv.providerId, account.id)
const slave = await this.governor.ensureRunning(slaveId)
```

### Alternative: Deterministic SlaveId

Instead of timestamp-based IDs, use deterministic IDs:

```typescript
// FleetSupervisor.spawn()
const id = `${providerSlug}_${accountId}`  // deterministic
// Check if already exists
if (this.instances.has(id)) {
  return this.instances.get(id)!
}
```

This is simpler and ensures the same provider+account always maps to the same slaveId. But it prevents multiple slaves for the same account (which may be desirable for parallel conversations).
