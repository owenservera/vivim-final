# 15.2 — Provider Login: Chrome Opens Itself

> **KPI:** Time-to-auth-confirmed
> **Moment:** User clicks a provider chip. Chrome spawns, navigates to provider,
> user logs in. Agent detects cookies and confirms.

## User Moment

1. User clicks provider chip (e.g. "Claude")
2. Chrome window opens with isolated profile
3. Agent narrates: "Opening Claude in a Chrome window…"
4. User logs in normally in Chrome
5. Agent detects cookies: "Login detected. Saving your profile…"
6. Chrome killed, profile persisted

## KPI Metrics

| Metric | Threshold | Unit | Description |
|--------|-----------|------|-------------|
| `chip_to_chrome_open` | ≤ 3000 | ms | Time from chip click to Chrome window visible |
| `chrome_to_narration` | ≤ 1000 | ms | Time from Chrome open to agent narration |
| `poll_interval` | 3000 | ms | Verify polling interval (fixed) |
| `auth_detect_latency` | ≤ 5000 | ms | Time from login to cookie detection |
| `total_flow_time` | ≤ 120000 | ms | Total onboarding flow (2 min max) |
| `kill_after_auth` | ≤ 2000 | ms | Time from auth confirmed to Chrome killed |

## Measurement

- **Automatic:** `OnboardFlow` / `GuidedLanding` emit `user_moment:provider_login` spans
- **Backend:** `ChromeGovernor` records `chrome.spawn` and `chrome.kill` timestamps
- **Manual:** `bun run devops kpi record --moment=provider_login --chip-to-chrome=<ms>`
