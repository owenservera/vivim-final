# 15.10 — Conversation Search: Memory That Works

> **KPI:** Search latency + relevance
> **Moment:** User searches conversations. Text filter runs against all conversations.
> Provider badges show which AI each conversation is linked to. Full history loads.

## User Moment

1. User types in conversation search bar
2. Text filter runs against all conversations
3. Provider badges show provider colors
4. Timestamps show relative time
5. User clicks conversation → full message history loads
6. Each message is a Node with fork-linking

## KPI Metrics

| Metric | Threshold | Unit | Description |
|--------|-----------|------|-------------|
| `search_to_results` | ≤ 100 | ms | Time from keystroke to filtered list |
| `search_accuracy` | ≥ 90 | % | Top results match user intent |
| `list_render_time` | ≤ 50 | ms | Time to render filtered conversation list |
| `conversation_load_time` | ≤ 500 | ms | Time from click to full history visible |
| `node_graph_materialize` | ≤ 1000 | ms | Time to rebuild graph from source |
| `search_result_count` | ≤ 100 | count | Max results shown (virtual scroll) |

## Measurement

- **Automatic:** `ConversationList` emits `user_moment:conversation_search` via analytics
- **Frontend:** `useCapabilitySearch` records search latency
- **Manual:** `bun run devops kpi record --moment=conversation_search --search-to-results=<ms>`
