# 15.11 — KPI Measurement Infrastructure

> **KPI:** KPI system operational
> **Moment:** DevOps loop can record, query, and alert on user moment KPIs.
> Health dashboard surfaces KPI cards with threshold indicators.

## User Moment (Internal)

1. Engine emits measurement via telemetry hook
2. `KpiMeasurement` row persisted to DB
3. `bun run devops kpi report` aggregates measurements
4. Health dashboard shows KPI cards with green/yellow/red indicators
5. Threshold breaches logged to TelemetryAggregator

## KPI Metrics

| Metric | Threshold | Unit | Description |
|--------|-----------|------|-------------|
| `kpi_record_latency` | ≤ 50 | ms | Time to persist a KPI measurement |
| `kpi_query_latency` | ≤ 200 | ms | Time to aggregate KPI report |
| `kpi_coverage` | 100 | % | All 10 moments have measurement hooks |
| `kpi_alert_accuracy` | 100 | % | Threshold breaches correctly detected |

## Schema

```prisma
model KpiMeasurement {
  id        String   @id @default(cuid())
  moment    String   // e.g. "first_launch", "provider_login"
  metric    String   // e.g. "launch_to_cursor"
  value     Float    // measured value in threshold unit
  unit      String   // e.g. "ms", "count", "%"
  threshold Float    // acceptable threshold
  passed    Boolean  // value <= threshold (or >= for inverted)
  context   String?  // JSON metadata (provider, surface, etc.)
  traceId   String?  // linked trace
  createdAt DateTime @default(now())

  @@index([moment])
  @@index([moment, metric])
  @@index([createdAt])
}
```

## CLI Commands

```bash
bun run devops kpi record --moment=<id> --metric=<name> --value=<n> --unit=<u>
bun run devops kpi report [--moment=<id>] [--since=<date>] [--format=table|json]
bun run devops kpi alerts [--threshold breached] [--since=<date>]
bun run devops kpi dashboard                     # JSON for health dashboard
```
