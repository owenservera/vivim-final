## Context

`ConversationManager.send` (today `src/engines/conversation-manager.ts:147`) is an 8-step **linear** pipeline and cannot iterate, reflect, retry with different providers, or escalate to HITL mid-flight. `AgenticLoopEngine` (`src/engines/agentic-loop.ts:45`) already implements the SENSE→PLAN→ACT→OBSERVE→REFLECT→ADAPT shape with the right bounds (`maxIterations = 20`, `maxDurationMs = 120_000`, `llmBudget = 5`, lines 46–48) but lives in a parallel universe — it is never wired to conversations and plans only with string actions, not capability DAGs.

`AgenticConversationLoop` promotes that loop into the conversation runtime: it senses via `MirrorEngine`, plans via `IntentDecomposer` (2.1) into a `CapabilityDAG`, executes via `CapabilityComposer` (2.4), re-projects, reflects ("did state change as expected?"), and adapts rule confidence in `MemoryEngine`.

## Existing Baseline

- `src/engines/agentic-loop.ts` — `AgenticLoopEngine.executeAgenticLoop` (line 58) provides the loop skeleton, `plan`/`reflect`/`adapt` (lines 155/166/173), `EpisodeRecord` (line 29). Reuse and extend rather than duplicate.
- `src/engines/mirror-engine.ts` — `projectState(conversationId)` (line 229) supplies SENSE/OBSERVE.
- `src/engines/intent-decomposer.ts` — `decompose` / `decomposeWithLlm` (2.1/2.2) supply PLAN as a `CapabilityDAG`.
- `src/engines/capability-composer.ts` — `execute` (2.4) supplies ACT.
- `src/engines/memory-engine.ts` — `recordEpisode` / rule-confidence store supplies ADAPT.

## Interface

### New file: `src/engines/agentic-conversation-loop.ts`

```typescript
import type { MirrorEngine } from './mirror-engine.js'
import type { IntentDecomposer } from './intent-decomposer.js'
import type { CapabilityComposer } from './capability-composer.js'
import type { MemoryEngine } from './memory-engine.js'
import type { CapabilityEventBus } from './capability-event-bus.js'

export interface LoopBounds { maxIterations?: number; maxDurationMs?: number; llmBudget?: number }

export class AgenticConversationLoop {
  private maxIterations = 20
  private maxDurationMs = 120_000
  private llmBudget = 5

  constructor(
    private mirror: MirrorEngine,
    private decomposer: IntentDecomposer,
    private composer: CapabilityComposer,
    private memory: MemoryEngine,
    private bus: CapabilityEventBus,
    bounds?: LoopBounds,
  ) { Object.assign(this, bounds ?? {}) }

  async run(conversationId: string, userMessage: string): Promise<AgenticLoopResult> {
    const start = Date.now()
    const actions: string[] = []
    const episodes: EpisodeRecord[] = []
    let llmCalls = 0

    for (let i = 0; i < this.maxIterations; i++) {
      if (Date.now() - start > this.maxDurationMs) break

      // SENSE
      const before = await this.mirror.projectState(conversationId)
      // PLAN
      const dag = this.decomposer.decompose(userMessage, { conversationId, availableCapabilities: [] })
            ?? await this.decomposer.decomposeWithLlm(userMessage, { conversationId, availableCapabilities: [] })
      if (!dag) break
      // ACT
      const result = await this.composer.executeDag(dag, { conversationId }, { metadata: { iteration: i } })
      actions.push(dag.nodes.map(n => n.capabilitySlug).join(' → '))
      // OBSERVE
      const after = await this.mirror.projectState(conversationId)
      // REFLECT
      const adapted = JSON.stringify(before) !== JSON.stringify(after)
      // ADAPT
      await this.memory.recordEpisode({ providerId: conversationId, action: 'loop', input: { userMessage }, output: { changed: adapted }, success: true, durationMs: Date.now() - start, tags: ['agentic'] })
      episodes.push({ iteration: i, stateBefore: before, action: userMessage, result, observed: after, adapted, ts: Date.now() })

      if (llmCalls >= this.llmBudget) break
    }
    return { success: true, iterations: actions.length, durationMs: Date.now() - start, actions, episodes }
  }
}
```

## Acceptance Criteria

1. `run()` executes SENSE→PLAN→ACT→OBSERVE→REFLECT→ADAPT and returns an `AgenticLoopResult` with `episodes` populated.
2. Bounds are honored: loop stops at `maxIterations=20` OR `maxDurationMs=120_000` OR `llmBudget=5`.
3. PLAN produces a real `CapabilityDAG` (via 2.1/2.2), not a free-text string.
4. Each iteration records an `EpisodeRecord` with `adapted` reflecting whether state changed.
5. `bun run devops gate` passes; loop ≥80% covered (bounds + plan-fallback paths).
