# Unit 2.2 — IntentDecomposer engine — LLM strategy

**Source:** v3 Overview §1.1; `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.2
**Design Doc:** `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.2
**Depends on:** 2.1, 1.3 (LLM backend resolved at runtime via UnifiedCapabilityRegistry; providers registered by Phase 5)
**Produces:** LLM-backed decomposition when no template matches.

---

## Context

When `IntentDecomposer.decompose()` (2.1) returns `null` (no template matched), the LLM strategy takes over. It injects the **available-capability catalog** into the prompt, asks the model to emit a `CapabilityDAG` JSON, validates that output against `CapabilityDAGSchema` (Zod), and — on parse/validation failure — falls through to the clarification flow (2.3).

The LLM never invents capabilities: every emitted `capabilitySlug` must exist in `UnifiedCapabilityRegistry`. This keeps the graph executable and provider-safe.

## Existing Baseline

- `src/engines/intent-decomposer.ts` — the `decompose()` template entry point (2.1) and `CapabilityDAG` / `CapabilityDagNode` types.
- `src/engines/local-model-adapter.ts` — `LocalModelAdapter` provides a local-first completion path (no network). The LLM strategy prefers this adapter so decomposition works offline (see Phase 9 local-first).
- `src/engines/unified-registry.ts` — `UnifiedCapabilityRegistry.list({ category })` (line 92) supplies the catalog to inject.

## Interface

### Extension in `src/engines/intent-decomposer.ts`

```typescript
import { z } from 'zod'
import type { LocalModelAdapter } from './local-model-adapter.js'

// Validates LLM output before it becomes executable.
export const CapabilityDagNodeSchema = z.object({
  id: z.string(),
  capabilitySlug: z.string(),
  inputMapping: z.record(z.unknown()),
  outputKey: z.string().optional(),
  dependsOn: z.array(z.string()),
})
export const CapabilityDAGSchema = z.object({
  nodes: z.array(CapabilityDagNodeSchema),
  edges: z.array(z.object({ from: z.string(), to: z.string() })),
  strategy: z.literal('llm'),
})

export class IntentDecomposer {
  constructor(
    private store: IntentDecomposerStore,
    private registry: UnifiedCapabilityRegistry,
    private llm: LocalModelAdapter,
  ) {}

  /** LLM-backed decomposition. Returns null on parse/validation failure. */
  async decomposeWithLlm(goal: string, ctx: DecomposeContext): Promise<CapabilityDAG | null> {
    const catalog = this.registry.list().map((c) => ({ slug: c.slug, description: c.description }))
    const prompt = this.buildPrompt(goal, catalog)
    const raw = await this.llm.complete(prompt)
    const parsed = this.safeParse(raw)
    if (!parsed) return null
    // Reject any node whose slug is not registered.
    const valid = parsed.nodes.every((n) => this.registry.getBySlug(n.capabilitySlug))
    return valid ? parsed : null
  }

  private buildPrompt(goal: string, catalog: { slug: string; description: string }[]): string { /* ... */ }
  private safeParse(raw: string): CapabilityDAG | null {
    try { return CapabilityDAGSchema.parse(JSON.parse(raw)) } catch { return null }
  }
}
```

## Acceptance Criteria

1. With a mock LLM returning valid `CapabilityDAG` JSON referencing real slugs, `decomposeWithLlm` returns that DAG with `strategy: 'llm'`.
2. Malformed JSON → `null` (no throw).
3. A DAG referencing an unregistered slug → `null` (rejected before execution).
4. The injected catalog contains only slugs from `registry.list()` — the LLM cannot see or emit capabilities outside it.
5. `bun run devops gate` passes; LLM path ≥80% covered via mocked `LocalModelAdapter`.
