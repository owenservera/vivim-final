# Unit 2.1 — IntentDecomposer engine — template strategy

**Source:** v3 Overview §1.1; `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.1
**Design Doc:** `docs/master-plan-v3/PHASE-02-agentic-core.md` §2.1
**Depends on:** 1.3
**Produces:** `decompose(goal, context) → CapabilityDAG` for known patterns.

---

## Context

Today `SituationDetector` (`src/engines/situation-detector.ts:257`) only classifies a message into a *task type* (`coding`, `debugging`, `researching`, …). It never decomposes intent into an executable capability graph. The agent has no mechanism to translate "find every failing test in this repo and open an issue for each" into a concrete `CapabilityDAG` of bound capability invocations.

`IntentDecomposer` is the planner that consumes `(user goal, conversation context, available capabilities)` and emits a typed `CapabilityDAG` whose nodes reference capability **slugs** from `UnifiedCapabilityRegistry` (not raw CDP selectors). The template strategy is the first and fastest of three strategies (template → LLM → clarification, see 2.2 / 2.3).

## Existing Baseline

- `src/engines/situation-detector.ts` — `SituationDetector.detect()` (line 263) returns `SituationSignal` (task type + confidence). Useful as a pre-filter but produces no DAG.
- `src/engines/unified-registry.ts` — `UnifiedCapability` (line 19) and `UnifiedCapabilityRegistry` (line 61). DAG nodes will reference `cap.slug` / `cap.id`. `register` (line 65) throws on duplicate slug.
- `src/engines/capability-macro.ts` — existing `CapabilityMacroEngine.define()` (line 50) stores an **opaque `dagJson` string** (line 14); `CapabilityComposer` (2.4) replaces this with typed DAGs.
- `src/storage/contracts/` — a new `IntentTemplateStore` contract is required (no existing one). The `intent_template` table is declared in `docs/master-plan-v3/00-OVERVIEW.md` §2 (Storage / Schema Adjustments).

## Interface

### New file: `src/engines/intent-decomposer.ts`

```typescript
import type { UnifiedCapabilityRegistry } from './unified-registry.js'

/** A single node in a decomposed capability graph. References a capability slug. */
export interface CapabilityDagNode {
  id: string
  capabilitySlug: string
  inputMapping: Record<string, unknown>   // bound params, may include wildcards resolved from context
  outputKey?: string                       // name this node's output is bound to for downstream nodes
  dependsOn: string[]                      // node ids that must run first
}

export interface CapabilityDAG {
  nodes: CapabilityDagNode[]
  edges: Array<{ from: string; to: string }>
  strategy: 'template' | 'llm' | 'clarification'
}

export interface IntentTemplate {
  id: string
  pattern: string                          // regex matched against normalized goal
  wildcards: string[]                      // e.g. ['url', 'provider', 'capability']
  dag: CapabilityDAG                       // template DAG with `{wildcard}` tokens
}

export interface IntentDecomposerStore {
  listTemplates(): Promise<IntentTemplate[]>
  getTemplate(id: string): Promise<IntentTemplate | null>
}

export interface DecomposeContext {
  conversationId?: string
  availableCapabilities: string[]          // slugs resolvable in the registry
  variables?: Record<string, string>       // pre-extracted {url}, {provider}, etc.
}

export class IntentDecomposer {
  constructor(
    private store: IntentDecomposerStore,
    private registry: UnifiedCapabilityRegistry,
  ) {}

  /** Template match. Returns null when no template matches (caller falls to 2.2). */
  decompose(goal: string, ctx: DecomposeContext): CapabilityDAG | null {
    const normalized = goal.trim().toLowerCase()
    for (const tpl of this.store.listTemplatesSync()) {
      const m = new RegExp(tpl.pattern, 'i').exec(goal)
      if (!m) continue
      const bindings = this.extractWildcards(tpl, m)
      const merged = { ...ctx.variables, ...bindings }
      return this.instantiate(tpl.dag, merged, ctx.availableCapabilities)
    }
    return null
  }

  private extractWildcards(tpl: IntentTemplate, m: RegExpExecArray): Record<string, string> { /* ... */ }
  private instantiate(dag: CapabilityDAG, vars: Record<string, string>, available: string[]): CapabilityDAG { /* resolve {tokens}, drop nodes whose slug is unavailable */ }
}
```

### Seed: `seeds/intent-templates/*.json`

Ship ~15 templates covering `navigate`, `search`, `extract`, `summarize`, `compare`, `translate`, etc. Each row binds `{url}`, `{provider}`, `{capability}` wildcards into a typed DAG.

## Acceptance Criteria

1. `IntentDecomposer.decompose('navigate to https://example.com and extract the title', ctx)` returns a `CapabilityDAG` with ≥2 nodes referencing real registry slugs.
2. A template whose capability slug is NOT in `ctx.availableCapabilities` is pruned or the node marked `unavailable`.
3. `decompose()` returns `null` for a goal with no matching template (so 2.2 can take over).
4. No node references a raw CDP selector — every `capabilitySlug` resolves via `registry.getBySlug()`.
5. `bun run devops gate` passes; `decompose` has ≥80% unit-test coverage.
