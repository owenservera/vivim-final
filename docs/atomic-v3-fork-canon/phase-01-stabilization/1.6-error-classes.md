# Unit 1.6 — Replace raw `new Error()` with CapStoreError subclasses

**Source:** invariant B7 (`checkB7_ErrorClasses`)
**Design Doc:** `docs/master-plan-v3/PHASE-01-stabilization.md` §1.6
**Depends on:** —
**Produces:** Zero B7 violations.

---

## Context

`devops invariants check --category B` reports B7 for every `new Error(` in `src/engines/`. The v1 codebase uses `EngineError` from `src/errors.ts` for most cases but has many stragglers using raw `Error`.

## Strategy

For each `new Error(...)` in `src/engines/`:

1. Determine the appropriate error class:
   - **`EngineError`** — generic engine failure (existing).
   - **`ValidationError`** — bad input (existing).
   - **`NotFoundError`** — entity not found (existing).
   - **`ConflictError`** — state conflict (existing).
   - **Add new subclasses as needed** (see below).

2. Replace `throw new Error('msg')` with `throw new EngineError('msg')` (or more specific subclass).

3. Update tests that catch `Error` to catch the more specific class.

## Acceptance Criteria

1. `rg "new Error\(" src/engines/` returns zero hits.
2. All new error subclasses have a unit test verifying their `code`, `message`, and `toJSON()`.
3. `bun run devops invariants check --category B` reports zero B7 violations.
4. `bun run devops gate` passes.

## Tests

`tests/unit/errors.test.ts` — extend existing:

```typescript
test('IntentDecompositionError', () => {
  const err = new IntentDecompositionError('no match', { goal: 'foo' })
  expect(err.code).toBe('IntentDecompositionError')
  expect(err.message).toBe('no match')
  expect(err.details).toEqual({ goal: 'foo' })
  expect(err.toJSON()).toEqual({
    error: 'no match',
    code: 'IntentDecompositionError',
    details: { goal: 'foo' },
  })
})

```
