# Unit 1.1 — Remove provider-logic/ legacy directory

**Source:** v3 Overview §1.10; invariant B3 (Seeds Not Code); `devops/invariants.ts:checkB3_SeedsNotCode`
**Design Doc:** `docs/master-plan-v3/PHASE-01-stabilization.md` §1.1
**Depends on:** —
**Produces:** Clean engine boundary; engines cannot accidentally import forbidden TS provider configs.

---

## Context

`provider-logic/` is a legacy TS mirror of `seeds/providers/*.json`. It contains hardcoded `PROVIDER_CONFIGURATIONS`, `PROVIDER_RECOVERY_STRATEGIES`, and `PROVIDER_CAPABILITY_OVERRIDES`. The v1 invariant B3 (`checkB3_SeedsNotCode`) explicitly forbids engines from importing these — providers must be DB-driven via `ProviderRegistrar` reading seed JSON.

The directory still exists because early engine prototypes imported from it; those imports have since been removed (verified by `rg "provider-logic" src/`), but the directory and its tests remain, creating confusion about the canonical source.

## Acceptance Criteria

1. `provider-logic/` directory does not exist.
2. `rg "provider-logic" --type ts` returns zero hits across `src/`, `tests/`, `scripts/`, `sdk/`, `web/`.
3. `bun run devops invariants check --category B` reports zero B3 violations.
4. `bun run devops gate` passes (no test breakage).

## Implementation Steps

1. Audit current usage:
   ```powershell
   rg "provider-logic" --type ts
   rg "PROVIDER_CONFIGURATIONS"
   rg "from.*provider-logic"
   ```
2. For each test file in `provider-logic/` that has live coverage value: port the test to `tests/unit/engines/provider-registrar.test.ts` (it should already exist; check for duplicates and merge).
3. Delete `provider-logic/` entirely:
   ```powershell
   Remove-Item -Recurse -Force "C:\0-BlackBoxProject-0\vivim-final\provider-logic"
   ```
4. Run `bun run devops gate` and resolve any import errors (likely zero since src doesn't import it).
5. Commit with `chore: remove legacy provider-logic/ directory (B3 compliance)`.

## Risk

- **Low.** Source code does not import from `provider-logic/` (already enforced by B3 invariant which currently passes for B3 specifically).
- If any test imported it, those tests get ported in step 2.

## DevOps Verification

```powershell
bun run devops invariants check --category B
# Expected: B3 reports zero violations
bun run devops truth scan
# Expected: provider-logic files no longer appear
```
