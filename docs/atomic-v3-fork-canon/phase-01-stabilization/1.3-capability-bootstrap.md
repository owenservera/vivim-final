# Unit 1.3 — Complete UnifiedCapabilityRegistry bootstrap with default capabilities

**Source:** v3 Overview §1.2, §1.3; `src/engines/unified-registry.ts`
**Design Doc:** `docs/master-plan-v3/PHASE-01-stabilization.md` §1.3
**Depends on:** 1.2
**Produces:** A registry populated at startup with ~20 default capabilities exported to all five surfaces (CLI, UI, workflow, MCP, API).

---

## Context

`UnifiedCapabilityRegistry` is implemented but empty at startup. No code registers capabilities into it. The registry's surface-export methods (`exportForCli`, `exportForMcp`) return empty arrays. This means: MCP servers expose no tools, CLI auto-commands is empty, workflows cannot call capabilities by reference.

This unit creates the bootstrap module that registers default capabilities. Each later phase adds more.

## Handler Dispatch

Handlers need access to engine instances (ConversationStore, Governor, etc.). Two options:

**Option A (chosen):** Handlers are closures capturing the engine instances from the bootstrap scope. Simple, no DI framework needed.

**Option B:** Handlers dispatch by string ID through a `ServiceLocator`. More flexible but adds indirection.

Going with Option A for v3. The `registerDefaultCapabilities` function takes a `services` argument:

```typescript
export interface BootstrapServices {
  db: CapStoreDb
  conversationStore: ConversationStore
  governor: ChromeGovernor
  conversationManager: ConversationManager
  memoryEngine?: MemoryEngine
  semanticSearch?: SemanticSearchEngine
  knowledgeIngestion?: KnowledgeIngestionEngine
  synthesizer?: CrossConversationSynthesizer
}

export function registerDefaultCapabilities(
  registry: UnifiedCapabilityRegistry,
  services: BootstrapServices,
): void { /* handlers close over `services` */ }
```

## Acceptance Criteria

1. After `createServerWithEngines`, `registry.list().length >= 18`.
2. `registry.exportForCli().length >= 18`.
3. `registry.exportForMcp().length >= 18`.
4. `registry.getBySlug('conversation_send')` returns the capability.
5. Executing `conversation_list` returns an array (possibly empty).
6. `bun run devops gate` passes.

## Tests

`tests/unit/engines/capability-bootstrap.test.ts`:

```typescript
import { describe, test, expect } from 'bun:test'
import { UnifiedCapabilityRegistry } from '@/engines/unified-registry'
import { registerDefaultCapabilities } from '@/engines/capability-bootstrap'

describe('registerDefaultCapabilities', () => {
  test('registers at least 18 capabilities', () => {
    const registry = new UnifiedCapabilityRegistry()
    registerDefaultCapabilities(registry, { /* mock services */ } as never)
    expect(registry.list().length).toBeGreaterThanOrEqual(18)
  })
  
  test('every capability has all five surfaces', () => {
    const registry = new UnifiedCapabilityRegistry()
    registerDefaultCapabilities(registry, {} as never)
    for (const cap of registry.list()) {
      expect(cap.surfaces).toContain('cli')
      expect(cap.surfaces).toContain('ui')
      expect(cap.surfaces).toContain('mcp')
      expect(cap.surfaces).toContain('api')
    }
  })
  
  test('capability slugs are unique', () => {
    const registry = new UnifiedCapabilityRegistry()
    registerDefaultCapabilities(registry, {} as never)
    const slugs = registry.list().map(c => c.slug)
    expect(new Set(slugs).size).toBe(slugs.length)
  })
  
  test('conversation_list handler returns an array', async () => {
    const registry = new UnifiedCapabilityRegistry()
    registerDefaultCapabilities(registry, mockServices)
    const result = await registry.execute('cap:conversation:list', {}, { metadata: {} })
    expect(Array.isArray(result)).toBe(true)
  })
})
```
