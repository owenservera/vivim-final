# Unit 1.2 — Wire AutonomousExecutionEngine into server bootstrap

**Source:** v3 Overview §1.4; `src/server/index.ts:createServerWithEngines` line ~426 passes `{} as never` for the registry
**Design Doc:** `docs/master-plan-v3/PHASE-01-stabilization.md` §1.2
**Depends on:** —
**Produces:** Autonomous endpoints fully functional; `/api/autonomous/*` always available, not conditional.

---

## Context

`createServerWithEngines` constructs `AutonomousExecutionEngine` with `{} as never` as the registry argument:

```typescript
autonomousEngine = new AutonomousExecutionEngine(
  autonomousStore,
  {} as never, // registry — optional, wired later
  policyEngine,
  governor,
  eventBus,
)
```

This is a stub escape hatch. The autonomous engine cannot execute `capability_call` steps because the registry is empty. Additionally, the autonomous router is conditionally attached only when both autonomous + policy engines exist — meaning a partial wiring failure silently disables the endpoints.

## Interface

```typescript
// src/server/index.ts (excerpt)
export async function createServerWithEngines(port = 9420): Promise<ServerContext> {
  // ... existing bootstrap ...
  
  const registry = new UnifiedCapabilityRegistry()
  // (Unit 1.3 will register default capabilities into this registry)
  
  const autonomousStore = new AutonomousStoreImpl()
  const pStore = new PolicyStoreImpl()
  const policyEngine = new ExecutionPolicyEngine(pStore)
  await policyEngine.initialize()
  
  const autonomousEngine = new AutonomousExecutionEngine(
    autonomousStore,
    registry,  // ← real registry, not {} as never
    policyEngine,
    governor,
    eventBus,
  )
  
  // Always attach the router; the engine is always present after the above wiring.
  const autonomousRouter = createAutonomousRouter({ autonomousEngine, policyEngine })
  
  // ... rest of bootstrap, autonomousRouter always non-null ...
}
```

`ServerContext` gets two new fields:

```typescript
export interface ServerContext {
  // ... existing ...
  autonomousEngine?: AutonomousExecutionEngine
  policyEngine?: ExecutionPolicyEngine
  registry?: UnifiedCapabilityRegistry
}
```

## Acceptance Criteria

1. `POST /api/autonomous/execute` with a `goal.description` returns 200 + `{taskId, status}`.
2. `GET /api/autonomous/tasks` returns 200 + task list (may be empty).
3. `GET /api/autonomous/gates` returns 200 + gate list.
4. No `as never` for the registry argument in `createServerWithEngines`.
5. `bun run devops gate` passes.
