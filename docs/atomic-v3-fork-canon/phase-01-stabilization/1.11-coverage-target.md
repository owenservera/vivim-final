# Unit 1.11 — Achieve 80% coverage on src/engines, 85% on src/server

**Source:** AGENTS.md testing protocol; v3 Overview §4 Scenario E
**Design Doc:** `docs/master-plan-v3/PHASE-01-stabilization.md` §1.11
**Depends on:** 1.4, 1.5, 1.6
**Produces:** `bun run devops gate --strict` passes the coverage step.

---

## Context

The devops gate (`devops/gate.ts:COVERAGE_THRESHOLD`) requires:
- `src/engines` ≥ 80%
- `src/storage/impl` ≥ 70%
- `src/server` ≥ 85%
- `src/cli` ≥ 60%

Current coverage is unknown (gate's coverage check is wrapped in try/catch and silently skips on failure). After 1.4-1.10 are done, every engine is real and tested in isolation; this unit fills the remaining gaps.

## Strategy

### Step 1: Measure baseline

```powershell
bun test --coverage 2>&1 | Select-String "src/engines|src/server|src/storage|src/cli|All files"
```

Capture per-directory coverage. Identify the laggards.

### Step 2: Prioritize

For each engine below 80% coverage:
1. List untested branches (`bun test --coverage --coverage-reporter=lcov` → open `coverage/lcov.info`).
2. Write one test per untested branch.
3. Re-measure after every 5 tests.

### Step 3: Focus on happy-path + one error path

Full edge-case coverage is Phase 10's job. Phase 1 just needs:
- Every public method has at least one test calling it.
- Every `throw new ...Error(...)` has at least one test triggering it.
- Every `if/else` branch has at least one test exercising each side.

### Step 4: Server coverage

For each router in `src/server/`:
- Test one successful request per endpoint.
- Test one auth-failure (when AUTH_TOKEN is set).
- Test one not-found case.

## Files to Add

Approximately:
- ~5 new tests in `tests/unit/engines/` for engines with <80% coverage.
- ~3 new tests in `tests/unit/server/` for routers with <85% coverage.

Specific engines likely needing more coverage (based on initial code review):
- `src/engines/workflow-engine.ts` (large file, complex execution logic)
- `src/engines/capability-resolution.ts` (35 field mappings + 3 filter stages)
- `src/engines/autonomous-execution.ts` (HITL gate flow, plan generation)
- `src/engines/encryption.ts` (round-trip encrypt/decrypt + lock state)
- `src/engines/sync.ts` (pairing, conflict handling)
- `src/engines/airgap.ts` (network probe, local model check)

## Acceptance Criteria

1. `bun test --coverage` reports:
   - `src/engines` ≥ 80%
   - `src/server` ≥ 85%
   - `src/storage/impl` ≥ 70%
   - `src/cli` ≥ 60%
2. `bun run devops gate --strict` passes the coverage step (does not silently skip).
3. No new tests use `as any` or skip assertions.
4. `bun run devops gate` passes end-to-end.

## DevOps Verification

```powershell
bun test --coverage
bun run devops gate --strict
```
