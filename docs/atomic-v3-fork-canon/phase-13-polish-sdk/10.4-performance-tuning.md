## Context

Before tagging v3 we need a performance baseline + the slowest 3 operations optimized. This unit measures: server boot time, capability resolution latency, canvas spawn latency, agentic-loop iteration latency, memory recall latency. Optimizes the slowest 3 and documents baselines in `docs/performance/baselines.md`.

## Existing Baseline

- `src/server/bootstrap.ts` — server boot; the boot-time probe wraps this.
- `src/engines/unified-registry.ts` (1.3) — capability resolution (`resolve(slug)`); the latency probe wraps it.
- `docs/atomic-v3/phase-03-html-canvas/3.3-canvas-spawner.md` — `CanvasSpawner.spawn`; canvas spawn latency.
- `src/engines/agentic-loop.ts` (2.11) — one iteration; agentic-loop iteration latency.
- `src/engines/memory-engine.ts` (6.x) — `recallFacts`/`recallEpisodes`; memory recall latency.
- `docs/performance/` — created by this unit.

## Interface

### New file: `bench/perf.ts` (sketch)

```typescript
const BENCHMARKS = {
  serverBootMs: () => timed(() => import('../src/server/bootstrap.js')),
  capabilityResolveMs: (slug) => timed(() => registry.resolve(slug)),
  canvasSpawnMs: () => timed(() => spawner.spawn({})),
  agenticIterationMs: () => timed(() => loop.iterate()),
  memoryRecallMs: (q) => timed(() => memory.recallFacts(q)),
}

export async function runBenchmarks(): Promise<Record<string, number>> {
  const out: Record<string, number> = {}
  for (const [k, fn] of Object.entries(BENCHMARKS)) out[k] = await fn()
  return out
}
```

### Optimization targets (slowest 3)

1. **Capability resolution** — memoize `UnifiedCapabilityRegistry.resolve` (cache by slug).
2. **Canvas spawn** — parallelize slace init + CDP attach (vs sequential).
3. **Memory recall** — add an index on `embedding` + cache recent recalls.

## Acceptance Criteria

1. `bench/perf.ts` measures all 5 operations and writes `docs/performance/baselines.md`.
2. The slowest 3 operations are optimized (with before/after numbers in the doc).
3. Optimization does not change behavior (regression tests still green).
4. `bun run devops gate` passes.
5. Baselines are committed so future runs can detect drift.
