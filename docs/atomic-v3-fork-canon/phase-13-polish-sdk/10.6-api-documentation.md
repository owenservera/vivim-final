# Unit 10.6 — API documentation (OpenAPI)

**Source:** v3 Overview §3; `docs/master-plan-v3/PHASE-10-polish-sdk.md` §10.6
**Design Doc:** `docs/master-plan-v3/PHASE-10-polish-sdk.md` §10.6
**Depends on:** all
**Produces:** `docs/api/openapi.yaml` generated from route definitions.

---

## Context

Every HTTP endpoint must be documented with params, request/response schemas, and examples — auto-generated from a route→schema map maintained alongside the routers. Published to `docs/api/` as both YAML and rendered HTML.

## Existing Baseline

- `src/server/*-router.ts` — `index.ts`, `autonomous-router.ts`, `conversation-router.ts`, `knowledge-router.ts`, `memory-viz-router.ts`, `mux-router.ts`, `setup-router.ts`, `websocket.ts`, `auth-gate.ts`. Each route is annotated (or will be) with a schema reference.
- `src/schema/*` — Zod schemas (request/response) the OpenAPI generator consumes.
- `docs/api/` — created by this unit (YAML + HTML output).

## Interface

### New file: `docs/api/build-openapi.ts`

```typescript
import { z } from 'zod'
import { conversationRoutes } from '../../src/server/conversation-router.js'
import { autonomousRoutes } from '../../src/server/autonomous-router.js'
// ...one entry per router

export interface RouteSpec {
  method: 'get' | 'post' | 'put' | 'delete'
  path: string
  requestSchema?: z.ZodType
  responseSchema: z.ZodType
  example: unknown
}

export function buildOpenApi(specs: RouteSpec[]): OpenApiDoc {
  const paths: Record<string, unknown> = {}
  for (const s of specs) {
    paths[s.path] ??= {}
    paths[s.path][s.method] = {
      requestBody: s.requestSchema ? { content: { 'application/json': { schema: zodToJson(s.requestSchema) } } } : undefined,
      responses: { 200: { content: { 'application/json': { schema: zodToJson(s.responseSchema), example: s.example } } } },
    }
  }
  return { openapi: '3.1.0', info: { title: 'vivim', version: '3.0.0' }, paths }
}
```

### Output

```
docs/api/openapi.yaml     (generated)
docs/api/openapi.html     (rendered via redoc/scalar)
```

## Acceptance Criteria

1. `docs/api/openapi.yaml` is valid OpenAPI 3.1 covering every route in `src/server/*-router.ts`.
2. Each operation documents params, request schema (if any), response schema, and an example.
3. Schemas are sourced from `src/schema/*` Zod defs (no hand-duplicated JSON).
4. Rendered `openapi.html` is produced alongside the YAML.
5. The generator is idempotent (re-running yields the same doc).
6. `bun run devops gate` passes.

## Tests

`tests/unit/api/openapi.test.ts`:
- buildOpenApi with the real router specs → valid doc; count of paths ≥ number of registered routes.
- every path has a `responses.200` with a schema.
