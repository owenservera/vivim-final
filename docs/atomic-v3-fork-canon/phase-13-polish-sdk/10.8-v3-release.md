# Unit 10.8 — v3 release

**Source:** v3 Overview §4; `docs/master-plan-v3/PHASE-10-polish-sdk.md` §10.8
**Design Doc:** `docs/master-plan-v3/PHASE-10-polish-sdk.md` §10.8
**Depends on:** all
**Produces:** Tagged release `v3.0.0`; migration guide from v1; changelog.

---

## Context

The capstone: cut the `v3.0.0` tag after the full gate passes, publish the SDK (10.1), and post release notes that explain what changed from v1 and how to migrate. Final gate: `bun run devops gate --strict --full` green, truth score ≥95%, coverage ≥80%/85%, all ADRs approved, all Overview §4 sample scenarios verified end-to-end.

## Existing Baseline

- `AGENTS.md` — `bun run devops gate` is the gate; `--strict` (new issues = fail) + `--full` (whole suite) are the release flags.
- `docs/roadmap/INVARIANTS.md` — invariant categories A–E; truth score is computed there.
- `docs/atomic-v3/01-tracker.md` — the 108-unit tracker; all must be `[x]`.
- `docs/decisions/` (10.5) — ADR-001..008 approved.
- `docs/master-plan-v3/` Overview §4 — the sample scenarios to verify.
- `package.json` — version bump to `3.0.0`; `sdk/` published.
- `CHANGELOG.md` / `docs/migration/v1-to-v3.md` — created/updated by this unit.

## Interface

### Release checklist (this unit enforces)

```powershell
# 1. Full strict gate
bun run devops gate --strict --full

# 2. Truth score
bun run devops invariants check --category A   # ground-truth / research-first
bun run devops invariants report          # truth score >= 95%

# 3. Coverage
bun run devops coverage                        # >= 80% engines, 85% server

# 4. ADRs approved
bun run devops decision list                   # 001..008 APPROVED

# 5. Sample scenarios (Overview S4) verified end-to-end
bun run tests/e2e/v3-scenarios.test.ts

# 6. Cut tag + publish
git tag -a v3.0.0 -m "vivim v3: sovereign agentic platform"
npm publish --workspace sdk
```

### Docs produced

```
CHANGELOG.md                      (v3.0.0 entry)
docs/migration/v1-to-v3.md       (what changed + migration steps)
docs/release-notes-v3.md         (user-facing summary)
```

## Acceptance Criteria

1. `bun run devops gate --strict --full` passes on the release commit.
2. Truth score ≥95% (invariants report).
3. Coverage ≥80% (engines) / ≥85% (server).
4. All ADRs (001..008) are APPROVED.
5. Every Overview §4 sample scenario verified end-to-end (incl. offline week, 7-day encrypted backup <100MB, 2-device pair <30s).
6. `v3.0.0` tag cut; `sdk/` published; `CHANGELOG.md` + `v1-to-v3.md` + release notes posted.
7. `bun run devops gate` stays green post-tag.
