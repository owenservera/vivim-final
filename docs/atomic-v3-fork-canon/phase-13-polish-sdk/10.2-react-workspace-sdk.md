# Unit 10.2 — React workspace SDK (`web/workspace-sdk/`)

**Source:** v3 Overview §3; `docs/master-plan-v3/PHASE-10-polish-sdk.md` §10.2
**Design Doc:** `docs/master-plan-v3/PHASE-10-polish-sdk.md` §10.2
**Depends on:** 10.1, Phase 4
**Produces:** Embeddable React components for the workspace shell.

---

## Context

The workspace (Phase 4) should be embeddable into other hosts — Electron, VS Code webviews, or any React app. This unit ships `web/workspace-sdk/` with a `<VivimWorkspace client={client} layout="dual" />` component that renders a full workspace from the 10.1 SDK client.

## Existing Baseline

- `web/` — React app (3.x/4.x) with the workspace shell, panels (ConversationPanel, CanvasPanel, MemoryBrowser 6.10, TelemetryDashboard 8.3, etc.).
- `sdk/` (10.1) — `VivimClient` provides data + WS to the component.
- `web/src/App.tsx` (4.x) — the in-product shell; the SDK component reuses the same panels.
- `package.json` (`web/`) — add `workspace-sdk` export + peer `react`.

## Interface

### New package: `web/workspace-sdk/VivimWorkspace.tsx` (sketch)

```tsx
import type { VivimClient } from '@vivim/sdk'
import { ConversationPanel } from '../surfaces/ConversationPanel'
import { CanvasPanel } from '../surfaces/CanvasPanel'
import { MemoryBrowser } from '../surfaces/MemoryBrowser'

export interface VivimWorkspaceProps {
  client: VivimClient
  layout?: 'dual' | 'single' | 'compact'
}

export function VivimWorkspace({ client, layout = 'dual' }: VivimWorkspaceProps) {
  return (
    <WorkspaceProvider client={client}>
      <div className={`vivim-workspace layout-${layout}`}>
        <ConversationPanel />
        <CanvasPanel />
        <MemoryBrowser />
      </div>
    </WorkspaceProvider>
  )
}
```

### `web/package.json` export

```json
{ "exports": { "./workspace-sdk": { "import": "./workspace-sdk/VivimWorkspace.tsx" } },
  "peerDependencies": { "react": ">=18", "@vivim/sdk": "3.0.0" } }
```

## Acceptance Criteria

1. `<VivimWorkspace client layout="dual" />` renders a full workspace inside a host React app.
2. The component consumes `VivimClient` (10.1) for data + WS; no direct server imports.
3. `layout` prop switches panel arrangement (`dual`/`single`/`compact`).
4. It is embeddable in Electron / VS Code webview (no `window`-only globals at module load).
5. Reuses the same panels as the in-product shell (no fork).
6. `bun run devops gate` passes (root + `web/`).

## Tests

`web/workspace-sdk/__tests__/VivimWorkspace.test.tsx` (mock `VivimClient`):
- renders with `dual` layout; contains conversation + canvas + memory panels.
- `layout="single"` renders without crashing.
- passes the client into panels (mock panel reads context).
