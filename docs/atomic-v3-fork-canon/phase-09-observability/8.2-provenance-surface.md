## Context

Users need to *see* why the system did what it did. This unit ships a `ProvenanceInspectorSurface`: pick an outcome, render the provenance tree (`selector → parser → program → provider state → conversation turn`), click any node to inspect the raw CDP request/response, and filter by date / provider / capability. Builds on `ProvenanceGraph` (2.14) + trace spans (8.1).

## Existing Baseline

- `docs/atomic-v3/phase-02-agentic-core/2.14-provenance-graph.md` — `ProvenanceGraph` with `recordEdge` / `edgesFor` / `querySelectorHistory`. The surface reads `edgesFor(outcomeId)`.
- `docs/atomic-v3/phase-07-autonomous-orchestration/7.2-step-reflection.md` — provenance edges already recorded during execution.
- `src/engines/trace-span.ts` (8.1) — `trace_span` rows give the raw CDP request/response shown on node click.
- `docs/atomic-v3/phase-03-html-canvas/3.x` — the surface is rendered as a built-in canvas (Phase 3 patterns) or a workspace panel (4.x).

## Interface

### New file: `web/src/surfaces/ProvenanceInspector.tsx` (sketch)

```tsx
import { useEffect, useState } from 'react'
import cytoscape from 'cytoscape'

export function ProvenanceInspector() {
  const [tree, setTree] = useState<ProvenanceTree | null>(null)
  const [filters, setFilters] = useState<{ date?: string; provider?: string; capability?: string }>({})

  async function load(outcomeId: string) {
    setTree(await fetch(`/api/provenance/tree/${outcomeId}?` + new URLSearchParams(filters)).then(r => r.json()))
  }

  useEffect(() => { if (tree) renderCytoscape(tree) }, [tree])

  return (
    <div className="provenance-inspector">
      <OutcomePicker onPick={load} />
      <GraphPanel onClickNode={(n) => openRaw(n.traceSpanId)} />
      <RawCdpDrawer />
      <FilterBar value={filters} onChange={setFilters} />
    </div>
  )
}
```

### Backend route: `src/server/routes/provenance.ts`

```
GET /api/provenance/outcomes?filter=...
GET /api/provenance/tree/:outcomeId?date=&provider=&capability=
GET /api/provenance/raw/:traceSpanId   // CDP request/response
```

## Acceptance Criteria

1. Picking an outcome renders its provenance tree (selector → parser → program → provider state → conversation turn).
2. Clicking a node fetches + shows the raw CDP request/response from `trace_span`.
3. Filters (date / provider / capability) narrow the rendered tree.
4. Any outcome in the system is reachable within 3 UI clicks (acceptance).
5. `bun run devops gate` passes (root + `web/`).
