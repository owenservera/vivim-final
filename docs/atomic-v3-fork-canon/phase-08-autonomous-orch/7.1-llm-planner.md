## Context

Today `planGoal` (autonomous-execution.ts:473) is regex-based action extraction. This unit replaces it with `IntentDecomposer.decompose` (spec'd in 2.1/2.2) so plans are real `CapabilityDAG`s. Each plan step becomes a triple `(capabilitySlug, inputMapping, classification)` instead of a free-form string.

## Existing Baseline

- `src/engines/autonomous-execution.ts:473` — `private async planGoal(goal)` returns `AutonomousStep[]`; today uses regex. We swap the body to call `IntentDecomposer`.
- `src/engines/autonomous-execution.ts:42` — `AutonomousStep.{action, actionInput, classification}`; `action` becomes a `capabilitySlug`.
- `docs/atomic-v3/phase-02-agentic-core/2.1-intent-templates.md` + `2.2-intent-llm.md` — define `IntentDecomposer.decompose(goal): { strategy, dag: CapabilityDAG }` where `CapabilityDAG = { nodes: CapabilityNode[], edges: [from,to][] }` and `CapabilityNode = { slug, inputMapping, classification }`.
- `src/engines/capability-composer.ts` (2.4) — resolves composite nodes later (7.9).

## Interface

### Change in `src/engines/autonomous-execution.ts`

```typescript
import { IntentDecomposer } from './intent-decomposer.js'

private async planGoal(goal: AutonomousGoal): Promise<AutonomousStep[]> {
  const decomposer = new IntentDecomposer()
  const { dag } = await decomposer.decompose({ description: goal.description, maxSteps: goal.maxSteps })
  return dag.nodes.map((node, i) => this.toStep(goal, node, i))
}

private toStep(goal: AutonomousGoal, node: CapabilityNode, i: number): AutonomousStep {
  return {
    id: ulid(), taskId: goal.id!, stepIndex: i,
    description: node.description ?? node.slug,
    action: node.slug,                       // capability slug, not raw string
    actionInput: node.inputMapping ?? {},
    classification: node.classification ?? 'read',
    status: 'pending', result: null, error: null,
    startedAt: null, completedAt: null,
    requiresHumanApproval: classificationAtLeast(node.classification ?? 'read', goal.requireApprovalAbove),
  }
}
```

## Acceptance Criteria

1. `planGoal` returns steps whose `action` is a valid `capabilitySlug` (resolvable in `UnifiedCapabilityRegistry`).
2. Each step carries `inputMapping` + `classification` from the decomposed `CapabilityDAG`.
3. No regex-based action extraction remains in `planGoal`.
4. `requiresHumanApproval` is derived from `classification` vs `goal.requireApprovalAbove` (unchanged behavior).
5. `bun run devops gate` passes.

## Tests
