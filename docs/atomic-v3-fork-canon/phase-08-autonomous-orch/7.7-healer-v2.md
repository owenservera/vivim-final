## Context

`SelectorHealer` (selector-healer.ts) tries 5 strategies in sequence. Phase 7.7 adds provenance-aware healing: (a) check `ProvenanceGraph` for "this selector last worked on {date} with provider state {X}"; (b) if a known-good alternate selector exists in `selector_strategy`, prefer it over the LLM proposal; (c) record the healed selector in `selector_strategy` with `isHealed: 1`.

## Interface

### Change in `src/engines/selector-healer.ts`

```typescript
export interface HealContext {
  providerId: string
  capabilityId: string
  provenance: ProvenanceGraph
  strategyStore: SelectorStrategyStore
}

export class SelectorHealer {
  async heal(params: { failedSelector: SemanticSelector; context: HealContext }): Promise<HealResult | null> {
    // (a) provenance: did this selector last work, and under what provider state?
    const last = params.context.provenance.querySelectorHistory(params.failedSelector, params.context.capabilityId)
    if (last?.providerState) {
      // (b) prefer a known-good alternate already in selector_strategy
      const knownGood = params.context.strategyStore.findAlternate(
        params.context.capabilityId, params.failedSelector,
      )
      if (knownGood && !knownGood.isHealed) {
        return this.applyKnownGood(knownGood)
      }
    }
    // fallback: existing 5-strategy LLM proposal
    const proposed = await this.llmHeal(params.failedSelector)
    if (proposed) {
      // (c) record healed selector with isHealed flag
      params.context.strategyStore.record({ selector: proposed.healed, capabilityId: params.context.capabilityId, isHealed: 1, lastWorkedAt: Date.now() })
    }
    return proposed
  }
}
```

## Acceptance Criteria

1. Before proposing, `heal` queries `ProvenanceGraph.querySelectorHistory` for the failed selector.
2. A known-good alternate in `selector_strategy` is preferred over the LLM proposal (when present + not already healed).
3. A successfully proposed heal is recorded in `selector_strategy` with `isHealed: 1`.
4. The 5-strategy fallback still runs when no provenance/known-good path applies.
5. Healing succeeds within 2 cycles on a simulated UI redesign (acceptance: provenance shortcut).
6. `bun run devops gate` passes.
