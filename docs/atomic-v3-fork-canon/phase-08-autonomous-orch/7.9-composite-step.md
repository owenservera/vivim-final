## Context

A plan step may be a **composite** capability (e.g. `composite:extract_and_summarize`) rather than a leaf capability. When the orchestrator hits such a step, it resolves the composite via `CapabilityComposer` and records the composite's internal nodes as **sub-steps** in the task tree — so the user sees the full breakdown and provenance.

## Existing Baseline

- `docs/atomic-v3/phase-02-agentic-core/2.4-composer-dag.md` — `CapabilityComposer` with `resolveComposite(slug): CapabilityDAG` returning the internal node list.
- `src/engines/autonomous-execution.ts:42` — `AutonomousStep` (we add an optional `parentStepId` + `isCompositeRoot`).
- `src/engines/autonomous-execution.ts:105` — step loop; we branch when `action` starts with `composite:`.
- `docs/atomic-v3/phase-02-agentic-core/2.14-provenance-graph.md` — sub-steps link to their composite root via `ProvenanceGraph`.

## Interface

### Change in `src/engines/autonomous-execution.ts`

```typescript
import { CapabilityComposer } from './capability-composer.js'

export interface AutonomousStep {
  // ...existing fields...
  parentStepId: string | null   // NEW: set for composite sub-steps
  isCompositeRoot: boolean        // NEW
}

export class AutonomousExecutionEngine {
  private async runStep(step: AutonomousStep, task: AutonomousTask): Promise<void> {
    if (step.action.startsWith('composite:')) {
      const slug = step.action.slice('composite:'.length)
      const inner = await this.composer.resolveComposite(slug) // CapabilityDAG
      let prev: string | null = null
      for (const node of inner.nodes) {
        const sub: AutonomousStep = this.toStep(task.goal, node, task.steps.length)
        sub.parentStepId = step.id
        sub.status = 'running'
        await this.runStep(sub, task)               // recurse on each inner node
        this.provenance.recordEdge(sub.id, prev ?? step.id, 'sub-step', {})
        prev = sub.id
      }
      step.isCompositeRoot = true
      step.status = 'completed'
      return
    }
    await this.executeStepWithHealing(step, task)
  }
}
```

## Acceptance Criteria

1. A step whose `action` starts with `composite:` resolves its inner nodes via `CapabilityComposer.resolveComposite`.
2. Each inner node is executed as a sub-step with `parentStepId` set to the composite root.
3. Sub-steps are linked to the composite root in `ProvenanceGraph` (`sub-step` edges).
4. After all inner nodes complete, the composite root is marked `completed`.
5. A composite containing a failing inner node fails the whole composite (no silent skip).
6. `bun run devops gate` passes.
