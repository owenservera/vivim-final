# Unit 5.8 — Provider consent + local-first enforcement

**Source:** v3 Overview §1.10; `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.8
**Design Doc:** `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.8
**Depends on:** 5.1
**Produces:** `provider_consent` table (consent policy consulted by the `TelemetryAuditInterceptor`, owned by 8.4).

---

## Context

Every cloud provider requires explicit user consent before first use, recorded in `provider_consent`. Bun's global `fetch` is monkey-patched by `TelemetryAuditInterceptor` to (a) check consent for the target host, (b) log the call to `TelemetryAudit`, and (c) throw a local `403` for any unconsented host. This is the local-first enforcement backbone: after a fresh install, zero outbound calls reach non-consented hosts (acceptance).

## Existing Baseline

- `src/engines/airgap.ts` — `AirGapEngine` already gates network; consent is the finer-grained per-provider allow-list on top.
- `src/engines/provider-registrar.ts` — `ProviderConfigRow` carries `authType`; consent state lives in the new `provider_consent` table keyed by `providerId` + `accountId`.
- `src/engines/unified-registry.ts` (1.3) — capability `execute` is the call site the interceptor wraps (so every outbound capability call is audited).
- Phase 9 (future) adds the broader `TelemetryAudit` store; this unit defines the interceptor + consent table and writes audit rows via a `TelemetryAuditStore` contract.

## Interface

### New migration: `prisma/schema.prisma`

```prisma
model ProviderConsent {
  id         String   @id
  providerId String
  accountId  String
  consented  Boolean  @default(false)
  consentedAt DateTime?
  grantedBy  String?  // 'user' | 'system' | 'default-deny'
  @@unique([providerId, accountId])
}
```

### New file: `src/engines/telemetry-audit-interceptor.ts`

```typescript
import type { TelemetryAuditStore } from '../storage/contracts/telemetry-audit.js'
import type { ProviderConsentStore } from '../storage/contracts/provider-consent.js'

export class TelemetryAuditInterceptor {
  private originalFetch: typeof fetch
  constructor(
    private consentStore: ProviderConsentStore,
    private auditStore: TelemetryAuditStore,
  ) {
    this.originalFetch = globalThis.fetch.bind(globalThis)
  }

  install(): void {
    const self = this
    globalThis.fetch = async (input: RequestInfo | URL, init?: RequestInit) => {
      const url = typeof input === 'string' ? input : input.toString()
      const host = new URL(url).host
      const providerId = self.resolveProvider(host) // map host -> providerId
      const consent = await self.consentStore.get(providerId, 'default')
      if (!consent?.consented) {
        await self.auditStore.record({ host, allowed: false, reason: 'no-consent' })
        throw new EngineError(`403: outbound call to ${host} blocked — provider ${providerId} not consented`)
      }
      const started = Date.now()
      const res = await self.originalFetch(input, init)
      await self.auditStore.record({ host, allowed: true, durationMs: Date.now() - started })
      return res
    }
  }

  private resolveProvider(host: string): string {
    // host allow-list -> providerId (seeded from manifests)
    return host // simplified: manifests declare hosts
  }
}
```

## Acceptance Criteria

1. `TelemetryAuditInterceptor.install()` replaces `globalThis.fetch` and audits every call.
2. A call to a host whose provider has no consent row → throws `403` locally, audit row `allowed:false`.
3. A consented provider's call proceeds and writes an `allowed:true` audit row.
4. After fresh install (no consent rows), any cloud-provider call is blocked → `TelemetryAudit` shows zero outbound to non-consented hosts (acceptance).
5. `bun run devops gate` passes.
