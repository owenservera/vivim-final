# Unit 5.7 — MCP server exposure (vivim-as-MCP-server)

**Source:** v3 Overview §1.3; `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.7
**Design Doc:** `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.7
**Depends on:** 1.3
**Produces:** `McpServerAdapter` (existing) wired with the full capability catalog.

---

## Context

Besides *consuming* MCP tools (5.6), vivim should *expose* its own capabilities as MCP tools so external agents (Claude Code, Cursor, etc.) can drive it. `McpServerAdapter` already exists; this unit wires it with the full `UnifiedCapabilityRegistry`: every entry whose `surfaces` includes `'mcp'` is exposed. Endpoint `ws://localhost:9421`.

## Existing Baseline

- `src/engines/mcp-server-adapter.ts` — `McpServerAdapter` already takes `governor` + optional `registry`, has `registerTools()` for base Chrome tools, serves on `Bun.serve`. We extend `registerTools()` to pull from the registry.
- `src/engines/unified-registry.ts` (1.3) — `exportForMcp()` returns `{ name, description, inputSchema }` per mcp-surface capability.
- `src/server/index.ts` — constructs the adapter; pass the registry in (currently optional).
- `3.13` already registers canvas caps with `mcpToolName`; those flow through automatically.

## Interface

### Extension in `src/engines/mcp-server-adapter.ts`

```typescript
import type { UnifiedCapabilityRegistry } from './unified-registry.js'

// inside McpServerAdapter:
private registerTools(): void {
  // existing base Chrome tools ...
  if (this.registry) {
    for (const cap of this.registry.exportForMcp()) {
      this.tools.push({
        name: cap.name,
        description: cap.description,
        inputSchema: cap.inputSchema,
      })
    }
  }
}

// Tool dispatch (added):
private async dispatchTool(name: string, args: Record<string, unknown>) {
  const cap = this.registry?.getBySlug(name) ?? this.registry?.get(name) ?? null
  if (!cap) throw new EngineError(`Unknown MCP tool: ${name}`)
  return this.registry!.execute(cap.id, args, { metadata: {} })
}
```

### Wiring in `src/server/index.ts`

```typescript
const mcpAdapter = new McpServerAdapter(governor, registry) // pass registry
mcpAdapter.start({ port: 9421 }) // ws://localhost:9421
```

## Acceptance Criteria

1. `McpServerAdapter` exposes every `registry` capability with `surface: 'mcp'`.
2. Dispatching a tool name routes to `registry.execute(cap.id, args, ctx)`.
3. Canvas caps (3.13, e.g. `canvas_spawn`) are reachable as MCP tools.
4. Unknown tool name → throws `EngineError`.
5. Adapter serves on `ws://localhost:9421`.
6. `bun run devops gate` passes.

## Tests
