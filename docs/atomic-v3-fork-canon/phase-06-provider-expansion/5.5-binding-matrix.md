# Unit 5.5 — Capability-binding matrix per provider

**Source:** v3 Overview §1.2; `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.5
**Design Doc:** `docs/master-plan-v3/PHASE-05-provider-expansion.md` §5.5
**Depends on:** 5.4
**Produces:** Every provider declares which capabilities it supports + selectors.

---

## Context

For each provider × capability, a `provider_capability` row declares: selector strategies (how to target the control on that provider's site), recovery strategies (what to do when a selector drifts), and UI overrides (provider-specific labels). Most browser providers share selectors; the matrix documents the differences. Each binding is exercised by the harness (5.10).

## Existing Baseline

- `src/engines/provider-registrar.ts` — writes `ProviderCapabilityRow` (referenced in its imports: `ProviderCapabilityRow` from `../schema/types.js`). This unit populates that table.
- `src/schema/provider-manifest.ts` — `capabilities: [...]` in manifests becomes the supported set; 5.5 adds the per-cap detail (`selectors`, `recovery`, `uiOverrides`).
- `src/engines/capability-shape-registry.ts` — `overrides` (line 47) is the natural carrier for per-provider UI overrides.
- `seeds/providers/{chatgpt,claude,gemini,deepseek,qwen,studio-ai,z-ai,system}.json` — existing manifests the matrix attaches to.

## Interface

### New migration: `prisma/schema.prisma` (extend or add)

```prisma
model ProviderCapability {
  id            String   @id
  providerId   String
  capabilitySlug String
  selectors     String   // JSON: { control: string; value?: string }
  recovery      String   // JSON: { strategy: 'retry'|'reselect'|'fallback'; maxAttempts: number }
  uiOverrides  String   // JSON: { label?: string; placeholder?: string }
  supported     Boolean  @default(true)
  @@unique([providerId, capabilitySlug])
  @@index([providerId])
}
```

### Seed builder: `seeds/providers/binding-matrix.ts`

```typescript
import { writeFileSync } from 'node:fs'
import { CAPABILITY_TAXONOMY_V2 } from '../../src/engines/capability-taxonomy.js'

// Shared selectors for browser providers; per-provider diffs applied below.
const SHARED_SELECTORS: Record<string, object> = {
  send_message: { control: 'textarea[ data-cap-bind="draft"]' },
  select_model: { control: '[data-cap-bind="model-switcher"]' },
  // ...
}

const PER_PROVIDER_DIFF: Record<string, Record<string, Partial<object>>> = {
  'chatgpt': { toggle_web_search: { control: '[data-testid="web-search-toggle"]' } },
  'claude':  { toggle_web_search: { control: '[data-cap-bind="web-search"]' } },
  // ... diffs per provider ...
}

export function buildBindingMatrix(): ProviderCapabilityRow[] {
  const rows: ProviderCapabilityRow[] = []
  for (const providerId of ['chatgpt', 'claude', 'gemini', 'deepseek', 'qwen', 'studio-ai', 'z-ai']) {
    for (const cap of CAPABILITY_TAXONOMY_V2) {
      const base = SHARED_SELECTORS[cap.slug]
      const diff = PER_PROVIDER_DIFF[providerId]?.[cap.slug]
      rows.push({
        id: newId(), providerId, capabilitySlug: cap.slug,
        selectors: JSON.stringify({ ...base, ...diff }),
        recovery: JSON.stringify({ strategy: 'reselect', maxAttempts: 3 }),
        uiOverrides: JSON.stringify({}), supported: !!base || !!diff,
      })
    }
  }
  return rows
}
```

## Acceptance Criteria

1. A `provider_capability` row exists for every `providerId × capabilitySlug` pair in scope.
2. `selectors` is valid JSON; shared selectors are reused, per-provider diffs override.
3. `recovery` declares a strategy + `maxAttempts`.
4. Unsupported pairs are flagged `supported: false` rather than omitted.
5. Each binding is addressable by the harness (5.10) for a smoke test.
6. `bun run devops gate` passes.

## Tests

`tests/integration/seeds/binding-matrix.test.ts`:
- matrix covers all providers × all v2 capabilities.
- every `selectors`/`recovery` parses as JSON.
- a known diff (e.g. `chatgpt` vs `claude` `toggle_web_search`) differs as declared.
