# DB E2E Audit — 2026-08-08

Scope: end-to-end audit of the vivim-final database layer — schema, migrations,
DDL application model, seed pipeline, and live-DB consistency (`prisma/dev.db`).
Trust only code. Assumption stated up front: devops scripts and docs (including
skills) are stale until read; every claim below was verified against actual
source and the live SQLite file.

---

## 1. Verdict (TL;DR)

| Dimension | Status |
|---|---|
| Schema ↔ migrations ↔ live DB | ✅ Zero drift (`prisma migrate diff` → empty) |
| DDL application model | ✅ `prisma db push`, no `_prisma_migrations` — by design (guard.ts) |
| Live DB seeded state | ✅ Providers/parsers/stream-configs/harness seeded |
| Seed source ↔ live DB consistency | ⚠️ **Taxonomy version skew** (348 live vs 3548 pool) |
| Test hygiene | ⚠️ e2e test writes rows to live DB, never cleans up |
| Dead code / orphan files | ⚠️ Several (applyMigration, migration_log, views*.sql, seed.sql) |

The system is **operationally sound** — schema and seed pipeline work — but has
**stale-data and dead-code debt** worth flagging before alpha.

## 3. CLI migrate/seed Commands — Thin Wrappers

- `bun run migrate` → `src/cli/commands/migrate.ts` → calls `createServerWithEngines(port)`.
- `bun run seed` → `src/cli/commands/seed.ts` → calls `createServerWithEngines(port)`.
- **Neither runs Prisma migrations.** They boot the server, which triggers the boot
  seed phase. DDL sync happens externally via `prisma db push` (see §5).
- `bun run devops db ...` does **not exist** — the devops CLI rejects unknown
  subcommands (`db` is not in its usage list).

---

## 4. Seed Pipeline (actual, verified)

Boot → `src/server/bootstrap/phases/seeds.ts` (`bootstrapSeedsPhase`):

1. `needsSeed = (providerDefinition.count() === 0)` unless `FORCE_SEED`.
2. If needsSeed and no snapshot: `runIndividualSeeds` (`src/server/bootstrap-seeds.ts`):
   - `registrar.seedAll()` → provider_definition + provider_config + provider_endpoint
     + provider_model + provider_capability
   - `seedHarvestedParsers` / `seedStreamConfigs` (harvest.seed.ts)
   - `seedAutomation` (automation.seed.ts)
   - `ensureTaxonomySeeded` (taxonomy-seed.ts)
   - `seedHarnessCommands` (harness/commands.seed.ts)
3. Snapshot path: `seeds/seed-snapshot.db` copied over dbPath **if it exists**.
   **It does not exist** (script `scripts/seed-snapshot.ts` exists, snapshot never
   generated) → falls back to individual seeds.
4. **Sticky gate:** if DB already has providers, boot skips all seeding entirely
   (needsSeed=false). This is the root cause of the taxonomy skew in §7.

Note: `automation_schedule` and `config_entry` tables are EMPTY. The automation
seed writes `agent_loop_run` + `agent_step` (5 rows each in live DB), not
`automation_schedule`/`config_entry` — so those two tables have seed files in the
repo but zero live rows.

## 7. ⚠️ Taxonomy Version Skew (most significant finding)

- `seeds/taxonomy/pool.taxonomy.json` (generated 2026-07-19): **3,921 nodes**,
  **3,548 capability** nodes (3,352 `oc_*` + 196 legacy).
- Live `capability_taxonomy`: **348 rows** = 291 non-CDP + 57 CDP.
- All 291 non-CDP live rows match slugs present in the current pool (95 oc_*, 196
  legacy) — so the live DB was seeded from an **older, smaller pool** and the pool
  was expanded afterward.
- **57 CDP rows** (`cap-cdp-*`, category `cdp`) are **not in the pool** (pool has
  only 4 cdp-containing slugs). Provenance: boot-time CDP registration via
  `src/server/bootstrap/phases/capabilities.ts` `ensureCdpBinding` (upserts into
  capabilityTaxonomy + capabilityBinding) — the `cap:cdp:*` UnifiedCapabilities
  registered by `cdp-capability-registrar.ts` are persisted here. Only 4 of those
  are in the pool; 57 live rows came from live protocol discovery.
- **Root cause of skew:** `ensureTaxonomySeeded` is sticky (skips when
  `existing > 0 && !force`), AND the outer boot gate skips seeding entirely when
  providers exist. So a populated DB never converges to the newer 3,548-node pool.
- **Fix:** re-run with force once (backup first):
  `FORCE_SEED=1` or call `ensureTaxonomySeeded(prisma, true)`.

## 8. ⚠️ Test Pollution (live DB)

`tests/e2e/harness-command-registry.test.ts` writes `e2e.nav` v1.9.0
(`description="old"`) and v1.10.0 (`description="new"`) rows into the **live**
`harness_command` table with `created_at: 0` and never cleans up. Both rows remain
in dev.db (2 of the 11 harness_command rows). The test should use a fixture DB or
clean up after itself.

## 10. Recommended Actions (priority order)

1. **Converge taxonomy:** run `ensureTaxonomySeeded(prisma, true)` once (backup
   `prisma/dev.db` first) so live DB matches the 3,548-node pool. Consider making
   boot seed idempotent-upsert capability nodes even when providers exist.
2. **Fix e2e test hygiene:** point `harness-command-registry.test.ts` at a fixture
   DB or add cleanup; delete the two `e2e.nav` residue rows from dev.db.
3. **Decommission dead migration scaffolding** OR wire it in: `applyMigration`,
   `hasMigration`, empty `MIGRATIONS`, `migration_log` (all currently inert).
4. **Remove or resurrect `ensureViews`** — delete `prisma/views*.sql` and
   `prisma/seed.sql`/`seed.ts`, or implement the referenced boot function.
5. **Generate the snapshot** (`bun run seed:snapshot`) so fresh clones get the
   fast restore path, or delete the dead branch in `seeds.ts`.
6. Update AGENTS.md provider matrix (deepseek now has a parser; 16 providers not 6;
   harness command list) and remove stale `docs/audits/` references.
