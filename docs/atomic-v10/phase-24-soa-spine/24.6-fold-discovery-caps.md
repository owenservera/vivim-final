# Unit 24.6: Fold Discovery Commands into Capabilities

**Phase:** 24 | **Files:** `src/engines/capability-bootstrap.ts`, delete `src/cli/commands/discovery.ts`
**Depends:** 24.1, 24.3 | **Class:** PORT

## Purpose
`discovery run/interact/align/list/show/manifest` currently instantiate
`buildLocalDiscoveryStack()` in-process (CLI-only, no server). Make them
server-side capabilities so the frontend can drive discovery too.

## Capabilities
| Subcommand | → Capability id | input |
|------------|-----------------|-------|
| run | `discovery_run` | `{providerId, accountId?, url, profileDir?, probeMessage?, composerSelector?, composerType?, sendSelector?, timeoutMs?}` |
| interact | `discovery_interact` | `{providerId, accountId?, url?, message, composer?, send?, timeoutMs?}` |
| align | `discovery_align` | `{providerId, bodies: string[], format?}` |
| list | `discovery_list` | `{limit?}` |
| show | `discovery_show` | `{sessionId}` |
| manifest | `discovery_manifest` | `{sessionId}` |

## Implementation
- Register `registerDiscoveryCapabilities(registry, services)` in `createServerWithEngines`. The `buildLocalDiscoveryStack()` builder becomes a shared helper the handler calls (server-side now).
- `discovery_run` handler = `runSession()` body from `discovery.ts:70`.
- `discovery_interact` = `interact()` body (`discovery.ts:124`).
- `surfaces: ['cli','ui','api']` for run/interact/list/show/manifest; `['cli','api']` for align (developer tool).
- Delete `cli/commands/discovery.ts`; the CLI autogen (24.8) reproduces the subcommands from `cliCommand.aliases`.

## Tests
- `POST /api/capabilities/discovery_list/execute {limit:50}` returns sessions.
- Frontend Discovery tab (Phase 27/30) calls `discovery_run` and gets `{sessionId, detectedCapabilities, alignment}`.
