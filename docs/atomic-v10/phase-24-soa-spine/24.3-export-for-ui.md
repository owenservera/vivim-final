# Unit 24.3: exportForUi + ui block on UnifiedCapability

**Phase:** 24 | **File:** `src/engines/unified-registry.ts`, `src/engines/capability-bootstrap.ts`
**Depends:** — | **Class:** EXTEND

## Purpose
The registry already exports for CLI and MCP but not UI. The frontend needs a
typed surface export so `ActionRegistry` can auto-populate (24.9). Also promote
`uiAction` to a full block matching the 21-field UI contract.

## Interface
```ts
// unified-registry.ts
export interface UnifiedCapability {
  ...
  ui?: {
    component: string          // 'action-button' | 'composer' | 'canvas-layer' | ...
    position: string           // 'sidebar' | 'composer' | 'canvas' | 'admin' | ...
    group?: string
    order: number
    icon?: string
    shortcut?: string          // e.g. 'ctrl+k'
    requiresConfirmation?: boolean
  }
  cliCommand?: { name; aliases: string[]; examples: string[] }  // aliases added
  ...
}

exportForUi(): Array<{ id, slug, name, ui, inputSchema, apiEndpoint, requiresConfirmation }>
```

## Implementation
- Extend `UnifiedCapability` interface with `ui?` block + `aliases` on `cliCommand`.
- Add `exportForUi()` mirroring `exportForCli()`/`exportForMcp()` (`unified-registry.ts:129-147`).
- Update `validateCapability` to require `ui` block when `surfaces.includes('ui')`.
- Update `capability-bootstrap.ts` default caps to add `aliases` + richer `ui` blocks (e.g. `conversation_send` gets `shortcut: 'enter'`, `ui.component: 'composer'`).
- `exportForCli()` now emits `aliases`.

## Tests
- `registry.exportForUi().length` equals `registry.list({surface:'ui'}).length`.
- A capability with `surfaces:['ui']` but no `ui` block throws on register.

## Gate
- typecheck + `tests/unit/engines/unified-registry.test.ts` extended.
