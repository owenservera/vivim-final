# Unit 24.9: Frontend ActionRegistry Auto-Population

**Phase:** 24 | **Files:** `web/ui/src/actions/catalog.ts` (delete), `web/ui/src/actions/registry.ts`, new `web/ui/src/actions/auto-populate.ts`
**Depends:** 24.2, 24.3 | **Class:** CREATE

## Purpose
`web/ui/src/actions/catalog.ts` is 276 lines of hand-written `ActionRegistry.register` calls that duplicate the unified registry. Replace with runtime fetch + auto-register so the frontend action set is always in sync with the server.

## Interface
```ts
// web/ui/src/actions/auto-populate.ts
export async function autoPopulateActions(apiBase = '/api'): Promise<void> {
  const res = await fetch(`${apiBase}/capabilities?surface=ui`)
  const caps = await res.json()
  for (const cap of caps) {
    ActionRegistry.register(cap.slug, {
      description: cap.description,
      params: jsonSchemaToZod(cap.inputSchema),
      run: async (params) => {
        const r = await fetch(`${apiBase}/capabilities/${cap.id}/execute`, {
          method:'POST', headers:{'Content-Type':'application/json'},
          body: JSON.stringify({ input: params })
        })
        return r.json()
      },
    })
  }
}
```

## Implementation
- New `auto-populate.ts` with `jsonSchemaToZod` (port from `registry-bridge.ts:36`).
- Call `autoPopulateActions()` in `web/sandbox/src/main.tsx` before render (and in `web/ui/src/index.ts` for prod consumers).
- `ActionRegistry.register` must tolerate re-registration (idempotent) — relax the "already registered" throw to upsert.
- Delete `web/ui/src/actions/catalog.ts`.
- `AgentBridge` (agent-bridge.ts) dispatch already routes through `ActionRegistry` — now it hits the universal route transparently.
