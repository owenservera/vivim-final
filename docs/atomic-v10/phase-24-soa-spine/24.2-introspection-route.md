# Unit 24.2: Introspection Route

**Phase:** 24 | **File:** `src/server/capability-router.ts`
**Depends:** 24.1 | **Class:** CREATE

## Purpose
Let CLI and frontend discover the full operation set at runtime. The frontend
action catalog and CLI help both become server-driven, not compiled.

## Interface
```
GET /api/capabilities                       → all
GET /api/capabilities?surface=ui            → only ui-surfaced
GET /api/capabilities?surface=cli           → only cli-surfaced
GET /api/capabilities?category=conversation → filtered
GET /api/capabilities?tag=core              → filtered
GET /api/capabilities/:id                   → single capability detail
```

Response shape per capability:
```json
{ "id","slug","name","description","category","surfaces":[],
  "inputSchema":{...}, "outputSchema":{...},
  "cliCommand":{"name","aliases","examples"},
  "uiAction":{"component","position","order","icon","shortcut"},
  "apiEndpoint":{"method","path"}, "mcpToolName":"...",
  "requiresConfirmation":bool }
```

## Implementation
- Add GET handlers in `capability-router.ts` delegating to `ctx.registry.list(filter)` and `ctx.registry.get(id)`.
- Surface filter reuses existing `UnifiedCapabilityRegistry.list({surface})`.

## Tests
- `GET /api/capabilities?surface=ui` returns ≥24 (default caps).
- `GET /api/capabilities/provider_list` returns the single detail.
- Unknown id → 404.
