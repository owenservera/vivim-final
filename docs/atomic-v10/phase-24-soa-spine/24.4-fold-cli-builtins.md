# Unit 24.4: Fold CLI Built-in Commands into Capabilities

**Phase:** 24 | **Files:** `src/engines/capability-bootstrap.ts`, delete `src/cli/commands/{version,health,system,fleet,providers,config,conversations,admin,telemetry}.ts`
**Depends:** 24.1, 24.3 | **Class:** PORT

## Purpose
The 9 hand-written CLI command modules each construct a `CapStoreBridge` and hit
hardcoded paths (mostly broken — missing `/api` prefix). Their logic is identical
to what the server routes do. Fold them into capability registrations so there is
ONE definition; the CLI auto-generates from the registry (24.8).

## Capabilities to register (extend `registerDefaultCapabilities`)
Each replaces a command file. Handler closes over `services` (db, governor, conversationManager, etc.) and does the same DB/engine call the server route does.

| Command file | → Capability id | surfaces |
|--------------|-----------------|----------|
| version.ts | `system_version` (exists — wire real handler) | cli,ui,api |
| health.ts | `provider_health_get` | cli,ui,api |
| system.ts | `system_serve` | cli,api |
| fleet.ts | `fleet_status`/`fleet_start`/`fleet_stop` (exist — wire real) | cli,ui,api |
| providers.ts | `provider_list`/`provider_get` (exist — wire real) | cli,ui,api |
| config.ts | `config_get`/`config_set`/`config_history` | cli,ui,api |
| conversations.ts | `conversation_list`/`create`/`send` (exist — wire real) | cli,ui,api |
| admin.ts | `admin_seed`/`admin_audit`/`admin_drift` | cli,api |
| telemetry.ts | `telemetry_summary`/`telemetry_compare` | cli,ui,api |

## Implementation
- In `capability-bootstrap.ts`, replace stub handlers (`async () => []`) with real closures over `services.db`, `services.governor`, `services.conversationManager`, etc.
- Add the missing capabilities (`provider_health_get`, `config_history`, `admin_audit`, `admin_drift`, `telemetry_summary`, `telemetry_compare`).
- Add `cliCommand.aliases` matching the old CLI subcommands so `vivim providers list` still resolves.
- Delete the 9 command files (their logic now lives in capability handlers).
- Keep `discovery.ts`, `kernel.ts`, `nlcl.ts` for 24.5-24.7.

## Tests
- `POST /api/capabilities/provider_list/execute` returns same as `GET /api/providers`.
- `POST /api/capabilities/telemetry_summary/execute {providerId, from, to}` returns summary.
- `vivim providers list` (via 24.8 autogen) returns identical structured output.
