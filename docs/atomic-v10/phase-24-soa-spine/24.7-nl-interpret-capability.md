# Unit 24.7: nl_interpret Meta-Capability

**Phase:** 24 | **Files:** `src/engines/capability-bootstrap.ts`
**Depends:** 24.1, 25.1 | **Class:** CREATE

## Purpose
NLCL itself is a capability. `POST /api/interpret` (25.7) and the universal
execute route both delegate to it. This makes NL parsing composable: a workflow
node or an MCP tool can invoke `nl_interpret { text }` to resolve arbitrary NL
to a capability chain. It also makes the system self-referential — you can ask
the system (via NL) to interpret NL.

## Interface
```ts
{
  id: 'cap:nlcl:interpret',
  slug: 'nl_interpret',
  surfaces: ['cli','ui','api','mcp','workflow'],
  inputSchema: {
    type:'object',
    properties: {
      text: { type:'string' },
      ctx: { type:'object' }   // conversationId, providerId, canvasState, ...
    },
    required: ['text']
  },
  outputSchema: { type:'object' },  // CommandResult { capabilityId, input, ... }
  handler: async (input, ctx) => nlclEngine.interpret(input.text, { ...ctx, ...input.ctx })
}
```

## Implementation
- Register in `registerDefaultCapabilities`. Handler closes over `services.nlclEngine` (add to `BootstrapServices`).
- `apiEndpoint: { method:'POST', path:'/api/interpret' }` — the dedicated route (25.7) is sugar over `/api/capabilities/nl_interpret/execute`.

## Tests
- `POST /api/capabilities/nl_interpret/execute {text:'list providers'}` returns `{ok, capabilityId:'provider_list', ...}`.
- Recursive: `{text:'interpret "ask claude about x"'}` resolves to `nl_interpret` again (no infinite loop — depth cap in NLCL).
