# Unit 24.1: Universal Execute Route

**Phase:** 24 | **File:** `src/server/capability-router.ts` (new) + `src/server/index.ts`
**Depends:** atomic-v9 Phase 23 (registry autobridge) | **Class:** CREATE | **Source:** SOA-ARCHITECTURE §1

## Purpose
The single execution transport. Every capability invocation — from CLI, frontend,
MCP, or workflow — crosses `POST /api/capabilities/:id/execute`. Kills the
"HTTP-bridge vs in-process" split and the broken per-command paths.

## Interface
```
POST /api/capabilities/:id/execute
  body: { input: Record<string, unknown>, ctx?: { conversationId?, providerId?, ... } }
  → 200 { ok, capabilityId, output, traceId, latencyMs }
  → 404 capability not found
  → 400 input failed inputSchema validation

POST /api/capabilities/:slug/execute   (slug alias — same handler)
```

## Implementation
- New `createCapabilityRouter(ctx)` in `src/server/capability-router.ts`.
- Resolves `:id` via `ctx.registry.get(id) ?? ctx.registry.getBySlug(id)`.
- Validates `body.input` against `cap.inputSchema.required` (extend to full Zod in 24.3).
- Calls `ctx.registry.execute(id, input, ctxFromRequest)`.
- Builds `CapabilityContext` from request (`conversationId`, `providerId` from body.ctx; `metadata` from auth/headers).
- Emits `capability:executed` on eventBus; records trace.
- Mount in `server/index.ts` `createServerWithEngines` before the conversation catch-all: `if (url.pathname.startsWith('/api/capabilities/')) return capabilityRouter(req)`.
- Auth-gated (reuse `createAuthMiddleware`).

## Tests
- `POST /api/capabilities/provider_list/execute {}` returns provider array identical to `GET /api/providers`.
- Unknown id → 404. Missing required input → 400. Slug and id resolve same handler.
