# Unit 24.5: Fold Kernel/Oracle Commands into Capabilities

**Phase:** 24 | **Files:** `src/engines/capability-bootstrap.ts`, delete `src/cli/commands/kernel.ts`
**Depends:** 24.1, 24.3 | **Class:** PORT

## Purpose
The 11 kernel/oracle CLI commands (`kernel oracle query|heal|scan|events|visibility|manifest|policy|explain`, `kernel config list|get|set|snapshot|rollback`) currently register with `{ kernel: null }` → every one returns "not available" (`cli/commands/kernel.ts:43,68,85`). They only work server-side. Make them real capabilities with handlers closing over `kernel` from `ServerContext`.

## Capabilities to register
| Command | → Capability id | input |
|---------|-----------------|-------|
| oracle query | `oracle_query` | `{op, filter?, limit?}` |
| oracle heal | `oracle_heal` | `{issueId}` |
| oracle scan | `oracle_scan` | `{}` |
| oracle events | `oracle_events` | `{tail?}` |
| oracle visibility | `oracle_visibility` | `{}` |
| oracle manifest | `oracle_manifest` | `{}` |
| oracle policy get/set | `oracle_policy_get`/`oracle_policy_set` | `{key?}`/`{policy}` |
| oracle explain | `oracle_explain` | `{target}` |
| config list/get/set/snapshot/rollback | `kernel_config_*` | per existing CLI |

## Implementation
- Register in a new `registerKernelCapabilities(registry, services)` called from `createServerWithEngines` after `bootstrapKernel` (`server/index.ts:604`), where `kernel` is non-null.
- Handlers: `kernel.context().oracle.query.query(...)`, `.actuator.heal(...)`, `.diagnostic.scan()`, etc. — exact calls the CLI file already makes.
- `surfaces: ['cli','ui','api']` for query/scan/events/visibility/manifest; `['cli','api']` for heal/policy (destructive).
- Delete `cli/commands/kernel.ts`.

## Tests
- `POST /api/capabilities/oracle_query/execute {op:'health'}` returns aggregate score.
- `POST /api/capabilities/oracle_scan/execute {}` returns DiagnosticIssue[].
- `vivim kernel oracle query --op health` (24.8) returns identical structured output.
