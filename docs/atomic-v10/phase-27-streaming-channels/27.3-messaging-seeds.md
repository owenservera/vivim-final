# Unit 27.3: Messaging Provider Manifest Seeds

**Phase:** 27 | **Files:** `seeds/providers/whatsapp.json`, `facebook.json`, `telegram.json`, `slack.json`, `dispatch.json`
**Depends:** 27.2 | **Class:** CREATE

## Purpose
Seed the messaging providers so they appear in `provider_list` and can be targeted by
`channel_add`. Reuses the existing `ProviderRegistrar` + `seeds/providers/*.json`
mechanism that already seeds AI providers (chatgpt/claude/gemini).

## Interface
```jsonc
// seeds/providers/whatsapp.json
{
  "providerId": "whatsapp",
  "name": "WhatsApp",
  "kind": "messaging",
  "loginUrl": "https://web.whatsapp.com/",
  "pollStrategy": "cdp-scrape",
  "capabilities": [/* message_send, message_receive */],
  "auth": { "type": "qr" | "oauth" }
}
```

## Implementation
- Add the five `*.json` seeds, each with `kind: 'messaging'`, `loginUrl`,
  `pollStrategy` (matching 27.2), and a minimal `capabilities` list.
- Ensure `admin seed` (`cap:admin:seed`) ingests `kind: 'messaging'` providers into the
  same `providers` table; `provider_list` filters them by `kind` so the UI can show a
  "Channels" section separately from AI providers.
- `ProviderRegistrar` already handles arbitrary manifests; only the seed files are new.

## Tests
- After `admin seed`, `provider_list` (filtered `kind=messaging`) returns ≥5 channels.
- A malformed seed JSON fails the seed command with a clear error (no partial insert).

## Gate
- typecheck + seed smoke test.
