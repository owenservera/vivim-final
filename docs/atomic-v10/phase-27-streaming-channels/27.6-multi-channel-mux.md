# Unit 27.6: Multi-Channel Stream Mux

**Phase:** 27 | **Files:** `src/engines/provider-mux.ts` (extend)
**Depends:** 27.1, 27.2 | **Class:** EXTEND

## Purpose
Subscribe many connected channels into **one** conversation so messages from WhatsApp,
Facebook, etc. flow into a single thread (Scenario 1b tail). `ProviderMuxEngine`
already exists; extend it to accept channel subscriptions and normalize+route inbound
messages to a target conversation.

## Interface
```ts
// on ProviderMuxEngine
async subscribeChannel(channelId: string, targetConversationId: string): Promise<void>
async unsubscribeChannel(channelId: string): Promise<void>

// eventBus events
//  channel:message  { channelId, conversationId, message: NormalizedMessage }
```

## Implementation
- Extend `ProviderMuxEngine` with `subscribeChannel` / `unsubscribeChannel`.
- For `cdp-scrape` archetypes (WhatsApp/Facebook), attach a scrape loop on the channel's
  slave (via `governor`) that calls the archetype `normalize` and emits `channel:message`.
- For `webhook`/`polling` archetypes (Telegram/Slack), register the inbound handler.
- `channel:message` is consumed by the conversation router → appended to the target
  conversation (reuse `ConversationManager.appendMessage`).
- `channel_connect` (27.5) auto-subscribes to the channel's default conversation.

## Tests
- `subscribeChannel('wa1','conv1')` then a simulated inbound message emits
  `channel:message` with `conversationId: 'conv1'`; the conversation gains a message.
- `unsubscribeChannel` stops further emissions.
