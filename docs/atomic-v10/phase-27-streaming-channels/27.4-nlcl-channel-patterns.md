# Unit 27.4: NLCL Channel Patterns

**Phase:** 27 | **Files:** `src/engines/nlcl/catalog.ts`
**Depends:** 25.1, 27.1 | **Class:** CREATE

## Purpose
Map channel sentences to the capabilities from 27.1 (Scenario 1b). NL → `capabilityId`
→ universal execute. "add my whatsapp" becomes a composite `[channel_add, channel_connect]`.

## Interface
```ts
// catalog.ts additions
{ intent: 'channel.add', capabilityId: 'cap:channel:add',
  patterns: [/add (my |a )?(whatsapp|facebook|telegram|slack|.*?) (feed|channel|messaging)/i],
  extract: (m) => ({ providerId: m[2] }) }
{ intent: 'channel.connect', capabilityId: 'cap:channel:connect',
  patterns: [/connect (my )?(.+?) (feed|channel)/i], extract: (m) => ({ providerId: m[2] }) }
// + channel.remove, channel.list
```

## Implementation
- Extend `getDefaultCommandPatterns()` with the four channel patterns, each binding
  `capabilityId` (25.1) and `inputSchema`.
- "add my whatsapp **and** my facebook" is detected as a composite by the existing
  `detectComposite` (`nlcl-engine.ts:204`) → `[channel_add, channel_add]` DAG.
- `executor: 'capability'` so they route through `registry.execute` (universal transport).

## Tests
- `interpret('add my whatsapp')` → `cap:channel:add`, `input.providerId: 'whatsapp'`.
- `interpret('add my whatsapp and my facebook')` → composite with two `channel_add` steps.
