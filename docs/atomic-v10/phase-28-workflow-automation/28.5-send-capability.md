# Unit 28.5: Send Capability

**Phase:** 28 | **Files:** `src/engines/send-capability.ts` (new)
**Depends:** 24.1 | **Class:** CREATE

## Purpose
The terminal step of the newsletter (and any outbound automation): send an email or a
messaging-platform message. Provide `email_send` and `message_send` capabilities that
route through SMTP / the provider's send API, reachable from CLI, UI, and workflows.

## Interface
```ts
//  cap:email:send   { to: string[], subject: string, body: string, from? }
//  cap:message:send { channelId: string, to?: string, text: string }
```

## Implementation
- New `src/engines/send-capability.ts` exporting `registerSendCaps(registry, deps)`.
- `email_send`: SMTP send (config from `config.ts` / a new `SMTP_` env block); returns
  `{ sent: true, messageId }`. If no SMTP configured, returns a clarification prompting
  for credentials (25.6).
- `message_send`: routes via the channel mux (27.6) / provider's send API for the given
  `channelId`.
- Both `classify` as `communication` (not `financial` unless a paid send); `email_send`
  to external recipients is `requiresConfirmation: true` when `to` has >1 recipient or
  a non-whitelisted domain (guards accidental mass mail).

## Tests
- `email_send` with a mocked SMTP transport returns `{sent:true}`.
- `message_send {channelId}` routes to the mocked mux and emits the message.

## Gate
- typecheck + unit test with mocked transports.
