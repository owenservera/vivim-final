# Unit 28.3: Schedule-as-Capability

**Phase:** 28 | **Files:** `src/automation/scheduler.ts` (extend), `src/engines/capability-bootstrap.ts`
**Depends:** 24.1 | **Class:** PORT

## Purpose
Enable *"every Monday send..."* — turn a schedule into a capability that drives the
existing `AutomationScheduler`. The scheduler already has `define({scheduleType,
scheduleValue, action, actionConfigJson})` and `tick()`; expose it as a capability so
NL and the UI can register cron/interval jobs through the universal route.

## Interface
```ts
// registered capability:
//  cap:schedule:register  { cron: string, action: string, actionConfig?: object, name? }
//  cap:schedule:list      { }
//  cap:schedule:run_now   { scheduleId }
```
`cron` supports standard 5-field expressions; `action` references a capability id
(e.g. a newsletter workflow capability from 28.1/28.2).

## Implementation
- Extend `AutomationScheduler` (or add a thin wrapper) to register the three
  capabilities in `capability-bootstrap.ts` (`registerDefaultCapabilities`), closing
  over `this.store` + `this.runner`.
- `schedule_register` handler → `scheduler.define({ scheduleType:'cron',
  scheduleValue: cron, action, actionConfigJson: JSON.stringify(actionConfig), name })`.
- The scheduler's `tick` already fires due schedules; `action` is resolved to a
  capability and run via `registry.execute` (so scheduled work goes through the same
  transport).
- `parseCronNextMs` is currently a stub (`scheduler.ts:59`); replace with a real cron
  library so `nextRunAt` is accurate.

## Tests
- `cap:schedule:register {cron:'0 9 * * 1', action:'cap:workflow:newsletter_demo'}` creates
  a schedule; `cap:schedule:list` includes it with a valid `nextRunAt`.
- `tick()` at the due time invokes `registry.execute(action)`.
