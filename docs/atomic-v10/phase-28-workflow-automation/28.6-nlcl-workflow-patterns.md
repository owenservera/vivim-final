# Unit 28.6: NLCL Workflow Patterns

**Phase:** 28 | **Files:** `src/engines/nlcl/catalog.ts`
**Depends:** 25.1, 28.2, 28.3, 28.5 | **Class:** CREATE

## Purpose
Map automation sentences to the capabilities from 28.1-28.5 (Scenario 1c). NL →
`capabilityId` → universal execute.

## Interface
```ts
// catalog.ts additions
{ intent: 'workflow.newsletter', capabilityId: 'cap:workflow:create_newsletter',
  patterns: [/create (a |an )?(weekly |daily )?newsletter(.+)?/i],
  extract: (m, raw) => ({ recipients: extractEmails(raw), windowDays: /weekly/?7:/daily/?1:7 }) }
{ intent: 'schedule.register', capabilityId: 'cap:schedule:register',
  patterns: [/every (monday|tuesday|...|hour|day) (.+)/i],
  extract: (m) => ({ cron: toCron(m[1]), action: resolveAction(m[2]) }) }
// + 'automate ...', 'distill the week', 'send to team'
```

## Implementation
- Extend `getDefaultCommandPatterns()` with workflow/automation patterns, each binding
  `capabilityId` (25.1) and `inputSchema`.
- "every Monday send a newsletter to team@x.io" is a composite: `schedule_register`
  whose `action` resolves to a previously-created `cap:workflow:create_newsletter`
  capability — the resolver (25.1) links them via `capabilityId`.
- `extractEmails` helper pulls `to:` addresses from the raw text; `toCron` maps
  weekday words to cron expressions.

## Tests
- `interpret('create a weekly newsletter for team@x.io')` →
  `cap:workflow:create_newsletter`, `input.recipients` includes `team@x.io`.
- `interpret('every monday send the newsletter')` → composite `[schedule_register,
  <newsletter cap>]`.
