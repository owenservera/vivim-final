# Unit 28.2: Newsletter Workflow Template

**Phase:** 28 | **Files:** `src/engines/workflow-templates/newsletter.ts` (new)
**Depends:** 28.1, 28.4, 28.5 | **Class:** CREATE

## Purpose
Realize Scenario 1c: *"create an automated weekly newsletter that distills the week's
work and sends to the team"*. Ships a reusable `WorkflowDefinition` template that
chains `knowledge_distill` → `compose` → `email_send`, plus a capability that
instantiates it from NL.

## Interface
```ts
export function buildNewsletterWorkflow(opts: {
  windowDays: number            // default 7
  recipients: string[]
  title?: string
}): WorkflowDefinition

// registered capability:
//  cap:workflow:create_newsletter  { windowDays?, recipients, title? }
```

## Implementation
- New `src/engines/workflow-templates/newsletter.ts`. `buildNewsletterWorkflow` returns a
  `WorkflowDefinition` with nodes:
  1. `trigger` (manual / cron via 28.3)
  2. `knowledge_distill` (28.4) — `input { window: '<windowDays>d' }`
  3. `ai` (compose) — prompt: "write a newsletter from {{distill.output}}"
  4. `email_send` (28.5) — `input { recipients, body: '{{compose.output}}' }`
- `cap:workflow:create_newsletter` handler builds the workflow, saves it
  (`WorkflowEngine.createWorkflow`), registers it as a capability (28.1), and returns
  the `capabilityId` + `workflowId`.
- Edges carry the pipeline dependencies (distill → compose → send).

## Tests
- `buildNewsletterWorkflow({recipients:['team@x.io']})` yields a 4-node DAG with the
  correct edge chain.
- `cap:workflow:create_newsletter` registers a capability whose execution runs all three
  stages (mock distill/compose/send).
