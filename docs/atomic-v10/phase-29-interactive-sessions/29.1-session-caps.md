# Unit 29.1: Session Lifecycle Capabilities

**Phase:** 29 | **Files:** `src/engines/session-caps.ts` (new)
**Depends:** 24.1, 24.3 | **Class:** PORT

## Purpose
Realize Scenario 2: *"load my chatgpt.com and start an interactive session"*. Provide
`session_load`, `session_start`, `session_switch`, `session_resume` capabilities that
spawn/attach a Chrome slave for a provider and bind it to a conversation — reachable
from CLI REPL and frontend identically.

## Interface
```ts
// src/engines/session-caps.ts → registerSessionCaps(registry, deps)
//  cap:session:load     { providerId, accountId? }   // spawn + ensure login + attach conv
//  cap:session:start    { providerId, conversationId? }
//  cap:session:switch   { providerId | sessionId }   // change active session
//  cap:session:resume   { sessionId }                 // restore from persistence (29.4)
```

## Implementation
- New `src/engines/session-caps.ts`. Handlers close over `FleetSupervisor` (already
  knows `PROVIDER_URLS` for chatgpt/claude/gemini — `fleet-supervisor.ts:17`),
  `ConversationManager`, and a new `SessionStore`.
- `session_load`: `fleet_start {providerId}` → wait for login (reuse `setup.verify` /
  29.5) → create/attach a conversation → return `{ sessionId, conversationId, slaveId }`.
- `session_switch`: updates the active session in the `SessionStore` (29.4) and the
  REPL/UI `ctx`.
- `session_resume`: re-attaches a persisted session (29.4) without re-spawning if the
  slave is still alive.

## Tests
- `session_load {providerId:'chatgpt'}` (mocked governor) returns a `sessionId` +
  `conversationId`; a second `session_switch {providerId:'claude'}` flips the active
  session.
- `session_resume` on a live session returns without spawning a new slave.
