# Unit 29.3: Frontend Session Bootstrapping from NL

**Phase:** 29 | **Files:** `web/sandbox/src/features/conversation-surface.tsx` (extend)
**Depends:** 25.9, 29.1 | **Class:** CREATE

## Purpose
Let the frontend chat box bootstrap a session from NL (Scenario 2, frontend side).
*"load chatgpt"* in the composer → `session_load` → the composer attaches to the new
conversation and starts streaming that provider's responses.

## Interface
```ts
// composer submit (from 25.9):
if (resolvedCapabilityId === 'cap:session:load') {
  const { sessionId, conversationId } = await interpretThenExecute(text)
  attachComposerToConversation(conversationId)   // existing conversation-surface wiring
  setActiveSession(sessionId)
}
```

## Implementation
- In `conversation-surface.tsx`, when `/api/interpret` resolves to `cap:session:load`,
  execute it (or let the route execute it) and read `sessionId`/`conversationId` from
  the result.
- Re-point the composer's `conversationId` to the new session conversation; the existing
  WebSocket/streaming block delivery shows the live session.
- A `session_switch` result re-points the composer without a page reload.

## Tests
- Typing "load chatgpt" routes to `session_load`, executes, and the composer's active
  conversation becomes the loaded session's conversation.
- "switch to claude" re-points without reload.
