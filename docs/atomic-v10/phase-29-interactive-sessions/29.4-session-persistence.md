# Unit 29.4: Session Context Persistence

**Phase:** 29 | **Files:** `src/storage/contracts/session-store.ts` (new) + `impl`, `src/engines/session-caps.ts` (extend)
**Depends:** 29.1 | **Class:** CREATE

## Purpose
Interactive sessions must survive across CLI invocations (Scenario 2 tail: *"resume
interactive sessions across CLI invocations"*). Persist the active session so the next
`vivim` launch can `session_resume` without re-authenticating.

## Interface
```ts
// session-store contract
interface SessionRow {
  id: string
  providerId: string
  accountId?: string
  conversationId: string
  slaveId?: string
  status: 'active' | 'detached' | 'closed'
  createdAt: number
  updatedAt: number
  lastActivityAt: number
}
interface SessionStore {
  upsert(row: SessionRow): Promise<void>
  get(id: string): Promise<SessionRow | null>
  getActive(): Promise<SessionRow | null>
  list(): Promise<SessionRow[]>
  close(id: string): Promise<void>
}
```

## Implementation
- New `src/storage/contracts/session-store.ts` + `session-store-impl.ts` (mirror the
  existing `storage/impl/*-store-impl.ts` pattern).
- `session_load`/`session_switch` upsert the active session; `session_resume` reads it.
- `getActive()` returns the most-recently-active session so a bare `vivim` REPL can
  offer to resume.
- On CLI exit, mark the session `detached` (slave may still be alive); `session_resume`
  re-attaches if the slave pid is live.

## Tests
- `session_load` then process exit simulation → `getActive()` returns the session; a
  subsequent `session_resume` re-attaches without spawning a new slave (mocked).
