# Unit 29.5: Provider Login-State Detection

**Phase:** 29 | **Files:** `src/engines/session-caps.ts` (extend)
**Depends:** 29.1 | **Class:** EXTEND

## Purpose
Before/while loading a session, detect whether the provider slave is already logged in
so the system can skip the login wizard or prompt only when needed. Reuses the existing
`/api/setup/verify` login-check.

## Interface
```ts
// registered capability:
//  cap:session:verify_login  { providerId, slaveId? }
//  → { loggedIn: boolean, account?: string, needsQr?: boolean }
```

## Implementation
- Extend `session-caps.ts` with `cap:session:verify_login`.
- Handler calls the governor's slave health/visibility check, then the setup verify
  endpoint (`setup.verify`) to read login state from the page (cookie/session present).
- `session_load` (29.1) calls `verify_login` first: if already logged in, skip the
  wizard; if a QR is required, return `needsQr: true` → UI shows it (25.6 clarification).
- Emits `session:login_state` on the eventBus so the UI can reflect logged-in/out live.

## Tests
- `verify_login` on a mocked slave reporting a session cookie → `{loggedIn:true}`.
- On a fresh slave → `{loggedIn:false, needsQr:true}`.

## Gate
- typecheck + unit test with mocked governor/verify.
