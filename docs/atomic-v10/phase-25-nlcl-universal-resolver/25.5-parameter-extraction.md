# Unit 25.5: Parameter Extraction

**Phase:** 25 | **Files:** `src/engines/nlcl/parameter-extraction.ts` (new)
**Depends:** 25.1, 25.3 | **Class:** CREATE

## Purpose
Once a capability is resolved (deterministically or via LLM), the natural-language
arguments must become a **typed `input`** that satisfies the capability's
`inputSchema`. Catalog patterns already carry `ZodSchema` input schemas; this unit
runs extraction + validation so every `interpret()` output is a clean
`{ capabilityId, input }` ready for `registry.execute`.

## Interface
```ts
export interface ExtractResult {
  input: Record<string, unknown>
  missing: string[]          // required props not found in NL / ctx
  ambiguous: string[]        // props with >1 plausible value
}

export function extractParameters(
  rawInput: string,
  ctx: NLCContext,
  schema: ZodSchema,
): ExtractResult

export function validateInput(
  input: Record<string, unknown>,
  schema: ZodSchema,
): { ok: true; value: unknown } | { ok: false; errors: string[] }
```

## Implementation
- New `parameter-extraction.ts`:
  - `extractParameters`: scans NL tokens + `ctx.metadata` for values matching each
    schema property (by name, by alias, by type heuristic — e.g. a quoted string →
    string prop, a URL → url prop, a number → number prop). Returns `missing` for
    required props not found.
  - `validateInput`: runs the Zod schema (safeParse); returns typed errors with
    field paths.
- `NLCLEngine`: after resolution (both the deterministic and LLM paths), call
  `extractParameters(rawInput, ctx, pattern.inputSchema)` then `validateInput`.
- If `missing.length > 0` and the capability is **not** `requiresConfirmation`-safe,
  route to clarification (25.6). If validation fails, route to clarification.
- Co-located with the LLM resolver (25.3): the LLM already emits typed `input`, but
  `validateInput` is the second gate that rejects schema-violating model output.

## Tests
- `extractParameters('list providers for claude', ctx, provider_list.schema)` →
  `{ input: { providerId: 'claude' }, missing: [] }`.
- Required prop absent → `missing: ['providerId']`; `validateInput` reports it.
- Type coercion: numeric string `"7"` into a `number` prop yields `7`.
