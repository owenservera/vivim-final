# Unit 25.8: CLI REPL Mode

**Phase:** 25 | **Files:** `src/cli/repl.ts` (new), `src/cli/index.ts`
**Depends:** 24.8, 25.7 | **Class:** CREATE

## Purpose
`vivim` with no args → an interactive natural-language loop. This is Scenario 2: the
user types English, the REPL posts to `/api/interpret`, and streams the response to
stdout. The CLI and the frontend chat box become the **same surface** — both just
emit NL text and consume `/api/interpret`.

## Interface
```bash
$ vivim                                   # → REPL
> load my chatgpt.com and start an interactive session
[spawning chrome slave for chatgpt... session active]
> ask it what is quantum computing
[streaming response...]
> switch to claude
[session active: claude]
```

## Implementation
- New `src/cli/repl.ts` exporting `runRepl(opts: { remote: string; auth?: string })`.
  - Reads lines from `stdin` (no raw mode needed; line-buffered).
  - Each line → `POST ${remote}/api/interpret { text, ctx: { activeSessionId?, providerId? } }`.
  - Maintains REPL-local `ctx` mutated by session commands (29.x) so pronouns
    ("it", "switch to claude") resolve across turns (reuses `resolvePronouns` logic server-side).
  - Streams `text` as it arrives (the route returns a single JSON; the REPL prints
    progressive `text` deltas if the server supports chunked output, else prints the
    final `text`).
  - `exit` / Ctrl-C / `:q` ends the loop. `--json` prints the full `CommandResult`.
- `src/cli/index.ts`: if `argv[2]` is empty, call `runRepl` instead of the one-shot path.
- Errors from the server render as `! <message>` without killing the loop.

## Tests
- Spawned REPL against a booted server: `echo "list providers" | vivim` returns the
  provider array.
- `interpret` 400/500 surfaces as an `! error` line; loop stays alive.
- `:q` exits with code 0.
