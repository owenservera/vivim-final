# Unit 25.6: Confirmation + Clarification Flow

**Phase:** 25 | **Files:** `src/engines/nlcl/nlcl-engine.ts`
**Depends:** 25.1, 25.5 | **Class:** CREATE

## Purpose
Ambiguous or irreversible intents must not execute blindly. Irreversible =
`requiresConfirmation` capability, or a `classification` of `destructive` /
`financial` (`classificationAtLeast` in `types.ts`). Ambiguous = parameter extraction
left `missing`/`ambiguous` props, or resolver confidence low. This unit returns a
structured `requiresConfirmation` / clarification result instead of a blind execute,
and the transports (25.7 route, 25.8 REPL, 25.9 UI) render the prompt.

## Interface
```ts
// CommandResult gains:
interface CommandResult {
  // ...
  requiresConfirmation?: boolean
  clarification?: {
    prompt: string
    missing?: string[]
    ambiguous?: string[]
    options?: string[]      // for enum-like choices
  }
}
```

## Implementation
- In `NLCLEngine.interpret`, before `registry.execute`:
  - If capability `requiresConfirmation === true` OR `classificationAtLeast(class, 'destructive')`
    → set `requiresConfirmation: true`, attach a `confirmationToken` (ULID) in
    `metadata`, and **do not** execute. The caller re-invokes
    `POST /api/capabilities/:id/execute` with `{ confirmToken }` to proceed.
  - If `extractParameters` returned `missing`/`ambiguous` and the intent is
    non-trivial → set `clarification` with a natural-language `prompt` asking for the
    missing value(s); the resolver's `text` field carries the question.
- Low confidence (< `minConfidence`) with no AIFallback result → `clarification` listing
  the `alternatives` (from `ParsedIntent.alternatives`).
- Follow-up: when the user answers the clarification, the REPL/UI re-calls `interpret`
  with the original `clarificationId` in `ctx.metadata` so `bindContext`/`resolvePronouns`
  can splice the answer into the pending input.

## Tests
- `interpret('delete the conversation')` (destructive) returns `requiresConfirmation: true`, no execution.
- Missing required param → `clarification.missing` populated, `ok: false`.
- Confirmation token round-trips: second call with token executes.
