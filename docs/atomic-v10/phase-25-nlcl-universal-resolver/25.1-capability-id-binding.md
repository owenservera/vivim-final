# Unit 25.1: capabilityId Binding on CommandResult

**Phase:** 25 | **Files:** `src/engines/nlcl/types.ts`, `src/engines/nlcl/catalog.ts`
**Depends:** 24.1, 24.3 | **Class:** EXTEND

## Purpose
Make the resolver's output a first-class system command. Today `CommandResult`
(`src/engines/nlcl/types.ts:45`) carries `intent` but no `capabilityId`, so the NLP
layer cannot name the capability it resolved to. Every catalog pattern must declare
the capability id it maps to, so that `interpret()` returns a structured
`{ capabilityId, input }` that downstream transports (universal execute route, MCP,
workflow nodes) can act on directly.

## Interface
```ts
// types.ts — add to CommandResult
interface CommandResult {
  // ...existing fields...
  capabilityId?: string          // NEW: the resolved UnifiedCapability id (or slug)
}

// catalog.ts — each CommandPattern gains:
interface CommandPattern {
  // ...existing...
  capabilityId?: string          // NEW: target UnifiedCapability id
}
```

## Implementation
- Extend `CommandResult` in `types.ts` with optional `capabilityId`.
- In `catalog.ts` (`getDefaultCommandPatterns`), bind every pattern to a `capabilityId`
  matching a slug in `capability-bootstrap.ts` (e.g. `providers list` →
  `cap:provider:list`, `knowledge search` → `cap:knowledge:search`).
- `IntentRouter.route` (already used by NLCLEngine) sets `result.capabilityId` from
  the matched pattern's `capabilityId` before returning.
- For composite results, set `capabilityId: 'composite'` and include per-step ids in
  `output.results[].capabilityId`.
- `CapabilityExecutor` (`src/engines/nlcl/executors/index.ts`) already closes over the
  registry; it becomes the default executor for any pattern that carries a
  `capabilityId` (routes straight to `registry.execute`).

## Tests
- `interpret('list providers')` returns `capabilityId === 'cap:provider:list'`.
- A pattern without `capabilityId` still resolves (backward-compatible, `capabilityId` undefined).
- `interpret('go to cnn and summarize')` returns `capabilityId: 'composite'` with step ids populated.
