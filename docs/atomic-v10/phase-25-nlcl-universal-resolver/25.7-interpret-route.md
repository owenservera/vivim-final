# Unit 25.7: /api/interpret Universal NL Endpoint

**Phase:** 25 | **Files:** `src/server/interpret-router.ts` (new), `src/server/index.ts`
**Depends:** 24.1, 24.7, 25.1, 25.2, 25.5, 25.6 | **Class:** CREATE

## Purpose
The single natural-language front door for **both** shells. The frontend chat box and
the CLI REPL POST raw text here; the server binds context, runs the resolver +
parameter extraction + confirmation flow, and returns either an executed result or a
clarification/confirmation request. `nl_interpret` (24.7) is sugar over this route.

## Interface
```
POST /api/interpret
  body: { text: string, ctx?: { conversationId?, providerId?, canvasState?, activeSessionId?, ... } }
  → 200 { ok, capabilityId?, output?, text?, clarification?, requiresConfirmation?, traceId }
  → 400 malformed body (missing text)
```
On success-without-confirmation, the route internally performs
`POST /api/capabilities/:id/execute` (24.1) so callers get a unified response shape.

## Implementation
- New `createInterpretRouter(ctx)` in `src/server/interpret-router.ts`:
  - Build `RawRequestContext` from `body.ctx`; call `bindContext` (25.2).
  - `nlclEngine.interpret(text, ctx)`.
  - If `result.requiresConfirmation` → 200 with `requiresConfirmation` + token; no execute.
  - If `result.clarification` → 200 with the clarification.
  - Else execute via `registry.execute(result.capabilityId, result.output ?? {}, capCtx)` and
    return `{ ok, capabilityId, output, text, traceId, latencyMs }` (reusing the 24.1 shape).
- Mount in `server/index.ts` before the `/api/capabilities/` branch:
  `if (url.pathname === '/api/interpret') return interpretRouter(req)`.
- Auth-gated (reuse `createAuthMiddleware`); `conversationId` from body is validated
  against the caller's scope.

## Tests
- `POST /api/interpret {text:'list providers'}` → `{ok, capabilityId:'cap:provider:list', output:[...]}`.
- `POST /api/interpret {text:'delete everything'}` (destructive) → `requiresConfirmation: true`.
- Malformed (`{}`) → 400.
