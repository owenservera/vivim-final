# Unit 26.2: Image Generation Bridge

**Phase:** 26 | **Files:** `src/engines/image-gen-bridge.ts` (new)
**Depends:** 26.1 | **Class:** CREATE

## Purpose
Turn a text query into an image the canvas can use as a background or layer asset.
Feeds `canvas_set_background { imageQuery }` (Scenario 1a: "moon made out of cheese").
Tries a local model first (offline, sovereign), falls back to the logged-in provider
LLM if no local model is configured.

## Interface
```ts
export interface ImageGenDeps {
  localModel?: LocalModelAdapter     // src/engines/local-model-adapter.ts
  providerLLM?: ProviderLLMAdapter
}
export async function generateImage(
  query: string,
  deps: ImageGenDeps,
): Promise<{ dataUrl: string; source: 'local' | 'provider' }>
```

## Implementation
- New `src/engines/image-gen-bridge.ts`.
  - If `localModel` configured → call it with an image-generation prompt; decode the
    returned bytes to a `data:` URL.
  - Else if `providerLLM` available → ask the provider to produce an image (provider-
    specific; e.g. DALL·E-style tool call) and decode.
  - Else throw `EngineError('No image generation backend available')`.
- `canvas_set_background` handler (26.1) calls `generateImage` when only `imageQuery`
  is supplied, then applies the resulting `dataUrl`.
- Returns `dataUrl` (base64) so it is directly assignable as a CSS background /
  `<img src>` without a second fetch.

## Tests
- With a mocked `localModel` returning PNG bytes, `generateImage('moon cheese')`
  returns a `data:image/png;base64,...` URL with `source: 'local'`.
- Neither backend available → throws a clear error; `set_background` surfaces it as
  `clarification` ("no image backend configured").
