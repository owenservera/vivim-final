# Unit 26.4: Canvas Live Mutation Stream

**Phase:** 26 | **Files:** `src/server/websocket.ts`, `src/canvas/canvas-engine.ts`
**Depends:** 26.1 | **Class:** EXTEND

## Purpose
When a canvas mutation executes (from CLI, UI, or workflow), the **live** canvas in
the frontend must re-render without a refresh. The mutation diff streams over the
existing WebSocket channel so every surface subscribed to the instance sees the
change simultaneously — reinforcing that all surfaces talk to one system.

## Interface
```ts
// eventBus already exists (CapabilityEventBus)
// canvas:mutated payload:
{ instanceId: string, op: 'set_background'|'add_layer'|'remove_layer'|'set_layout'|'set_theme',
  diff: unknown, by: 'cli'|'ui'|'workflow'|'api' }
```
WebSocket message to subscribed clients:
`{ type: 'canvas:mutated', instanceId, op, diff }`.

## Implementation
- In `registerCanvasMutationCaps` (26.1), after each successful mutation, publish
  `canvas:mutated` on `ctx.eventBus`.
- `websocket.ts`: subscribe to `canvas:mutated`; relay to all WS clients watching that
  `instanceId` (the WS layer already multiplexes by instance/region).
- Frontend (`conversation-surface.tsx` / canvas host) listens for `canvas:mutated` and
  applies the `diff` to the live layer (reuses the existing `SandboxBridge.pushState`
  mirror mechanism from `capability-bridge.ts`).

## Tests
- Execute `cap:canvas:set_background` via HTTP → a connected WS test client receives a
  `canvas:mutated` message for the right `instanceId`.
- No clients subscribed → mutation still succeeds (broadcast is best-effort).
