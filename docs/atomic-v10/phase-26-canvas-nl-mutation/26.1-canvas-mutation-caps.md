# Unit 26.1: Canvas Mutation Capability Catalog

**Phase:** 26 | **Files:** `src/canvas/mutation-caps.ts` (new), `src/canvas/canvas-engine.ts`
**Depends:** 24.1, 24.3 | **Class:** EXTEND

## Purpose
Give the canvas first-class, NL-addressable mutation operations so the frontend chat
box and CLI can change the canvas by talking to the system in natural language
(Scenario 1a: *"change my canvas background to an image of the moon made out of
cheese"*). Each mutation is a `UnifiedCapability` registered into the single registry,
so it is reachable from CLI, UI, and `/api/interpret` identically.

## Interface
```ts
// src/canvas/mutation-caps.ts
export function registerCanvasMutationCaps(
  registry: UnifiedCapabilityRegistry,
  canvas: CanvasEngine,
): void

// Capabilities:
//  cap:canvas:set_background  { imageBase64?, imageQuery?, layerId? }
//  cap:canvas:add_layer       { kind, title, config? }
//  cap:canvas:remove_layer    { layerId }
//  cap:canvas:set_layout      { layout }
//  cap:canvas:set_theme       { theme }
```
All `surfaces: ['cli','ui','api','mcp','workflow']`, `requiresConfirmation: false`
except `remove_layer` (destructive → `requiresConfirmation: true`).

## Implementation
- New `src/canvas/mutation-caps.ts`; `registerCanvasMutationCaps` calls
  `registry.register(...)` for each, with handlers closing over `CanvasEngine`.
- Handlers delegate to the engine's `designer` / `mounter` / `mirror` (already wired
  in `CanvasEngine` constructor). `set_background` accepts either `imageBase64`
  (direct) or `imageQuery` (→ 26.2 image bridge).
- In `CanvasEngine.registerCapabilities`, also call `registerCanvasMutationCaps`
  (alongside the existing `registerCanvasCapabilities` from `canvas-agent-tools.ts`).
- Each mutation emits a `canvas:mutated` event on the `CapabilityEventBus` carrying
  the diff (feeds 26.4 live stream).

## Tests
- `POST /api/capabilities/cap:canvas:set_background/execute {imageBase64:'data:...'}`
  updates the layer background and emits `canvas:mutated`.
- `add_layer` then `remove_layer {layerId}` round-trips; `remove_layer` returns
  `requiresConfirmation: true` before executing.
