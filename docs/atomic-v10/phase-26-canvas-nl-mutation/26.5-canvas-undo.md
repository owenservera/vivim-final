# Unit 26.5: Canvas Undo / Rollback

**Phase:** 26 | **Files:** `src/canvas/mutation-caps.ts` (extend), `src/canvas/canvas-mirror.ts`
**Depends:** 26.1 | **Class:** CREATE

## Purpose
Mutations can be disliked (Scenario 1a ends with *"canvas_undo if the user dislikes
it"*). Provide `canvas_undo` and `canvas_history` capabilities backed by the
`CanvasMirror` (already part of `CanvasEngine`), so any surface can roll back a
mutation through the universal execute route.

## Interface
```ts
// added to registerCanvasMutationCaps
//  cap:canvas:undo        { steps?: number }            // default 1
//  cap:canvas:history      { limit?: number }
```
`canvas:mutated` events (26.4) are appended to the mirror's history log; `undo`
pops the last N and re-applies the prior state.

## Implementation
- Extend `CanvasMirror` (`canvas-mirror.ts`) with `pushMutation(entry)` and
  `undo(n)` that returns the state to restore.
- In `mutation-caps.ts`, after each mutation, `mirror.pushMutation({ op, diff, before, after })`.
- `canvas_undo` handler calls `mirror.undo(steps ?? 1)` and applies the restored state
  via the mounter; emits a `canvas:mutated` (op: `undo`) so 26.4 streams it.
- `canvas_history` returns the last `limit` mutation entries (read-only).

## Tests
- `set_background` then `canvas_undo` restores the previous background; `canvas_history`
  lists both entries.
- `undo` beyond history length is a no-op (returns current state, no error).
