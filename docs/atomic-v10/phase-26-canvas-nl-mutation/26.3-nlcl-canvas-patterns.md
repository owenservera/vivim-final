# Unit 26.3: NLCL Canvas Patterns

**Phase:** 26 | **Files:** `src/engines/nlcl/catalog.ts`, `src/engines/nlcl/types.ts`
**Depends:** 25.1, 26.1 | **Class:** CREATE

## Purpose
Add natural-language patterns that map canvas sentences to the mutation capabilities
from 26.1. This is how Scenario 1a enters the system: NL → `capabilityId` → universal
execute route → canvas mutation.

## Interface
```ts
// catalog.ts additions (each carries capabilityId)
{ intent: 'canvas.set_background', capabilityId: 'cap:canvas:set_background',
  patterns: [/change (my |the )?canvas (background|bg).*?(to|into) (.+)/i],
  extract: (m) => ({ imageQuery: m[4] }) }
{ intent: 'canvas.add_layer', capabilityId: 'cap:canvas:add_layer',
  patterns: [/add (a )?layer (showing|for|called) (.+)/i],
  extract: (m) => ({ title: m[3] }) }
// + remove_layer, set_layout, set_theme
```

## Implementation
- Extend `getDefaultCommandPatterns()` in `catalog.ts` with the five canvas patterns,
  each binding `capabilityId` (per 25.1) and an `inputSchema` (Zod) mirroring the
  capability's `inputSchema`.
- `executor` for these patterns = `capability` (the `CapabilityExecutor` routes to
  `registry.execute`), so they inherit the universal transport and confirmation flow.
- `set_background` with an `imageQuery` and no image backend triggers the clarification
  from 26.2/25.6.

## Tests
- `interpret('change my canvas background to an image of the moon made of cheese')`
  → `capabilityId: 'cap:canvas:set_background'`, `input.imageQuery` present.
- `interpret('add a layer showing my calendar')` → `cap:canvas:add_layer`,
  `input.title: 'my calendar'`.
