# Unit 30.4: Cleanup Dead Bridges & Orphan Handlers

**Phase:** 30 | **Files:** delete `src/cli/bridges/*`, orphan `src/cli/commands/*` (folded), `web/ui/src/actions/catalog.ts`
**Depends:** 24.8, 24.9 | **Class:** FIX

## Purpose
Remove the divergent second/third registries and hand-written bridges that v10 makes
obsolete, so the "one registry, one transport" invariant is physically enforced (no
dead code to regress into).

## Interface
- Delete `src/cli/bridges/cap-store-bridge.ts`, `backend-bridge.ts`, `extension-bridge.ts`
  (replaced by 24.1 universal route).
- Delete orphan hand-written CLI command files folded into capabilities in 24.4-24.6
  (version/health/fleet/providers/config/conversations/admin/telemetry/kernel/discovery
  command modules) — the CLI now auto-generates from the registry (24.8).
- Replace `web/ui/src/actions/catalog.ts` hand-written `ActionRegistry` with auto-
  population from `GET /api/capabilities?surface=ui` (24.9). Keep `ActionRegistry` as
  the runtime container; fill it from the server, not from a static file.

## Implementation
- After 24.8/24.9 land, run a grep to confirm no remaining imports of the deleted
  modules; delete them.
- `web/ui/src/actions/catalog.ts` becomes a thin `await populateActionsFromRegistry()`
  that fetches `?surface=ui` and calls `ActionRegistry.register` per capability.
- Update `web/ui/src/actions/index.ts` import path if needed.
