# Unit 30.2: NLCL Golden Test Set

**Phase:** 30 | **Files:** `tests/e2e/nlcl-golden.test.ts` (new)
**Depends:** 25.1, 25.3, 25.4, 26.3, 27.4, 28.6 | **Class:** CREATE

## Purpose
Lock the NLP formatting layer: the scenario sentences from the brief must resolve to
the exact capability chains the architecture promises. This is the regression guard for
*"the system's NLP formats to system-level commands"*.

## Interface
```ts
// golden cases (input text → expected capabilityId chain)
const GOLDEN = [
  { text: 'change my canvas background to an image of the moon made out of cheese',
    expect: [{ capabilityId: 'cap:canvas:set_background', input:{ imageQuery:'moon made out of cheese' } }] },
  { text: 'add new streaming channels like my facebook messaging feed, my whatsapp',
    expect: [{ capabilityId:'cap:channel:add', input:{providerId:'facebook'}},
             { capabilityId:'cap:channel:add', input:{providerId:'whatsapp'}}] },
  { text: 'create an automated weekly newsletter that distills the week\'s work and sends to the team',
    expect: [{ capabilityId:'cap:workflow:create_newsletter', input:{ recipients:[...] } }] },
  { text: 'load my chatgpt.com and start an interactive session',
    expect: [{ capabilityId:'cap:session:load', input:{ providerId:'chatgpt' } }] },
]
```

## Implementation
- New `tests/e2e/nlcl-golden.test.ts`. For each golden case, call `nlclEngine.interpret`
  (with a mocked LLM slave for the novel sentences) and assert the resolved
  `capabilityId` + extracted `input` match `expect`.
- Composites assert the ordered step chain; single intents assert the one capability.
- Keep golden inputs frozen; any change to resolution that alters a golden output must
  be a deliberate, reviewed decision (CI fails otherwise).

## Tests
- All four scenario sentences resolve to their expected chains.
- Adding a new capability pattern requires a golden entry (enforced by a count assert).

## Gate
- `bun test tests/e2e/nlcl-golden` green.
