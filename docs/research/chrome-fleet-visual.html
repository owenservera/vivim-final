The Takeaway

vivim-final is already SOTA-aligned on the big patterns (single orchestrator, persistent profiles, one-Chrome-per-provider). The gaps are admission control — the fleet has no limiter, no pressure gate, and no first-class retry-on-crash. These are small, well-bounded additions to ChromeGovernor.

SOTA Patterns Observed
🛡️ Single Orchestrator
browserless / Steel centralize all Chrome lifecycle. Matches vivim's ChromeGovernor (Governor Canon).
📁 Persistent Profiles
Logged-in sessions cached on disk. Matches chrome-profiles/<slug>/<acct>.
🔢 Concurrency Caps
maxConcurrent / maxQueued + queue timeout. GAP in vivim.
🔁 Retry on Crash
First-class retryLimit / willRetry. GAP in vivim.
⚡ Pre-spawn Pressure
CPU/MEM overload gates before launching. GAP in vivim.
🧹 Orphan Reaping
Child Chrome PIDs reaped on exit. GAP (Windows) in vivim.
📊 Health + Metrics
Live fleet dashboards. Partial via governor-store.
🎯 Session Affinity
Sticky provider→browser. Matches one-Chrome-per-provider model.

4 Gaps to Close
1 GAP No Admission Limiter
Nothing enforces maxConcurrent / maxQueued / queueTimeoutMs. A burst of provider requests can over-launch Chrome. Add a FleetLimiter in front of ChromeGovernor.spawn.
2 GAP No Pressure Gate
No cpuOverloadPct / memOverloadPct check before spawning. Pre-spawn gate should refuse / queue when host is saturated.
3 GAP No Retry-on-Crash
Crash recovery is implicit. Add explicit retryLimit / retryDelayMs / willRetry with bounded backoff.
4 GAP Windows Orphan Reaper
No child-PID reaper for leaked Chrome processes on Windows shutdown. Track spawned PIDs and kill the tree on exit.
Proposed Code Path

Extends src/executor/fleet-config.ts and wraps ChromeGovernor.spawn(). Probable convergence — full draft in docs/research/code-paths/chrome-fleet-management-path.md. 

// FleetConfig — add admission-control fields
interface FleetConfig {
  maxConcurrent: number;      // e.g. CONCURRENCY_BROWSER
  maxQueued: number;          // queue depth before reject
  queueTimeoutMs: number;     // give up waiting
  cpuOverloadPct: number;      // pre-spawn gate
  memOverloadPct: number;     // pre-spawn gate
  retryLimit: number;        // retry-on-crash
  retryDelayMs: number;      // backoff base
}

// FleetLimiter — sits in front of ChromeGovernor.spawn
class FleetLimiter {
  async acquire(provider: string): Promise<Lease> {
    if (this.overloaded()) throw new FleetOverloaded();
    return this.queue.enqueue(provider);
  }
  async spawnGuarded(provider: string) {
    for (let i = 0; i < cfg.retryLimit; i++) {
      try { return await governor.spawn(provider); }
      catch (e) { if (!willRetry(e)) throw e; await sleep(cfg.retryDelayMs * 2**i); }
    }
  }
}
