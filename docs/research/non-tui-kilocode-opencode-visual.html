01 The Core Insight: "Provider" means the opposite thing

vivim providers are browser UIs driven over CDP. Kilo/OpenCode providers are LLM API backends they call. Wiring them in is a new axis, not a new row in the CDP table.

03 How Top-Tier Teams Leverage Non-TUI Agents

① CI/CD gated checks

Run run --auto in GitHub Actions for scheduled refactors, PR triage, pre-merge review. Pipeline-native: prints stdout + exits.

② Agentic dev loops

Launch serve once, then run --attach repeatedly — skip MCP cold-boot. Exactly vivim's devops / vivim-runtime pattern.

③ Subagent orchestration

agent create (scoped perms/model) or ACP for embedding. Ralph-TUI wraps OpenCode as a managed, task-routed subagent.

04 Two Integration Shapes into vivim

Shape A — CDP-wrap their Web UI ❌

Register kilo/opencode like chatgpt, point endpoints at web, drive composer via ChromeGovernor.

Why rejected: needs a logged-in browser, defeats headless purpose, loses structured JSON, and breaks the point of using an agent.

Shape B — local-agent provider type ✅ (recommended)

Add provider_type:'local-agent' alongside 'llm'. Capabilities execute by shelling out to run --auto or POSTing to serve, then parsing output into ContentBlock[] via StreamParserEngine.

Wins: no CDP, ChromeGovernor untouched (Governor Canon safe), Store-Contracts honored. Enables "run unit X via Kilo agent", subagent fan-out, headless devops.

05 Confirmed Code Path (Convergence: CONFIRMED)

A thin LocalAgentProviderExecutor — the only net-new surface. Spawns the CLI or hits serve, parses to ContentBlock[].

// src/engines/local-agent-provider.ts — Shape B: agent backend as a vivim provider.
// No CDP. Spawns the CLI / hits serve HTTP. Governor Canon preserved.
import { spawn } from 'node:child_process';
import { type ContentBlock } from '@/engines/stream-parser';

export interface LocalAgentRequest {
  slug: 'kilo' | 'opencode';
  message: string;
  model?: string;          // provider/model
  cwd?: string;
  timeoutMs?: number;      // kilo returns 124 on timeout
}

// Option 1: one-shot CLI (preferred for unattended devops jobs)
export async function runLocalAgent(req: LocalAgentRequest): Promise<ContentBlock[]> {
  const bin = req.slug === 'kilo' ? 'kilo' : 'opencode';
  const args = ['run', '--auto', req.message,
    ...(req.model ? ['--model', req.model] : []),
    ...(req.cwd  ? ['--dir',  req.cwd ] : [])];
  if (req.slug === 'opencode') args.push('--format', 'json');

  const proc = spawn(bin, args, { cwd: req.cwd, env: { ...process.env } });
  const chunks: Buffer[] = [];
  proc.stdout.on('data', (d) => chunks.push(d));

  const code = await new Promise<number>((res) => {
    proc.on('close', (c) => res(c ?? 1));
    setTimeout(() => proc.kill('SIGTERM'), req.timeoutMs ?? 120_000).unref();
  });
  if (code === 124) throw new Error('local-agent: timeout');
  if (code !== 0)   throw new Error(`local-agent: exit ${code}`);

  return parseAgentOutput(req.slug, Buffer.concat(chunks).toString('utf8'));
}

// Option 2: persistent server (only if networked + OPENCODE_SERVER_PASSWORD set)
export async function postToServe(baseUrl: string, sessionId: string, message: string) {
  return await fetch(`${baseUrl}/session/${sessionId}/message`, {
    method: 'POST', headers: { 'content-type': 'application/json' },
    body: JSON.stringify({ parts: [{ type: 'text', text: message }] }),
  }).then((r) => r.json()); // { info: Message, parts: Part[] }
}

06 Limitations & Risk Controls

⚠ Blind follow-ups

Autonomous mode auto-answers "decide autonomously". Set explicit deny for destructive tools.

permission: { "*": "ask",
  bash: { "rm *": "deny" } }

⚠ serve hang risk

Community reports serve+client infinite loops. Prefer run for unattended jobs; client-side timeout + 124 check.

⚠ Unauth by default

serve/web are open unless OPENCODE_SERVER_PASSWORD set. Bind to localhost for devops.

⚠ resume互斥

--continue can't combine with a prompt or --auto. Design pipelines around explicit session IDs.

08 Recommendations for vivim-final

1. Adopt Shape B (local-agent provider type) as the headless devops execution backend.
2. Use run --auto (+ --format json for OpenCode) for jobs; reserve serve/acp for persistent MCP reuse.
3. Permission policy: explicit deny for risky tools; anything not auto-approved is blocked.
4. Candidate ADR: "Agent backends as vivim providers" — cross-refs the SOTA brief.
5. Do NOT give non-TUI agents DOM vision; keep CDP/ChromeGovernor for real web-chat providers.
