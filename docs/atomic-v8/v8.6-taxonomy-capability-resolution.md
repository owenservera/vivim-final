## Context

The `CapabilityResolutionEngine` is the central engine that resolves user intent to executable capabilities. By wiring the `ProviderTaxonomyResolver` into it, the engine gains taxonomy-first resolution: before falling back to runtime probing, it checks the pre-seeded taxonomy for the best match.

## Interface

### Wire into `CapabilityResolutionEngine` — `src/engines/capability-resolution/index.ts`

Add a new resolution strategy that runs before existing strategies:

```typescript
import { ProviderTaxonomyResolver } from '../provider-taxonomy/provider-taxonomy-resolver.js';

// In CapabilityResolutionEngine constructor or init:
private taxonomyResolver: ProviderTaxonomyResolver;

// New resolution strategy — taxonomy-first:
async resolveWithTaxonomy(
  userInput: string,
  providerSlug?: string
): Promise<CapabilityResolution | null> {
  const results = await this.taxonomyResolver.resolveIntent(userInput, providerSlug);
  
  if (results.length === 0) return null;

  const best = results[0];

  return {
    capabilitySlug: best.matchedIntent,
    providerSlug: best.providerSlug,
    confidence: best.confidence,
    entities: best.extractedEntities,
    source: 'taxonomy',
  } as CapabilityResolution;
}
```

### Resolution order update

```
1. Taxonomy resolution (NEW — v8.6)
2. Pattern matching (existing)
3. Semantic resolution (existing)
4. Fuzzy matching (existing)
5. Runtime probing (existing fallback)
```

## Acceptance Criteria

1. `CapabilityResolutionEngine` accepts a `ProviderTaxonomyResolver` instance.
2. Taxonomy resolution runs first (before pattern matching, semantic, fuzzy, runtime probing).
3. If taxonomy finds a match with confidence >= 0.6, it is returned immediately.
4. If taxonomy finds no match, existing resolution strategies are tried.
5. The `source` field distinguishes taxonomy matches from other resolution sources.
