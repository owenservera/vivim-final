# Unit v8.7 — Discovery engine acceleration: taxonomy-first discovery

**Source:** `docs/research/briefs/provider-taxonomy-brief.md` §Used In
**Design Doc:** v8 tracker §v8.7
**Depends on:** v8.5
**Produces:** Discovery engine uses taxonomy hints for DOM selectors; eliminates runtime probing for known platforms.

---

## Context

The `ProviderDiscoveryEngine` currently probes the DOM at runtime to find composer selectors, send buttons, and message lists. With the taxonomy pre-seeded with these hints, the discovery engine can skip probing for known platforms and use the taxonomy's `discoveryHintsJson` directly.

## Existing Baseline

- `src/engines/discovery/` — existing provider discovery engine.
- `src/engines/provider-taxonomy/provider-taxonomy-resolver.ts` — v8.5 resolver with `getDiscoveryHints()`.
- DOM selectors are the most fragile part of discovery — taxonomy seeds them.

## Interface

### Wire into `ProviderDiscoveryEngine`

```typescript
import { ProviderTaxonomyResolver } from '../provider-taxonomy/provider-taxonomy-resolver.js';

// In ProviderDiscoveryEngine — taxonomy-first discovery:
async discoverWithTaxonomy(providerSlug: string): Promise<DiscoveryResult> {
  // 1. Check taxonomy for pre-seeded hints
  const hints = await this.taxonomyResolver.getDiscoveryHints(providerSlug);
  
  if (hints) {
    // 2. Use taxonomy hints — skip DOM probing
    return {
      providerSlug,
      composerSelector: hints.composerSelector,
      sendButtonSelector: hints.sendButtonSelector,
      messageListSelector: hints.messageListSelector,
      source: 'taxonomy',
      confidence: 0.9,  // High confidence for pre-seeded data
    } as DiscoveryResult;
  }

  // 3. Fallback to existing DOM probing
  return this.discoverWithProbing(providerSlug);
}
```

### Discovery result type update

```typescript
interface DiscoveryResult {
  providerSlug: string;
  composerSelector: string;
  sendButtonSelector: string;
  messageListSelector: string;
  source: 'taxonomy' | 'probing' | 'manifest';
  confidence: number;
}
```

## Acceptance Criteria

1. `ProviderDiscoveryEngine` accepts a `ProviderTaxonomyResolver` instance.
2. For known platforms (facebook, instagram, linkedin, whatsapp, telegram, x_twitter), discovery uses taxonomy hints directly.
3. For unknown platforms, discovery falls back to DOM probing.
4. The `source` field distinguishes taxonomy discovery from probing.
5. Discovery for known platforms completes in < 100ms (no DOM interaction needed).
