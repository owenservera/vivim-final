# Unit v8.2 — Storage contract: ProviderTaxonomyStore interface

**Source:** `docs/research/code-paths/provider-taxonomy-path.md` §Why This Works
**Design Doc:** v8 tracker §v8.2
**Depends on:** v8.1
**Produces:** `ProviderTaxonomyStore` contract; `ProviderTaxonomyRow` type; `rowToTaxonomy`/`taxonomyToRow` mappers.

---

## Context

Engines never import storage implementations directly (P5). The `ProviderTaxonomyStore` contract defines the interface that `PrismaProviderTaxonomyStore` implements. All taxonomy lookups — by provider, by category, by interaction pattern — go through this contract.

## Existing Baseline

- `src/storage/contracts/provider-store.ts` — existing provider contract pattern.
- `src/storage/contracts/capability-store.ts` — capability contract pattern.
- All contracts export: interface, row type, mapper functions.

## Interface

### Contract — `src/storage/contracts/provider-taxonomy-store.ts`

```typescript
import type { ProviderCapabilityTaxonomy } from '@prisma/client';

export type ProviderTaxonomyRow = ProviderCapabilityTaxonomy;

export interface ProviderTaxonomyInput {
  providerId: string;
  platformCategory: string;
  interactionPattern: string;
  messageTypesJson?: string;
  capabilitiesJson?: string;
  constraintsJson?: string;
  authRequirementsJson?: string;
  discoveryHintsJson?: string;
  nlpEntityTypesJson?: string;
  nlpIntentPatternsJson?: string;
  seedDataVersion?: number;
  isActive?: number;
}

export interface ProviderTaxonomyStore {
  create(input: ProviderTaxonomyInput): Promise<ProviderTaxonomyRow>;
  getById(id: string): Promise<ProviderTaxonomyRow | null>;
  getByProviderId(providerId: string): Promise<ProviderTaxonomyRow[]>;
  getByCategory(category: string): Promise<ProviderTaxonomyRow[]>;
  getByPattern(pattern: string): Promise<ProviderTaxonomyRow[]>;
  getByProviderAndCategory(providerId: string, category: string): Promise<ProviderTaxonomyRow | null>;
  list(opts?: { category?: string; pattern?: string; isActive?: number }): Promise<ProviderTaxonomyRow[]>;
  update(id: string, patch: Partial<Omit<ProviderTaxonomyInput, 'providerId'>>): Promise<ProviderTaxonomyRow>;
  delete(id: string): Promise<void>;
  upsertByProviderAndCategory(
    providerId: string,
    category: string,
    pattern: string,
    input: Omit<ProviderTaxonomyInput, 'providerId' | 'platformCategory' | 'interactionPattern'>
  ): Promise<ProviderTaxonomyRow>;
}

export function rowToTaxonomy(row: ProviderTaxonomyRow): ProviderCapabilityTaxonomy {
  return { ...row };
}

export function taxonomyToRow(taxonomy: ProviderCapabilityTaxonomy): ProviderTaxonomyRow {
  return { ...taxonomy };
}
```

## Acceptance Criteria

1. `ProviderTaxonomyStore` interface compiles with zero type errors.
2. `rowToTaxonomy` and `taxonomyToRow` are loss-less inverses.
3. All CRUD methods are covered: create, getById, getByProviderId, getByCategory, getByPattern, getByProviderAndCategory, list, update, delete, upsertByProviderAndCategory.
4. The `ProviderTaxonomyInput` type omits `id`, `createdAt`, `updatedAt` (auto-generated).
