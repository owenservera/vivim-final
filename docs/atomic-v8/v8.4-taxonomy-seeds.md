# Unit v8.4 — Seed data: 6 platforms (Facebook, Instagram, LinkedIn, WhatsApp, Telegram, X)

**Source:** `docs/research/code-paths/provider-taxonomy-path.md` §Step 2
**Design Doc:** v8 tracker §v8.4
**Depends on:** v8.1, v8.3

## Context

Pre-populate the `ProviderCapabilityTaxonomy` table with platform-specific metadata for all 6 target platforms. Each seed entry includes: platform category, interaction pattern, message types, capabilities (with auth scopes), constraints (rate limits, max message length, media types), auth requirements, DOM discovery hints, NLP entity types, and NLP intent patterns.

## Existing Baseline

- `seeds/` — existing seed files for providers, capabilities, etc.
- `seeds/adapters/` — adapter pattern for loading seeds.
- `seeds/providers/` — provider seed JSON files.

export async function seedProviderCapabilityTaxonomy(prisma: any) {
  const now = Math.floor(Date.now() / 1000);

  for (const seed of platformTaxonomySeeds) {
    const provider = await prisma.providerDefinition.findUnique({
      where: { slug: seed.providerSlug },
    });

    if (!provider) {
      console.warn(`Provider ${seed.providerSlug} not found, skipping taxonomy seed`);
      continue;
    }

    const existing = await prisma.providerCapabilityTaxonomy.findFirst({
      where: {
        providerId: provider.id,
        platformCategory: seed.platformCategory,
        interactionPattern: seed.interactionPattern,
      },
    });

    if (existing) {
      await prisma.providerCapabilityTaxonomy.update({
        where: { id: existing.id },
        data: {
          messageTypesJson: JSON.stringify(seed.messageTypes),
          capabilitiesJson: JSON.stringify(seed.capabilities),
          constraintsJson: JSON.stringify(seed.constraints),
          authRequirementsJson: JSON.stringify(seed.authRequirements),
          discoveryHintsJson: JSON.stringify(seed.discoveryHints),
          nlpEntityTypesJson: JSON.stringify(seed.nlpEntityTypes),
          nlpIntentPatternsJson: JSON.stringify(seed.nlpIntentPatterns),
          updatedAt: now,
        },
      });
    } else {
      await prisma.providerCapabilityTaxonomy.create({
        data: {
          id: ulid(),
          providerId: provider.id,
          platformCategory: seed.platformCategory,
          interactionPattern: seed.interactionPattern,
          messageTypesJson: JSON.stringify(seed.messageTypes),
          capabilitiesJson: JSON.stringify(seed.capabilities),
          constraintsJson: JSON.stringify(seed.constraints),
          authRequirementsJson: JSON.stringify(seed.authRequirements),
          discoveryHintsJson: JSON.stringify(seed.discoveryHints),
          nlpEntityTypesJson: JSON.stringify(seed.nlpEntityTypes),
          nlpIntentPatternsJson: JSON.stringify(seed.nlpIntentPatterns),
          seedDataVersion: 1,
          isActive: 1,
          createdAt: now,
          updatedAt: now,
        },
      });
    }
  }

  console.log(`Seeded ${platformTaxonomySeeds.length} provider capability taxonomies`);
}

## Acceptance Criteria

1. `seeds/taxonomy/platform-taxonomy.seed.ts` compiles.
2. All 6 platforms have seed entries: facebook, instagram, linkedin, whatsapp, telegram, x_twitter.
3. Each platform has correct `platformCategory`, `interactionPattern`, message types, capabilities, constraints, auth requirements, discovery hints, NLP entity types, and NLP intent patterns.
4. `upsertByProviderAndCategory` is used (create-or-update pattern).
5. Missing providers are logged as warnings, not errors.
