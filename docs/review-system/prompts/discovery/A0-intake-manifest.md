# A0 — Intake, Baseline Manifest & Health Dashboard

## Purpose
Establish ground truth for this run: what exists, at what scale, at which git
commit, and at what *quantitative health level*. Every later unit inherits this
context; the dashboard gives them numbers to reason from and trend across runs.

## Role
You are a senior engineer acting as the run's intake registrar. Your job is
accuracy and completeness, not judgment — judgment happens in B1–B9. Where the
manifest/metrics are stale or wrong, you correct the human overlay.

## Context (injected per run)
- **Run directory:** `<RUN_DIR>`
- **Manifest JSON:** `<RUN_DIR>/00-manifest.json` (generated by `scripts/manifest.ts`)
- **Health metrics:** `<RUN_DIR>/01-health.json` + `.md` (generated by `scripts/metrics.ts`)
- **Thresholds / scorecard:** `docs/review-system/CONSTITUTION.md`
- **Delta:** `<RUN_DIR>/delta.md`
- **Repo docs:** `docs/merged-design-v2/` (design), `AGENTS.md` (conventions)

## Scope
- Verify the *manifest* is accurate against the live source tree. If any number,
  file, or route is stale, correct it in `00-manifest.md` and note the
  discrepancy — do NOT silently trust the generated JSON.
- Verify the *health metrics* are sane (the heuristics are noisy; sanity-check for
  gross errors, not exact counts).
- Re-derive the entry points, runtime dependency surface, and Prisma surface even
  if the manifest lists them.

## Method
1. Re-run or re-verify `scripts/manifest.ts` and `scripts/metrics.ts` for this run dir.
2. Spot-check inventory: actual file counts, prisma model/enum counts, route scrape.
3. Re-derive the true entry chain from `package.json` bins/scripts → actual files.
4. Record git state (HEAD, branch, dirty, commits) and the changed-surface delta.
5. **Health readout** — report the dashboard numbers against `CONSTITUTION.md`
   thresholds, and flag any metric in Warning/Critical as a *signal* for the
   relevant unit (e.g. type-cleanliness >4/1k → flag B1; long blocks → f flag B1).

## Checklist
- Does the manifest match the source tree? List every discrepancy.
- Are all real entry points captured (CLI, server, desktop/sidecar, frontend)?
- Is the dependency surface complete (runtime + dev + bundled/Tauri sidecar deps)?
- Does the delta.md correctly reflect the git history and inventory movement?
- Are there files/dirs that look like they SHOULD be reviewed but are excluded
  from the manifest (vendored, generated, archived)? Flag them explicitly.
- Health: which dashboard rows are in Warning/Critical per `CONSTITUTION.md`?
  Cross-reference each to the unit that must investigate (B1/B7/B5/C1).

## Output contract
- Update/verify `00-manifest.md` in the run dir.
- Publish a short `00-intake-summary.md` with: verified counts, discrepancy list,
  corrected entry-point chain, a "review surface" list, and the health readout.
- Findings ledger rows go in this file only if they are A0-level (manifest
  integrity / metric baseline). Everything else belongs to B1–B9.
