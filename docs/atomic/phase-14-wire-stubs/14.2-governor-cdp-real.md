# Unit 14.2: ChromeGovernor CDP Real Implementation

**Phase:** 14 | **File:** `src/engines/chrome-governor.ts`
**Depends:** 14.1 CDPTransport | **Produces:** Remove stubCdp, wire real CDP proxy
**Source:** upgrade-02-architecture.md §Modified Engines

## Purpose

Replace the `stubCdp` object in ChromeGovernor (lines 630-658) that throws "implement in Phase 9" with a real CDP proxy backed by `CdpTransportImpl`. This is the single most critical fix — without it, no autonomous execution, conversation sending, or capability execution can work.

## Changes to Existing File

### Remove

Lines 630-658 of `chrome-governor.ts` (the entire `stubCdp` object and its getter).

### Add

```typescript
// New private field
private cdpTransport: CDPTransport | null = null

// New method to inject transport
setCdpTransport(transport: CDPTransport): void {
  this.cdpTransport = transport
}

// Replace get cdp() to return real proxy
get cdp(): CDPProxy {
  if (!this.cdpTransport) {
    throw new EngineError('CDP transport not configured. Call setCdpTransport() first.')
  }
  if (!this._cdpProxy) {
    this._cdpProxy = new CDPProxy(
      this.slaves,
      this.mutexes,
      this.cdpTransport,
      this.eventBus as GovernorEventBus | undefined,
    )
  }
  return this._cdpProxy
}

private _cdpProxy: CDPProxy | null = null
```

## Execution Flow

1. Governor constructed (existing behavior)
2. Caller calls `governor.setCdpTransport(transport)` after construction
3. First access to `governor.cdp` creates CDPProxy with real transport
4. All subsequent CDP operations route through real proxy → transport → BunCdpClient → Chrome
