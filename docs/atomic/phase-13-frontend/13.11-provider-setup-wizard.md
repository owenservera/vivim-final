# Unit 13.11: Provider Setup Wizard (Workspace Selection + Slave Profile Creation)

**Phase:** 13 | **Type:** CREATE | **Status:** DONE

**Depends:** 13.6 Capability API Endpoints, 13.7 WS Agent Command Channel

**Purpose:** First user moment post-install — choose workspace location, then add providers via modal wizard with visible Chrome login flow.

## User Journey

```
App Launch
    │
    ├─ First run? → WorkspaceSetupModal
    │     ├─ Default suggestion: <platform-data>/vivim-workspace
    │     ├─ File picker to choose alternative
    │     └─ Writes workspace hint to ~/.config/vivim/config.json
    │
    └─ Logged in? → If no provider accounts → ProviderSetupWizard
          │
          ├─ Step 1: ProviderSelect
          │     ├─ Grid of provider tiles (ChatGPT, Claude, Gemini)
          │     ├─ Explains what profiles are + isolation benefits
          │     └─ Choose provider → Step 2
          │
          ├─ Step 2: AccountName
          │     ├─ Label: "Account nickname (e.g. 'work', 'personal')"
          │     ├─ Validates: no spaces, unique per provider
          │     └─ Save account → Step 3
          │
          ├─ Step 3: LoginFlow
          │     ├─ Visible Chrome opens to provider login URL
          │     ├─ Modal shows: "Log in, then return here"
          │     ├─ Button: "I've logged in"
          │     └─ On click → Verify + Complete
          │
          └─ Post-Login
               ├─ Kill visible Chrome
               ├─ Relaunch HEADLESS on same profile
               ├─ Verify auth via CDP (cookies + URL check)
               ├─ Update ProviderAccount.profileDir, loginState, debugPort
               └─ Show "Setup Complete" + return to main UI
```

## Implementation Notes

- **Workspace hint storage:** `~/.config/vivim/setup-config.json` (cross-session, read on boot)
- **Profile layout:** `<workspace>/<provider>/<account>/` (matches existing `ProfileAllocator`)
- **Visible Chrome:** Uses `launchChrome({ visible: true, profileDir, extraArgs: [loginUrl] })`
- **Verification:** CDP check for cookies > 0 and non-login URL
- **State persistence:** Update `ProviderAccount.loginState = 'authenticated'`, `profileDir`, `debugPort`
