# Unit 90.6 — Capability API Endpoints

**Phase:** 90 (Frontend Sandbox)
**Depends:** 4.7 (CapabilityResolutionEngine), 5.1 (Server entry)
**Source:** `.kilo/plans/1783690988012-sandbox-frontend-system.md` (Phase 2)

## Interface

```typescript
// src/server/routes/capabilities.ts
GET /api/providers/:id/capabilities?planTier=free
  → CapabilityResolutionEngine.resolve({ providerId, planTier })
  → { capabilities: CapabilityUIContract[] }

GET /api/conversations/:id/capabilities?planTier=free
  → CapabilityResolutionEngine.resolve({ conversationId, planTier })
  → { capabilities: CapabilityUIContract[] }

POST /api/conversations/:id/capabilities/:slug/execute
  → ChromeGovernor.executeCapability(conversationId, slug)
  → Streams progress over WS, returns final result
```

## Store Contract

- Uses `CapabilityResolutionEngine.resolve()` (already exists)
- Uses `ChromeGovernor` for execution (already exists)
- Needs route registration in `src/server/index.ts`

## Gate Criteria

- [ ] `GET /api/providers/:id/capabilities` returns resolved capabilities
- [ ] `GET /api/conversations/:id/capabilities` returns resolved capabilities
- [ ] `POST /execute` triggers real backend execution
- [ ] `bun run typecheck` passes

## Notes

- Resolution exists but is not HTTP-exposed — this is the gap
- Execution is riskiest build item — needs generic harness-module invocation
- Sandbox `capability-store.ts` already calls these endpoints
