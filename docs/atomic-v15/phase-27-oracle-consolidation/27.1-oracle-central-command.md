# 27.1 — oracle-central-command

**Depends:** 26.1–26.6 · **Phase:** 27 · **Closes:** AR-0064, AR-0065, AR-0066 (P2 central)

## Intent
Three `cliCommand`s — `kernel oracle query`, `kernel oracle visibility`, `kernel oracle heal` — are each
emitted by **two** capabilities (an oracle capability and a kernel capability). The audit flags these as
central-command candidates (colliding CLI routes). Give each capability a distinct, canonical CLI command so
the collision clears while both remain reachable.

## Current collision (from audit evidence)
- `kernel oracle query` — defined by `cap:oracle:query` AND `cap:kernel:query`
- `kernel oracle visibility` — defined by `cap:oracle:visibility` AND `cap:kernel:visibility`
- `kernel oracle heal` — defined by `cap:oracle:heal` AND `cap:kernel:heal`

## Fix
In `src/engines/capability-bootstrap.ts`, rename the **kernel** capability cliCommands to a non-colliding
form (e.g. `kernel query`, `kernel visibility`, `kernel heal`) and keep the oracle ones as
`kernel oracle query|visibility|heal`. Optionally add `aliases` for back-compat. Do **not** remove either
capability — both are real.

## Interface (no new capability; edit cliCommand.name only)
```ts
// cap:kernel:query  -> cliCommand.name = 'kernel query'   (was 'kernel oracle query')
// cap:kernel:visibility -> cliCommand.name = 'kernel visibility'
// cap:kernel:heal -> cliCommand.name = 'kernel heal'
```

## Store Contract
- Edit-only; no schema/store change.

## Test Contract
- Re-run `bun run devops audit-arch standard --pass commands` → AR-0064..0066 gone (0 central candidates).
- CLI command names remain unique across the registry (a small unit test can assert no cliCommand.name dup).

## Gate
`bun run devops gate` green; audit P2 central count = 0.
