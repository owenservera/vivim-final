# 28.1 — ui-binding-parity

**Depends:** 26.1–26.6 · **Phase:** 28 · **Closes:** AR-0007…AR-0018 (12 P2 surface)

## Intent
12 capabilities declare `surfaces` including `ui` but provide no `ui:` binding field, so their UI surface is
unbound. Add a real `ui:` binding to each so the declared surface is satisfied.

## Targets (from audit AR-0007…AR-0018)
- `src/canvas/canvas-agent-tools.ts`: `cap:canvas:spawn`, `cap:canvas:dismiss`, `cap:canvas:mutate`,
  `cap:canvas:observe`, `cap:canvas:define`, `cap:canvas:list`
- `src/engines/capability-bootstrap.ts`: `cap:kernel:query`, `cap:kernel:visibility`, `cap:kernel:heal`,
  `cap:config:list`, `cap:config:get`, `cap:config:set`

## Fix
Add to each capability definition:
```ts
ui: { component: '<kebab-from-id>', position: '<context>', order: <n> }
```
Use a sensible `component` slug derived from the capability id and a `position` drawn from the existing
convention (`sidebar` / `tools` / `admin` / `context`). No new UI component code is required by the audit —
the binding declares intent and satisfies the surface; the frontend resolves unknown components gracefully.
