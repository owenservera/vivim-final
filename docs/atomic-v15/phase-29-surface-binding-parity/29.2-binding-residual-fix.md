# 29.2 — binding-residual-fix

**Depends:** 29.1 · **Phase:** 29 · **Closes:** residual AR-0019…AR-0063 after refinement

## Intent
After 29.1 refines the audit, any capability that is **still** flagged "potential new command" is a genuine
gap: it declares an interactive surface yet has no binding on any surface. Add the minimal missing binding
(cliCommand + apiEndpoint, matching the existing convention) so it becomes command-surface-complete.

## Procedure (data-driven)
1. Run `bun run devops audit-arch standard --pass commands` after 29.1.
2. Enumerate residual `Potential new command` ids.
3. For each, edit its capability definition to add `cliCommand` (+ `apiEndpoint`, + `mcpToolName`) using the
   established naming convention (`<category> <verb>`, kebab `mcpToolName`, REST `apiEndpoint`).
4. If an id is API-only/internal by design and was mis-flagged, extend 29.1's rule (do **not** weaken
   silently — document the decision).

## Store Contract
- Edit-only; no schema/store change unless a capability legitimately needs a new store (should be none).

## Test Contract
- Re-run audit → "Potential new command" count = 0.

## Gate
`bun run devops gate` green; audit P2 potential-new count = 0.
