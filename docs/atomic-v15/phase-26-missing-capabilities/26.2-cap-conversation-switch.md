# 26.2 — cap:conversation:switch

**Depends:** none · **Phase:** 26 · **Closes:** AR-0002 (P1 dangling `cap:conversation:switch`)

## Intent
`conversation.switch` NL pattern extracts a `providerId` (e.g. "switch to claude") but `cap:conversation:switch`
is never registered. Implement it to switch the active conversation/provider for the session.

## Interface
```ts
makeCapability(
  {
    id: 'cap:conversation:switch',
    slug: 'conversation_switch',
    name: 'Switch Conversation',
    description: 'Switch the active conversation, by provider or by conversation id.',
    category: 'conversation',
    inputSchema: {
      type: 'object',
      properties: { providerId: { type: 'string' }, sessionId: { type: 'string' } },
    },
    outputSchema: { type: 'object' },
    cliCommand: { name: 'conversations switch', aliases: ['csw'], examples: ['conversations switch --provider=claude'] },
    ui: { component: 'conversation-switcher', position: 'sidebar', order: 3 },
    mcpToolName: 'conversation_switch',
    apiEndpoint: { method: 'POST', path: '/api/conversations/switch' },
    surfaces: ['cli', 'ui', 'api', 'mcp'],
  },
  async (input) => {
    /* resolve target conversation:
       - if sessionId: conversationStore.getConversation(sessionId)
       - else if providerId: conversationStore.listConversations({providerId,limit:1})[0]
       set as active via conversationManager (setActiveSession / setActiveProvider if present) */
  },
)
```

## Store Contract
- `services.conversationStore.getConversation(id)` / `listConversations({providerId})`.
- `services.conversationManager` — use `setActiveSession(id)` / `setActiveProvider(providerId)` if present;
  otherwise record active selection in a module-level `Map` and return it. Never invent a new store.

## Test Contract
- Unit: resolves by `providerId` (returns the most recent conversation for that provider) and by `sessionId`.
- Errors clearly when neither resolves to an existing conversation.
