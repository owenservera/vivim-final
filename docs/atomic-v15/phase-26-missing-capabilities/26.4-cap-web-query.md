# 26.4 — cap:web:query

**Depends:** none · **Phase:** 26 · **Closes:** AR-0001 (P1 dangling `cap:web:query`)

## Intent
`web.query` NL pattern (`catalog.ts`) fetches a URL but `cap:web:query` is never registered. Implement a real
HTTP query capability (GET with optional body→POST) returning status, headers, and a bounded body.

## Interface
```ts
makeCapability(
  {
    id: 'cap:web:query',
    slug: 'web_query',
    name: 'Web Query',
    description: 'Fetch a URL over HTTP(S). GET by default; POST when a body is supplied.',
    category: 'web',
    inputSchema: {
      type: 'object',
      properties: { url: { type: 'string' }, body: { type: 'string' }, method: { type: 'string' } },
      required: ['url'],
    },
    outputSchema: { type: 'object' },
    cliCommand: { name: 'web query', aliases: ['wq'], examples: ['web query https://example.com'] },
    ui: { component: 'web-query', position: 'tools', order: 1 },
    mcpToolName: 'web_query',
    apiEndpoint: { method: 'POST', path: '/api/web/query' },
    surfaces: ['cli', 'ui', 'api', 'mcp'],
  },
  async (input) => {
    /* fetch(url, {method, body}) -> {status, headers, body(truncated to ~50kb)} */
  },
)
```

## Store Contract
- No DB. Uses global `fetch` (Bun). Validate `url` is http(s); reject otherwise.
- Bound body to a safe size; return `truncated: true` when clipped.

## Test Contract
- Unit (mock global fetch): GET returns status+body; POST sends body; non-http(s) url rejected; oversized
  body flagged `truncated`.

## Gate
`bun run devops gate` green; audit-arch commands P1 drops by 1.
