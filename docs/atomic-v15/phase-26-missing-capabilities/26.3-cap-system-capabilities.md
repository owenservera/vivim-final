# 26.3 — cap:system:capabilities

**Depends:** none · **Phase:** 26 · **Closes:** AR-0003 (P1 dangling `cap:system:capabilities`)

## Intent
`system.capabilities` NL pattern ("what can you do") binds to `cap:system:capabilities`, which is never
registered. Implement it as a machine-oriented listing of all registered capabilities (id, name, category,
surfaces, cli command) for the requesting surface.

## Interface
```ts
makeCapability(
  {
    id: 'cap:system:capabilities',
    slug: 'system_capabilities',
    name: 'List Capabilities',
    description: 'List all registered capabilities and their invocation surfaces.',
    category: 'system',
    inputSchema: { type: 'object', properties: {} },
    outputSchema: { type: 'array' },
    cliCommand: { name: 'capabilities', aliases: ['caps'], examples: ['capabilities'] },
    ui: { component: 'capability-list', position: 'admin', order: 1 },
    mcpToolName: 'list_capabilities',
    apiEndpoint: { method: 'GET', path: '/api/capabilities' },
    surfaces: ['cli', 'ui', 'api', 'mcp'],
  },
  async () => {
    /* registry.list() -> [{id,name,category,surfaces,cli:cliCommand?.name}] */
  },
)
```

## Store Contract
- `registry.list(): UnifiedCapability[]` (closure).
- No DB writes.

## Test Contract
- Unit: returns every registered capability with `id`, `name`, `category`, `surfaces`.
- `cap:help` and `cap:system:capabilities` are distinct (help=grouped user view; capabilities=raw list).
