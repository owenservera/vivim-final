# 26.6 — cap:schedule:register

**Depends:** none · **Phase:** 26 · **Closes:** AR-0006 (P1 dangling `cap:schedule:register`)

## Intent
`schedule.register` NL pattern extracts a `cron` + `action` (e.g. "every monday …") but `cap:schedule:register`
is never registered. Implement it to register a real schedule that fires a target capability on a cron.

## Interface
```ts
makeCapability(
  {
    id: 'cap:schedule:register',
    slug: 'schedule_register',
    name: 'Register Schedule',
    description: 'Register a recurring schedule that triggers a capability.',
    category: 'schedule',
    inputSchema: {
      type: 'object',
      properties: { cron: { type: 'string' }, action: { type: 'string' }, name: { type: 'string' } },
      required: ['cron', 'action'],
    },
    outputSchema: { type: 'object' },
    cliCommand: { name: 'schedule register', aliases: ['sreg'], examples: ['schedule register "0 9 * * 1" cap:workflow:create_newsletter'] },
    ui: { component: 'schedule-builder', position: 'tools', order: 3 },
    mcpToolName: 'register_schedule',
    apiEndpoint: { method: 'POST', path: '/api/schedules' },
    surfaces: ['cli', 'ui', 'api', 'mcp'],
  },
  async (input) => {
    /* validate cron (lenient) + that `action` is a registered capability id
       store in module-level Map<string, ScheduleDef> keyed by generated id */
  },
)
```

## Store Contract
- Validate `action` against `registry.list()` ids (closure) — reject unknown capability.
- Persist in a module-level `Map` (process-scoped); return `{id, cron, action, nextRun?}`.
- If a scheduler service exists later, this is the natural integration point.

## Test Contract
- Unit: valid cron+action returns an id; unknown `action` capability rejected; malformed cron rejected.
