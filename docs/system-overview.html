Architecture Principles

Nine non-negotiable rules from the design spec. They are enforced, not suggested — drift fails the gate.

👑
P1

Governor Canon

Only ChromeGovernor touches CDP. No engine imports a raw CDP client.

📜
P2

Store Contracts

Engines depend on storage contracts, never on concrete impl/* classes.

🔬
P3

Research-First

No implementation without a classified research report.

🚪
P4

Phase Gates

Phase N requires phase N−1 complete before it can start.

🗄️
P5

DB-Only Parsers

Parser logic loads only from the DB (logic_type=inline).

🎛️
P6

One Entry Point

Every op is a UnifiedCapability; CLI & UI are thin NL shells.

🪟
P7

Surface Parity

CLI = API = SDK = UI = MCP. A capability on one is on all.

🧬
P8

Node Layer v2

Universal Node DB: every message is a node with version chains.

🛡️
P9

Invariant Guards

devops invariants check is a hard boundary in the gate.

03

One Entry Point, Four Surfaces

Every operation is a UnifiedCapability. CLI and frontend are thin natural-language shells — they all converge on the same two endpoints. Build a capability once, it ships everywhere.

UnifiedCapability Registry

POST /api/interpret → POST /api/capabilities/:id/execute

💻
CLIThin client to the running server
🌐
APIREST + WebSocket events
🧩
MCPTool server for agents
🎨
UIHot-swappable capability slots

Adding a capability

Register it in a *caps.ts module with surfaces: ['cli','ui','api'], add NL patterns to catalog.ts, and it resolves on all four transports automatically.

Verify-cross-surface

devops verify-cross-surface checks every capability resolves across CLI name, API path, MCP tool name, and UI slot id — parity is a gate, not a hope.

Parser fallback chain: provider/001 → generic/001 → system/001. If a provider's own parser misses, the format-agnostic parser catches it; the raw-text parser never throws.
