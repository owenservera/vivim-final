# Unit 3.1 — Conversation State Persistence Across Turns

**Phase:** 3 | **ID:** 3.1 | **Dependencies:** 2.8

## Problem

Multi-turn conversations require the Chrome page to maintain its state (provider conversation ID, scroll position, loaded context) between sends. Currently, each `send()` call assumes the page is in the same state as the previous send, but SPAs can reload, navigate, or clear state between turns.

## Spec

### State Recovery Check

Before each send, verify the page is still in the expected state:

```typescript
// In ConversationManager.send(), after ENSURE:

// [4.5] VERIFY PAGE STATE
const pageState = await this.governor.cdp.getPageState(slaveId)
const providerUrl = PROVIDER_URLS[conv.providerId]

// If page navigated away or reloaded, re-navigate
if (!pageState.url.startsWith(providerUrl) || pageState.readyState !== 'complete') {
  await this.governor.cdp.send(slaveId, 'Page.navigate', { url: providerUrl })
  await this.waitForPageLoad(slaveId, 10_000)
  
  // Verify login still active
  const loggedIn = await this.checkLoginState(slaveId, conv.providerId)
  if (!loggedIn) {
    throw new EngineError(`Session expired for ${conv.providerId}. Re-login required.`)
  }
}
```

### Conversation Context Tracking

Store the provider's internal conversation ID (if available) to detect when the SPA creates a new conversation:

```typescript
// After each successful send + capture, extract provider conversation ID
const providerConvId = await this.extractProviderConversationId(slaveId, conv.providerId)
if (providerConvId && providerConvId !== conv.providerConvId) {
  // Provider started a new conversation — update our record
  await this.store.updateConversation(conversationId, {
    providerConvId,
  })
}
```

### Message Context for Multi-Turn

When sending message N, the provider already has messages 1..N-1 in its DOM. VIVIM doesn't need to re-send history. But if the page reloaded, the provider lost its history and VIVIM may need to re-navigate to the correct conversation thread.

## Test

```typescript
test('conversation persists across 3 turns', async () => {
  const r1 = await cm.send(conv.id, 'What is 2+2?')
  expect(r1.ok).toBe(true)
  
  await delay(2000) // wait between turns
  
  const r2 = await cm.send(conv.id, 'Now multiply by 3')
  expect(r2.ok).toBe(true)
  
  await delay(2000)
  
  const r3 = await cm.send(conv.id, 'What was the first number?')
  expect(r3.ok).toBe(true)
  // The response should reference "2+2=4" if the provider maintained context
})
```
