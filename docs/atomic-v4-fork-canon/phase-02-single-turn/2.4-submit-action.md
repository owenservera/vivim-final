# Unit 2.4 — Provider-Specific Submit Action via CDP

**Phase:** 2 | **ID:** 2.4 | **Dependencies:** 2.3

## Problem

After typing the message, the submit action varies by provider:
- ChatGPT: Click `[data-testid='send-button']` or press Enter (textarea with event listeners)
- Claude: Click `button[aria-label='Send Message']` or press Enter (contenteditable)
- Gemini: Click `button.send-button` (Quill doesn't auto-submit on Enter)

Some providers have `send_method: "both"` in their manifest, meaning either click or Enter works. Others require specific methods.

## Spec

### Submit Implementation

```typescript
async function submitMessage(
  governor: ChromeGovernor,
  slaveId: string,
  endpoint: { send_button?: string; send_method?: string },
  composerSelector: string,
): Promise<void> {
  const method = endpoint.send_method ?? 'both'
  const buttonSelector = endpoint.send_button

  // Strategy 1: Click send button (most reliable)
  if (buttonSelector && (method === 'click' || method === 'both')) {
    const safeButton = JSON.stringify(buttonSelector)
    const result = await governor.cdp.send(slaveId, 'Runtime.evaluate', {
      expression: `(() => {
        const btn = document.querySelector(${safeButton});
        if (btn) { btn.click(); return true; }
        return false;
      })()`,
      returnByValue: true,
    })
    if (result?.result?.value === true) return
  }

  // Strategy 2: Press Enter key
  if (method === 'enter' || method === 'both') {
    await governor.cdp.send(slaveId, 'Input.dispatchKeyEvent', {
      type: 'keyDown', key: 'Enter', code: 'Enter',
      windowsVirtualKeyCode: 13,
    })
    await governor.cdp.send(slaveId, 'Input.dispatchKeyEvent', {
      type: 'keyUp', key: 'Enter', code: 'Enter',
      windowsVirtualKeyCode: 13,
    })
    return
  }

  // Strategy 3: Submit form
  if (method === 'submit') {
    const safeComposer = JSON.stringify(composerSelector)
    await governor.cdp.send(slaveId, 'Runtime.evaluate', {
      expression: `document.querySelector(${safeComposer})?.form?.submit()`,
    })
    return
  }

  // Fallback: try Enter
  await governor.cdp.send(slaveId, 'Input.dispatchKeyEvent', {
    type: 'keyDown', key: 'Enter', code: 'Enter',
  })
  await governor.cdp.send(slaveId, 'Input.dispatchKeyEvent', {
    type: 'keyUp', key: 'Enter', code: 'Enter',
  })
}
```

### Endpoint Manifest Fields

From `seeds/providers/*.json`:
```json
{
  "send_method": "both",     // "click" | "enter" | "submit" | "both"
  "send_button": "[data-testid='send-button']"
}
```

These are stored in `provider_endpoint.selectors_json` and parsed as:
```typescript
const selectors = JSON.parse(endpoint.selectors_json)
const sendButton = selectors.send_button
const sendMethod = endpoint.send_method
```

### ChatGPT-Specific Consideration

ChatGPT's textarea has a React `onKeyDown` handler that listens for Enter (without Shift). The `Input.dispatchKeyEvent` approach works but must include proper `code` and `windowsVirtualKeyCode` for React to recognize it.

### Claude-Specific Consideration

Claude uses a contenteditable div with `shift+enter` for newline and `enter` for send. The native `dispatchKeyEvent` works.

### Gemini-Specific Consideration

Gemini's Quill editor requires clicking the send button — Enter doesn't submit. The `send_method` should be `"click"` for Gemini.
