# Unit 7.6 — SQLite Pragma Tuning + WAL Mode

**Phase:** 7 | **ID:** 7.6 | **Dependencies:** none

## Problem

SQLite runs in default journal mode (DELETE). Under concurrent writes (message storage + health ticks + trace logs), write lock contention causes `SQLITE_BUSY` errors and latency spikes.

## Re-Programmable Design

A **DbPragmaPolicy** controls all SQLite configuration:

```typescript
interface DbPragmaPolicy {
  journalMode: 'DELETE' | 'WAL' | 'TRUNCATE' | 'MEMORY'
  synchronous: 'OFF' | 'NORMAL' | 'FULL' | 'EXTRA'
  cacheSize: number           // negative = KB, positive = pages
  tempStore: 'DEFAULT' | 'FILE' | 'MEMORY'
  mmapSize: number            // memory-mapped I/O size (bytes)
  busyTimeoutMs: number       // how long to wait on lock
  walAutocheckpoint: number   // WAL checkpoint threshold (frames)
  foreignKeys: boolean
}
```

### Implementation

```typescript
// src/storage/db.ts — add pragma configuration at connection time

import type { DbPragmaPolicy } from '../schema/config.js'

const DEFAULT_PRAGMAS: DbPragmaPolicy = {
  journalMode: 'WAL',
  synchronous: 'NORMAL',
  cacheSize: -64000,        // 64MB cache
  tempStore: 'MEMORY',
  mmapSize: 268435456,      // 256MB mmap
  busyTimeoutMs: 5000,
  walAutocheckpoint: 1000,
  foreignKeys: true,
}

export async function configurePrisma(db: CapStoreDb, policy?: Partial<DbPragmaPolicy>): Promise<void> {
  const pragmas = { ...DEFAULT_PRAGMAS, ...policy }

  // Execute via $executeRawUnsafe (Prisma doesn't have a pragma API)
  await db.prisma.$executeRawUnsafe(`PRAGMA journal_mode = ${pragmas.journalMode}`)
  await db.prisma.$executeRawUnsafe(`PRAGMA synchronous = ${pragmas.synchronous}`)
  await db.prisma.$executeRawUnsafe(`PRAGMA cache_size = ${pragmas.cacheSize}`)
  await db.prisma.$executeRawUnsafe(`PRAGMA temp_store = ${pragmas.tempStore}`)
  await db.prisma.$executeRawUnsafe(`PRAGMA mmap_size = ${pragmas.mmapSize}`)
  await db.prisma.$executeRawUnsafe(`PRAGMA busy_timeout = ${pragmas.busyTimeoutMs}`)
  await db.prisma.$executeRawUnsafe(`PRAGMA wal_autocheckpoint = ${pragmas.walAutocheckpoint}`)
  await db.prisma.$executeRawUnsafe(`PRAGMA foreign_keys = ${pragmas.foreignKeys ? 'ON' : 'OFF'}`)

  // Verify settings took effect
  const journalMode = await db.prisma.$queryRawUnsafe<{ journal_mode: string }[]>(
    'PRAGMA journal_mode'
  )
  if (journalMode[0]?.journal_mode?.toLowerCase() !== pragmas.journalMode.toLowerCase()) {
    console.warn(`[db] Failed to set journal_mode to ${pragmas.journalMode}, got ${journalMode[0]?.journal_mode}`)
  }
}

// In createServerWithEngines():
const pragmaPolicy = await configStore.get<DbPragmaPolicy>('db.pragmas')
await configurePrisma(db, pragmaPolicy ?? undefined)
```

### WAL Benefits

| Mode | Concurrent Readers | Concurrent Writers | Crash Safety | Speed |
|------|-------------------|-------------------|--------------|-------|
| DELETE (default) | 1 | 1 | Full | Slow |
| **WAL** | **Unlimited** | **1** | **Full** | **Fast** |
| MEMORY | Unlimited | 1 | None | Fastest |

WAL mode allows unlimited concurrent readers while one writer writes. This eliminates read blocking during message storage, health ticks, and trace logging.

### Busy Timeout

With `busy_timeout = 5000`, SQLite waits up to 5 seconds to acquire a write lock before returning `SQLITE_BUSY`. This handles transient contention without error propagation.
