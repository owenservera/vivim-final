# Unit v7.12 — Canvas attach points: HTTP router + WS protocol v2 (P2 attach)

**Source:** vision §3 (anatomy), integration-source README §"where the canvas attaches"
**Design Doc:** v7 tracker §v7.12
**Depends on:** v7.1–v7.10
**Produces:** `src/server/canvas-router.ts` + `src/server/canvas-ws.ts` (spec; wiring PENDING).

## Context

The canvas attaches to the existing server host (Part 3 of the
integration surface): `server/index.ts` + `server/websocket.ts`. The
canvas never replaces the server; it is *mounted* into it. All
canvas HTTP/WS traffic is just capability calls + mirror events,
already expressible through the v7.9 capability plane.

## Attach map

```
vivim-home canvas (pure HTML shell)
        │  spawn/mutate/observe (capabilities)
        ▼
   CanvasEngine.registerCapabilities(registry)   ← v7.9
        │  routes to: mounter / mirror / oracle / designer
        ▼
   server/index.ts  → canvas-router.ts
        GET  /api/canvas/definitions      → cap:canvas_list
        POST /api/canvas/definitions      → cap:canvas_define
        POST /api/canvas/spawn            → cap:canvas_spawn
        DELETE /api/canvas/instance/{id}    → cap:canvas_dismiss
        POST /api/canvas/instance/{id}/mutate → cap:canvas_mutate
        GET  /api/canvas/observe           → cap:canvas_observe
   server/websocket.ts → canvas-ws.ts (protocol v2)
        canvas:spawn | canvas:dismiss | canvas:mutate | canvas:state
```

## Interface (target)

```typescript
// src/server/canvas-router.ts
export function registerCanvasRoutes(
  app: Router,
  registry: UnifiedCapabilityRegistry,
): void

// src/server/canvas-ws.ts
export function attachCanvasWs(
  wss: WebSocketServer,
  engine: CanvasEngine,
): void
```

The router maps each HTTP path to `registry.execute('cap:canvas:*', ...)`;
the WS bridge forwards `canvas:*` frames to `engine.bridge` + `mirror`.
No new authz model — requests carry the same `CapabilityContext`
the rest of the system uses, and enforcement stays in the bridge (v7.5).

## Status: [x] implemented

The engines (v7.1–v7.10) are complete and tested. `CanvasEngine` is wired
into `createServerWithEngines`: `canvas-router.ts` maps `/api/canvas/*` to
the canvas capability plane, and `canvas-ws.ts` owns the sandbox-bridge
attach/detach lifecycle over the existing WS channel. Local-first
`InMemoryCanvasStore` is the shipped backing; a Prisma impl is a follow-up
to v7.1 (does not change any engine contract).
