# Unit v7.3 — Core primitive set (closed, composable)

**Source:** vision §1.2, §3.2 (P6)
**Design Doc:** v7 tracker §v7.3
**Depends on:** v7.1
**Produces:** `PrimitiveKind` (closed), `CorePrimitiveRegistry`, `PrimitiveProvider`, `fnPrimitive`, `PrimitiveReader`.

---

## Context

The system ships with a robust, **closed** set of core primitives —
workspace, projects, knowledge, agents, providers, conversations. Users
and agents *compose* these primitives into layers; they do not reinvent
them. Primitives are the vocabulary; layers are the sentences. New
capability comes from new *compositions*, not new *frameworks*.

## Interface — `src/canvas/primitives.ts`

```typescript
export type PrimitiveKind =
  | 'workspace' | 'projects' | 'knowledge'
  | 'agents' | 'providers' | 'conversations'

export interface PrimitiveProvider {
  readonly kind: PrimitiveKind
  read(query: Record<string, unknown>): Promise<unknown>
}

export class CorePrimitiveRegistry {
  register(provider: PrimitiveProvider): void
  unregister(kind: PrimitiveKind): void
  has(kind: PrimitiveKind): boolean
  kinds(): readonly PrimitiveKind[]
  reader(): PrimitiveReader          // what layers/canvas consume
  getProvider(kind): PrimitiveProvider | null
}

export function fnPrimitive(
  kind: PrimitiveKind,
  fn: (query: Record<string, unknown>) => Promise<unknown>,
): PrimitiveProvider
```

The composition seam: `fnPrimitive` wires ANY store/engine into the
closed primitive set without inventing a new framework. The oracle and
layers consume `CorePrimitiveRegistry.reader()`.

## Acceptance Criteria

1. `PrimitiveKind` is the exact closed set; `kinds()` returns it.
2. `register` rejects a duplicate kind; `reader().read` delegates to provider.
3. `fnPrimitive` adapts a plain async fn into a `PrimitiveProvider`.
4. Adding a *new* primitive is contract-stable (no framework change) — verified by wiring a fake store via `fnPrimitive`.
5. `bun test tests/unit/canvas` passes.
