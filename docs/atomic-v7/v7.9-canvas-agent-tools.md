## Context

Every canvas operation (spawn, dismiss, mutate, observe, define,
list) is a **capability** — simultaneously a CLI command, a UI
action, a workflow node, an **MCP tool**, and an API endpoint. An
agent drives the canvas through the exact same surface the user does.
There is no "human UI" and "agent API"; there is one capability
plane. Agents are first-class inhabitants of the canvas, not bolt-ons.

## Interface — `src/canvas/canvas-agent-tools.ts`

```typescript
export interface CanvasCapabilityServices {
  registry: CanvasRegistry
  mounter: LayerMounter
  mirror: CanvasMirror
  oracle: OracleReader
  designer: CanvasDesigner
}

export function registerCanvasCapabilities(
  registry: UnifiedCapabilityRegistry,
  svc: CanvasCapabilityServices,
): void
```

Capabilities (all five surfaces, `tags:['canvas']`):

| slug | maps to |
|------|---------|
| `canvas_spawn` | `mounter.spawn` |
| `canvas_dismiss` | `mounter.dismiss` |
| `canvas_mutate` | `mirror.pushOptimistic` |
| `canvas_observe` | `oracle.visibility()` / `oracle.buildManifest()` |
| `canvas_define` | `designer.publish` |
| `canvas_list` | `registry.list` + `mounter.list` |

## Acceptance Criteria

1. After bootstrap, `registry.list({ category:'canvas' }).length === 6`.
2. Each is exported to MCP (`exportForMcp` includes `canvas_*`).
3. `execute('cap:canvas:spawn', {definitionId}, ctx)` → `mounter.spawn`.
4. `canvas_mutate` → `mirror.pushOptimistic(instanceId, regionId, state)`.
5. `canvas_observe` op switch returns oracle visibility or manifest.
6. `bun test tests/unit/canvas` passes; canvas caps covered.
