# Unit v7.11 — Canvas security model (inline-script rejection + sandbox enforcement)

**Source:** vision §3.3 (P8), §4 (table), §7 (non-negotiable #2)
**Design Doc:** v7 tracker §v7.11
**Depends on:** v7.1, v7.5
**Produces:** structural guarantees in `schema.ts` + `capability-bridge.ts`.

---

## Context

Layers are data, sandboxed, and swapped on demand (non-negotiable
#2). A user-published or agent-published layer cannot exfiltrate,
cannot escalate, cannot touch the kernel. The shell is a hypervisor,
not an open `eval`.

## Mechanisms (implemented)

1. **No inline `<script>`** — `assertNoInlineScript` (P8) rejects at
   `define` time (P1) AND the host must reject at render time.
   `sandbox.allowInlineScript` is structurally `false`.
2. **Capability whitelist** — `canUseCapability(def, slug)` gates every
   `bridge:capability:request`; denied → `SandboxPermissionError`,
   never executed.
3. **No raw network** — `sandbox.allowNetwork:false` by default;
   all I/O flows through the bridge → `CapabilityExecutor` /
   `PrimitiveReader` contracts. The layer cannot open its own channel.
4. **Governor Canon (P7)** — no canvas engine imports
   `BunCdpClient` / `chrome-governor`. Mutation is performed by
   whatever `CapabilityExecutor` the engine was wired with (the
   Governed authority), never by the layer itself.
5. **Least-privilege by default** — `defaultSandbox()` CSP, no
   capabilities, no network; `CanvasDesigner.sandboxFor` grants only
   the capabilities a draft's bindings reference.

## Acceptance Criteria

1. `assertNoInlineScript({html:'<script>x</script>'})` throws.
2. `canUseCapability(def, ungranted)` → false (bridge denies).
3. No canvas engine imports chrome-governor / BunCdpClient (invariant B).
4. `defaultSandbox()` has `allowInlineScript:false`, `allowNetwork:false`.
5. `bun test tests/unit/canvas` passes; `bun run devops invariants check` clean.
