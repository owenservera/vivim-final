# Unit 2.3 — Wire UIAutomator into devops CLI

**Source:** PRD R6, R7; session output
**Depends on:** none (new code, no deps on Phase 1)
**Produces:** `bun run devops automate <action>` commands working

---

## Context

We built `UIAutomator` + `automation-router.ts` + `automate.ts` CLI in this session. The
automation engine is working but not wired into the `devops` CLI. The agent needs to be able
to drive the frontend UI from the devops loop.

## Interface

### New commands in `devops/index.ts`
```typescript
case 'automate': {
  // Delegate to src/cli/commands/automate.ts
  const proc = spawn('bun', ['run', join(process.cwd(), 'src', 'cli', 'commands', 'automate.ts'), ...args], { stdio: 'inherit' })
  proc.on('close', (code) => process.exit(code ?? 0))
  break
}
```

### Commands available
| Command | Action |
|---------|--------|
| `automate navigate <url>` | Navigate browser to URL |
| `automate type <selector> <text>` | Type text into element |
| `automate click <selector>` | Click element |
| `automate text <selector>` | Get element text |
| `automate value <selector>` | Get input value |
| `automate exists <selector>` | Check element exists |
| `automate screenshot` | Take screenshot |
| `automate page` | Get page content |
| `automate reset` | Reset automator connection |

## Steps
1. Add `automate` case to `devops/index.ts` switch statement
2. Verify `bun run devops automate page` returns structured JSON
3. Verify `bun run devops automate navigate http://localhost:5173` works
4. Update `devops/SKILL.md` to document the automate commands
5. Commit

## Acceptance
- `bun run devops automate page` returns `{ ok: true, ... }` or `{ ok: false, error: 'CDP not connected' }`
- `bun run devops automate navigate http://localhost:5173` works
- Commands return structured JSON (not raw errors)
- `devops/SKILL.md` documents the automate commands
