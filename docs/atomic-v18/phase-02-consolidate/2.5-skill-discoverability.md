# Unit 2.5 — Add skill descriptions + skill index

**Source:** PRD R11, R12; skills upgrade design P5
**Depends on:** 2.1, 2.2, 2.4 (descriptions + index need final skill list)
**Produces:** All skills have descriptions; `docs/SKILLS.md` exists

---

## Context

5 skills have empty `description` fields in their frontmatter:
- `devops-research`
- `devops-roadmap`
- `devops-generators`
- `source-audit`
- `arch-audit`

Without descriptions, the agent can't auto-trigger skills based on user intent. Also, no
skill index exists for the agent to route user intents to the right skill.

## Interface

### Add descriptions to frontmatter
Each skill gets a 1-2 sentence description:
- `devops-research`: "Research-first intelligence layer with web search, synthesis, and convergence loops"
- `devops-roadmap`: "Research-first roadmap with truth scanning, gap discovery, and interview protocol"
- `devops-generators`: "Taxonomy generation (PlatformCatalog + ProviderCapabilityTaxonomy)"
- `source-audit`: "P0-P3 source-code audit with 4 depth tiers"
- `arch-audit`: "Module-graph architecture audit (cycles, layering, coupling, boundaries)"

### Create `docs/SKILLS.md`
Skill index mapping user intents → skills:

| User Intent | Skill |
|-------------|-------|
| "implement the next unit" / "continue" / "keep going" | `devops` |
| "research X" / "deep dive on Y" | `devops-research` |
| "plan the roadmap" / "what should we build?" | `devops-roadmap` |
| "generate taxonomy for X" | `devops-generators` |
| "audit the codebase" / "find bugs" | `source-audit` |
| "audit the architecture" / "find cycles" | `arch-audit` |
| "build an engine" | `devops` (Build Strategies) |
| "write tests" / "fix flaky tests" | `vivim-testing` |
| "build frontend UI" / "add a button" | `vivi-frontend` |
| "set up Prisma" / "create a migration" | `prisma-workflow` |
| "automate the browser" / "type in the UI" | `devops` (automate commands) |

## Steps
1. Add `description` to each of the 5 skills missing them
2. Create `docs/SKILLS.md` with the intent→skill mapping
3. Verify the agent can load any skill by intent
4. Commit

## Acceptance
- All 9 skills have non-empty `description` in frontmatter
- `docs/SKILLS.md` exists with intent→skill mapping
- Agent can route user intents to correct skills
