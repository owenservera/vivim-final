# vivim v11 — User Manual

> Local-first AI conversation platform. Every action is a **UnifiedCapability**;
> the CLI, web UI, and MCP surface are thin shells over two universal API routes:
> `POST /api/interpret` and `POST /api/capabilities/{id}/execute`.

## 1. Install & run

```bash
bun install
bun run prisma:generate
bun run migrate          # applies schema migrations
bun run dev              # starts CapStoreServer on :8787 + web UI
```

Open the web UI at `http://localhost:8787`. First run launches the **onboarding
flow** (see §4).

## 2. The two-route mental model

| Goal | Route | Example |
|------|-------|---------|
| "I want to…" in plain words | `POST /api/interpret` | `{"text":"summarize this page"}` → `{capabilityId, params}` |
| Run a capability | `POST /api/capabilities/{id}/execute` | streams SSE `delta`/`done` events |

All surfaces (CLI, UI, MCP) map down to these two calls. You never hand-write
transport-specific glue — you add a capability, and the CLI command, UI button,
and MCP tool are generated from its `surfaces: ['cli','ui','api']` declaration.

## 3. CLI quick start

```bash
# Natural-language interpretation
bun run src/cli/index.ts interpret "list my conversations"

# Execute a capability by id
bun run src/cli/index.ts caps exec cap:conversation:list

# Capability catalog
bun run src/cli/index.ts caps list
```

See the auto-generated **Command Reference** (§7) for the full command surface.

## 4. Onboarding & surfaces

The first-run wizard covers: welcome → connect provider → (cloud consent, only
when not airgapped) → run a sample task. You can **skip** anytime; **reopen** from
settings. Under **airgap** mode the wizard defaults to the local provider and
skips the cloud-consent step entirely.

## 5. Privacy, consent & airgap

- **Airgap** (default): autonomous goals resolve to the `local` LLM provider.
  Cloud providers are never contacted without explicit consent.
- **Consent gate**: any goal that would call a cloud `llmProvider` requires
  `consentCheck()` to return `true`; otherwise it fails with `ConsentViolationError`.
- **Sovereign data**: enable DB-at-rest encryption (`CAP_STORE_ENCRYPT_DB=1`) and
  schedule encrypted backups. See `docs/atomic-v11` phases 36.1–36.3.

## 6. Device pairing & backups

- **Pairing** (`/surfaces/device-pairing`): pair this instance with a second device;
  confirm the pairing code on both sides. Pure-logic reducers keep UI in sync.
- **Backups** (`BackupScheduler`): daily/weekly cadence, keep-N retention, encrypted
  archives, one-command restore.

## 8. Performance & tuning

Run the benchmark suite to track p50/p95 latency and catch regressions:

```bash
bun run bench
```

Baselines are stored in `bench/baseline.json`; a run fails CI if any scenario's
p95 exceeds 1.5× the recorded baseline.

(generate/refresh with `bun run docs:openapi`).
