# Unit 2.4 — Server-Bootstrap Dispatcher (bootstrap.ts)

**Depends on:** 2.1, 2.2, 2.3
**Produces:** `devops/runtime-test/bootstrap.ts`
**Source:** `docs/atomic-runtime/RUNTIME-OS-DESIGN.md` §3.3

## Problem
The agent needs one call to bring the whole stack to a known-good state (up + healthy) so `engage`
(3.1) can assume a running world. Scattered launchers aren't enough.

## Approach
- `bootstrap.ts`: `up()` → supervisor.start() (2.1) → preflight.run() (2.3); retry with backoff up
  to N; on fail, return structured error. `down()` → supervisor.stop().
- Idempotent: calling `up()` when already healthy is a no-op.
- Pluggable profile: `minimal` (backend+slave) vs `full` (+frontend via 2.2).

## Acceptance
- `bootstrap.up({profile:'minimal'})` resolves only when preflight green.
- Double `up()` is a no-op (no second server).

## Tests
- `tests/integration/runtime-test/bootstrap.test.ts`: idempotent up/down with mock supervisor.
