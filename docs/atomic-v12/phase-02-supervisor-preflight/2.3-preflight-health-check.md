# Unit 2.3 — Pre-flight Health Check (preflight.ts)

**Depends on:** 1.1, 2.1, 2.2
**Produces:** `devops/runtime-test/preflight.ts`
**Source:** `docs/atomic-runtime/RUNTIME-OS-DESIGN.md` §3.3

## Problem
Before each loop the agent must verify the world: DB reachable + WAL on, server up, slave attached,
Governor connected. Without a pre-flight the loop wastes cycles on a broken substrate.

## Approach
- `preflight.ts` checks (in order): prisma connected + `journal_mode=wal`; `GET /api/health` 200;
  slave registered (provider count > 0); Governor CDP session attached (1.2).
- Returns `{ok, checks[]}` with per-check detail; `ok=false` lists the first failing gate.
- Expose `preflight.run()` used by the loop (6.1) and `runtime` meta-cmd.

## Acceptance
- On a healthy stack `preflight.run().ok === true` with all checks green.
- After killing the server, `preflight.run().ok === false` and names the dead check.

## Tests
- `tests/unit/runtime-test/preflight.test.ts`: mock each check fail → correct gate reported.
