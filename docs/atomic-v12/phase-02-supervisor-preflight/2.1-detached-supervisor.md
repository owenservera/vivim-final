# Unit 2.1 — Detached Supervisor (supervisor.ts)

**Depends on:** 1.1
**Produces:** `devops/runtime-test/supervisor.ts`
**Source:** `docs/atomic-runtime/RUNTIME-OS-DESIGN.md` §3.1

## Problem
The loop must launch the backend + slave as detached child processes so opencode/claude-code keep
control while the stack runs. There is no supervisor today; `bun run serve` blocks the tool (120s
hang observed). Without this, no autonomous cycle can start.

## Approach
- `supervisor.ts`: spawn `bun run serve` (backend) + `bun run slave --cdp` (provider slave) detached,
  capture pids, stream logs, expose `start()`, `stop()`, `restart()`, `status()`.
- Wait for health endpoint (`GET /api/health` or `/api/capabilities`) before resolving `start()`.
- On `stop()`, send SIGTERM then force-kill after timeout; ensure child pids reaped.
- Use the fixed `bun` path (`C:\Users\VIVIM.inc\AppData\Roaming\npm\bun.ps1`).

## Acceptance
- `supervisor.start()` resolves only when server responds 200.
- `supervisor.restart()` performs a clean WAL restart (relies on 1.1) ×5 without error.
- `supervisor.stop()` leaves no orphan `bun` processes.

## Tests
- `tests/integration/runtime-test/supervisor.test.ts`: start/stop/restart with a mock server.
- Manual: 5× restart loop clean.
