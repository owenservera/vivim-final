# Unit 3.3 — Discover Frontend (discover-frontend.ts)

**Depends on:** 3.1
**Produces:** `devops/runtime-test/discover-frontend.ts`
**Source:** `docs/atomic-runtime/RUNTIME-OS-DESIGN.md` §3.5

## Problem
FRONTEND=BACKEND means every backend capability with `surface: ui` must have a bound frontend part,
and every frontend action must map to a backend capability. Orphan ui caps (backend has ui surface but
no component) and dead slugs (component references a missing capability) must be found automatically.

## Approach
- `discover-frontend.ts`: static-scan `src/frontend` (or UI registry) for `ui.component` bindings +
  slugs; compare to backend model (3.2).
- Flag: orphan ui caps (backend ui surface, no frontend part), dead slugs (frontend ref, no backend cap).
- Use `engage` session to confirm a rendered component exists for a sampled ui cap (live check).

## Acceptance
- On current code, discovers the `ui.component` set verified in baseline (FRONTEND=BACKEND green).
- Injecting a dead slug is flagged in the diff.
- `bunx tsc --noEmit` clean.

## Tests
- `tests/integration/runtime-test/discover-frontend.test.ts`: orphan + dead-slug detection.
