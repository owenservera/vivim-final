# Unit 3.2 — Discover Backend (discover-backend.ts)

**Depends on:** 3.1, 1.3
**Produces:** `devops/runtime-test/discover-backend.ts`
**Source:** `docs/atomic-runtime/RUNTIME-OS-DESIGN.md` §3.5

## Problem
The agent must learn the live backend's real protocol (endpoints, capability shapes, provider taxonomy)
without a human. `GET /api/capabilities` already returns provider→capability→surface; the taxonomy from
1.3 makes single caps addressable. This unit turns that into a structured `BackendModel`.

## Approach
- `discover-backend.ts`: GET `/api/capabilities` (+ `/api/providers`), build `BackendModel`
  {providers, capabilities, surfaces, uiComponents}.
- Cross-reference against `capability_taxonomy` (1.3): flag caps missing intents/selectors.
- Emit a diff: `discovered` vs `registered` → candidates for new/refined capabilities (feeds 5.3).

## Acceptance
- On the running stack, `discover-backend()` returns ≥12 providers and the ui-component set.
- Diff correctly flags a capability lacking a selector (injected test).
- `bunx tsc --noEmit` clean.

## Tests
- `tests/integration/runtime-test/discover-backend.test.ts`: against live server snapshot.
