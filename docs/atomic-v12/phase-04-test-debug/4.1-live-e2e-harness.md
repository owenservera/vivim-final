# Unit 4.1 — Live E2E Harness (test.ts)

**Depends on:** 3.2
**Produces:** `devops/runtime-test/test.ts`
**Source:** `docs/atomic-runtime/RUNTIME-OS-DESIGN.md` §3.6

## Problem
The loop must run real frontend↔backend tests against the LIVE server (no Playwright): hit endpoints,
assert responses, and call capabilities end-to-end. Today there is only `curl`/smoke; no reusable harness.

## Approach
- `test.ts`: given a `BackendModel` (3.2), generate + run assertions: `GET /api/capabilities`,
  `POST /api/interpret`, `POST /api/capabilities/:id/execute`, assert shape + status.
- Each test returns `{name, pass, detail}`; aggregate into a report; exit non-zero on any fail.
- Use HTTP QUERY/cache from 1.5 to avoid redundant hits during the loop.

## Acceptance
- `test.run(backendModel)` reports green against current live stack (baseline endpoints pass).
- A deliberately broken capability yields a failing assertion with detail.
- `bunx tsc --noEmit` clean.

## Tests
- `tests/integration/runtime-test/test.test.ts`: against a live snapshot fixture.
