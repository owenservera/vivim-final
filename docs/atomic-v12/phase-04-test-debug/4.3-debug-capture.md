# Unit 4.3 — Debug Capture (debug.ts)

**Depends on:** 3.1, 4.1, 4.2
**Produces:** `devops/runtime-test/debug.ts`
**Source:** `docs/atomic-runtime/RUNTIME-OS-DESIGN.md` §3.7

## Problem
When a test/ui-gate fails, the loop must capture evidence (console logs, network, DOM snapshot, server
logs) so the agent (or a human) can fix it. Today failures are silent.

## Approach
- `debug.ts`: on failure, collect: browser console (via Governor session), failed request/response,
  DOM snapshot at failure point, and tail of server/supervisor logs (2.1).
- Produce a `DebugReport` (structured) written to `devops/runtime-test/.debug/<runId>.json`.
- Expose `debug.capture(context)` used by `test`/`ui-gate`/loop (6.1).

## Acceptance
- A failing gate produces a `DebugReport` with console + DOM + request detail.
- Report path is deterministic and parseable by the loop.
- `bunx tsc --noEmit` clean.

## Tests
- `tests/unit/runtime-test/debug.test.ts`: given a fake failure context, report has all fields.
