# Unit 4.2 — CDP UI Gate (ui-gate.ts)

**Depends on:** 3.1
**Produces:** `devops/runtime-test/ui-gate.ts`
**Source:** `docs/atomic-runtime/RUNTIME-OS-DESIGN.md` §3.6

## Problem
Frontend assertions must go through the live browser via Governor-mediated CDP (no Playwright). The
ui-gate exercises a ui capability: navigate, find the component (by `ui.component` slug), click/assert,
read resulting DOM/state. This is the FRONTEND half of FRONTEND=BACKEND verification.

## Approach
- `ui-gate.ts`: `gate(uiCap)` → via `engage` session: navigate to the cap's route, `findSelector`
  for the component, `evaluate` an assertion (visible, text, state), return pass/fail.
- All CDP through Governor (relies on 1.2 + 3.1); never raw `Runtime.enable`/`evaluate`.
- Sample a slice of ui caps per loop (configurable) to keep the cycle fast.

## Acceptance
- `ui-gate.run(aUiCap)` passes for the verified ui-component set from baseline.
- A hidden/missing component yields a failing gate with the selector detail.
- `bunx tsc --noEmit` clean.

## Tests
- `tests/integration/runtime-test/ui-gate.test.ts`: mocked Governor session + component present/absent.
