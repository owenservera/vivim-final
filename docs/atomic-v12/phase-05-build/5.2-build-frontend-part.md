# Unit 5.2 — Build Reusable Frontend Part (build.ts part)

**Depends on:** 5.1, 3.3, 4.3
**Produces:** `devops/runtime-test/build.ts` (part generator), `src/frontend/parts/**`
**Source:** `docs/atomic-runtime/RUNTIME-OS-DESIGN.md` §3.8

## Problem
When `discover-frontend` (3.3) finds an orphan ui cap (backend has `surface: ui` but no component), the
loop must be able to GENERATE the frontend part and bind its slug — proving it can build frontend
systems, not just test them.

## Approach
- `build.ts generatePart(cap)`: scaffold a React part at `src/frontend/parts/<slug>.tsx` using the
  `ui.component` contract (5.1), wire it to `POST /api/capabilities/:id/execute`, register in the UI
  registry, and re-run `ui-gate` (4.2) to verify it renders.
- Idempotent: skip if the slug already exists.
- After build, `discover-frontend` should report zero orphans for that cap.

## Acceptance
- Generated part renders and passes `ui-gate` against its backend cap.
- Re-running `discover-frontend` no longer flags the built cap as orphan.
- `bunx tsc --noEmit` clean.

## Tests
- `tests/integration/runtime-test/build.test.ts`: generate part → ui-gate green.
