# Unit 1.2 — CDP Runtime-Enable Elimination (DISC-3)

**Depends on:** none
**Produces:** `src/executor/slave-read.ts`, `src/executor/slave-write.ts`, `src/executor/cdp.ts`, `src/executor/cdp-transport.ts`, `src/engines/chrome-governor.ts`
**PRD:** `docs/roadmap/prds/PRD-DISC-3-cdp-evaluate.md`

## Problem
Governor Canon: only `ChromeGovernor` touches CDP. But `slave-read.ts:40` calls `Runtime.enable`
directly and `evaluate` is used in `slave-write.ts`, `cdp-transport.ts`, `cdp.ts`. These raw calls
are exactly what the runtime-OS `engage` step (3.1) must eliminate; they also risk double-enabling
Runtime.

## Approach
- Drop `Runtime.enable` from `slave-read.ts`; use `governor.enableDomains(['Runtime','DOM','Page'])`.
- Route all `evaluate` through `governor.evaluate(targetId, expr, opts)`.
- Gate `cdp-transport.evaluate` behind a `viaGovernor` flag (set by Governor only).
- CI grep guard: raw `Runtime.enable` / `Runtime.evaluate` allowed only in `chrome-governor.ts`.

## Acceptance
- grep across `src/executor` → zero `Runtime.enable` outside `chrome-governor.ts`.
- UI probe still returns capability map (integration test).
- `bunx tsc --noEmit` clean.

## Tests

- CI grep guard test.
