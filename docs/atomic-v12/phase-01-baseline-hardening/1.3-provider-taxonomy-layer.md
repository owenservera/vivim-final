# Unit 1.3 — Provider Taxonomy Layer (DISC-1)

**Depends on:** none
**Produces:** `prisma/schema.prisma`, `src/engines/provider-registrar.ts`, backfill script
**PRD:** `docs/roadmap/prds/PRD-DISC-1-provider-taxonomy.md`

## Problem
`ProviderRegistrar` persists the whole capability graph as one `capabilities_json` blob. Refining a
single capability rewrites the provider row. No versioned capability, no per-provider override, no
intent/selector diffing. The runtime-OS `discover-backend` (3.2) needs a granular, mutable taxonomy.

## Approach
- New tables: `capability_taxonomy`, `capability_override`, `capability_intent`, `capability_selector`
  (keyed by `providerId.capabilityKey.version`).
- `ProviderRegistrar` reads taxonomy rows; `capabilities_json` becomes a generated cache.
- Add `registerCapability`, `overrideCapability`, `listCapabilities(providerId)`.
- One-shot backfill: blobs → taxonomy rows (with reconciliation assert).

## Acceptance
- Adding one capability modifies exactly one taxonomy row.
- `getCapabilities` output identical to prior blob content for seeded providers.
- Overrides don't mutate canonical row.

## Tests
- `tests/unit/engines/provider-registrar.test.ts`: register single → 1 row.
- `tests/integration`: backfill row count == sum of blob caps.
- `bunx tsc --noEmit` clean.
