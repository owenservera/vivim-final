# Unit 1.5 — HTTP QUERY + Body Cache (DISC-5)

**Depends on:** none
**Produces:** `src/server/index.ts`, `src/server/response.ts`, `src/server/capability-router.ts`
**PRD:** `docs/roadmap/prds/PRD-DISC-5-http-query-cache.md`

## Problem
Only GET/POST/PUT/DELETE registered; no `QUERY` (safe body-bearing read) and no cache/ETag. The
runtime-OS test/debug (4.x) and loop hammer endpoints repeatedly; without `QUERY` + cache the loop is
slow and can't do conditional requests.

## Approach
- Add `app.query(path, handler)` for safe reads with body.
- `response.ts sendJson`: optional `ETag` + `Cache-Control` from `cacheKey`; honour `If-None-Match`.
- `Map`-backed cache (`cacheKey → {etag, body, expires}`) with TTL (default 5s, bust on write).
- `GET /api/capabilities` returns `ETag`; repeat with `If-None-Match` → `304`.

## Acceptance
- `curl -X QUERY /api/capabilities -d '{}'` → 200 with body.
- Repeat with `If-None-Match: <etag>` → `304`.
- `bunx tsc --noEmit` clean.

## Tests
- `tests/unit/server/response.test.ts`: etag + 304.
- `tests/integration/server/query.test.ts`: QUERY + cache hit.
