# Unit 1.4 — NLCL Hierarchical + Entity Resolution (DISC-4)

**Depends on:** none
**Produces:** `src/engines/nlcl/catalog.ts`, `src/engines/nlcl/entity-resolution.ts`
**PRD:** `docs/roadmap/prds/PRD-DISC-4-nlcl-hierarchy.md`

## Problem
`catalog.ts` is a flat array; `routePattern` does a linear scan; `entity-resolution.ts` matches a
fixed set. The runtime-OS `discover-frontend` (3.3) and the agent loop need a hierarchical,
intent-rich catalog so NL resolves to a precise provider→platform→capability path and new intents
register programmatically.

## Approach
- `CATALOG` → nested `provider → platform → capability[]` with `intent`, `patterns`, `confidence`.
- `routePattern` (`resolve`) returns best-match path + confidence.
- Extend `entity-resolution.ts` entities + add `registerIntent(...)`.
- Keep cli/ui/api surface parity.

## Acceptance
- 3-level NL ("open twitter DM compose") → provider=twitter, platform=dm, capability=compose,
  confidence > 0.6.
- `registerIntent` adds a resolvable entry without code change.
- `bunx tsc --noEmit` clean.

## Tests
- `tests/unit/engines/nlcl/catalog.test.ts`: hierarchical resolution + confidence.
- `tests/unit/engines/nlcl/entity-resolution.test.ts`: extended entities.
