# Unit 6.1 — Runtime Loop Meta-cmd (index.ts loop)

**Depends on:** 5.2, 5.3
**Produces:** `devops/runtime-test/index.ts` (`runtime` meta-cmd)
**Source:** `docs/atomic-runtime/RUNTIME-OS-DESIGN.md` §3.10

## Problem
All previous units are libraries. The loop must be a single command the agent (opencode/claude-code)
runs: `bootstrap → preflight → engage → discover → test → debug → build → repeat` until green or budget
hit. This is the operational heart of the runtime-OS skill.

## Approach
- `index.ts` exposes `runtime({profile, maxCycles, mode})`:
  1. `bootstrap.up` (2.4) → `preflight` (2.3) → `engage` (3.1)
  2. loop: `discover-backend` + `discover-frontend` → `test` + `ui-gate` → if fail `debug.capture`
     → `build` (5.2/5.3) → re-test → until green or `maxCycles`
  3. `bootstrap.down` on exit (or keep-alive in interactive mode).
- `mode: 'autonomous'` (full loop) or `'mitm'` (stop and ask on build/blocked).
- Emits a per-run `LoopReport` (units touched, fixes applied, final health).

## Acceptance
- `bun run devops runtime-test --profile minimal --max-cycles 3` runs the full cycle without hanging.
- On an injected failure, the loop builds a fix and re-test goes green (or stops in mitm mode).
- `bunx tsc --noEmit` clean.

## Tests
- `tests/integration/runtime-test/index.test.ts`: mock deps, assert cycle order + report.
