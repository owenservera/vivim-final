# 0.4 — sdk/client.ts CapStoreError fix

**Phase:** 0 (Baseline Typecheck Green) · **Status:** done · **Depends on:** —
**Source:** constructor-signature mismatch (DISC-baseline)

## Objective
Construct `CapStoreError` with the correct argument order.

## Context
`CapStoreError` is `constructor(code: string, message: string, details?: unknown)`.
`src/sdk/src/client.ts` called `new CapStoreError(err.error, err.code, res.status, err.details)`
(4 args, wrong order), producing a TS2554 error.

## Deliverable
`src/sdk/src/client.ts` (error branch):
- `new CapStoreError(err.error, err.code, res.status, err.details)`
  → `new CapStoreError(err.code, err.error, err.details)`.

## Acceptance
`bunx tsc --noEmit` no longer reports a constructor-arity error in `src/sdk/src/client.ts`.
