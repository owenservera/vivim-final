# 0.5 — storage/impl bigint coercions (12 files)

**Phase:** 0 (Baseline Typecheck Green) · **Status:** done · **Depends on:** 0.1, 0.3
**Source:** Int→BigInt DB migration regression (DISC-baseline)

## Objective
Coerce `bigint` DB timestamps to `number` at every `toRow`/`get`/`list` boundary in
`src/storage/impl/*` so the public store contracts (`{createdAt,updatedAt}: number`) hold.

## Context
The Int→BigInt migration left every `Row.createdAt`/`updatedAt` as `bigint`. Each store's
`toRow`/return literal assigned the raw `bigint` to a `number` field → TS2322 across the layer.

## Deliverable
Wrap the outgoing timestamp fields with `Number(...)` in each store's row→contract mapping:

- `automation-store-impl.ts`
- `capability-macro-store-impl.ts` (both `list` `r.*` AND `get` `row.*`)
- `discovery-store-impl.ts`
- `harness-checkpoint-store-impl.ts`
- `hpe-session-store-impl.ts`
- `knowledge-ingestion-store-impl.ts`
- `router-store-impl.ts`
- `sandbox-audit-store-impl.ts`
- `shape-binding-store-impl.ts`
- `slave-setup-store-impl.ts`
- `sync-store-impl.ts`
- `workflow-store-impl.ts`

Pattern: `createdAt: row.createdAt` → `createdAt: Number(row.createdAt)` (and `updatedAt`).

## Acceptance
`bunx tsc --noEmit` reports zero errors across `src/storage/impl/*` (excluding the 3 legacy
files listed in the tracker header).
